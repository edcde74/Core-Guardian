기존 코드의 `PathRemaining`은 이미 `전체 경로 길이 - PathTravelled`였다. 각 X/Y 구간을 따라 계산하며 코어와의 직선거리를 비교하지 않았다. 사용자가 말한 현상을 직선거리 버그로 재현/확정하지 않았다. 체력 우선·최초 획득·현재 대상 유지 때문에 경로상 가장 앞선 적으로 즉시 바뀌지 않을 수 있으며, 사용자는 이 규칙들을 유지하도록 확인했다. 노션 본문은 수정하지 않았다.

`CombatData.cs`의 `CombatRules.CompareTargetPriority`로 공통 비교를 모으고, Session 재선택·공개 Priority/TowerPriorityOrder가 같은 역할/HP/남은 경로/최종ID를 사용하도록 했다. 직선거리는 **공격 사거리** 판정에만 기존대로 사용한다. 플레이어 보스 취급·최초 ID 선택·현재 대상 유지·타워 보스 후순위·공격 주기/이미 비행 중 탄환은 변경하지 않았다.

## 공간 탐색 적용과 제한

- Session 호출별 StepWork가 4타일 구역 인덱스를 소유한다. 모든 이동이 끝난 뒤 구축하고 해당 틱의 공격 후보 조회에 재사용한다. 후보는 원래 Enemies 열거 순서로 복원한 뒤 기존 순위에 넣는다.
- 구역은 후보를 좁히는 용도다. 최종 포함 판정은 기존 float `Vector2.Distance <= Range` 그대로다. 보수적으로 경계 바깥1구역도 포함해 반올림/아주 작은 값의 후보 누락을 막는다.
- 적 목록32 미만, 구역 조회256개 초과 또는 구역 수가 원래 적 수 이상, 유한하지 않은 값/음수 사거리/지원 좌표±65536 밖 조건은 기존 선형 조회다. 임계값은 미계측 휴리스틱이며 이 값이 최적이라는 주장은 없다.
- 외부 ProjectileLaunched/AttackLaunched 콜백 호출 **전** 인덱스를 무효화한다. 콜백이 공개 적 목록/좌표를 바꾸거나 Tick에 재진입할 수 있어, 나머지 해당 틱은 선형 조회한다. 버퍼는 호출별이며 finally에서 참조를 Clear한다.
- **틱 밖 TowerTarget 조준 조회는 선형을 유지**한다. 공개 목록/위치의 외부 변경을 추적 없이 캐시하지 않는다. 정상 게임의 발사 구독자도 무효화를 일으키므로 첫 발사 이후 인덱스 이득은 제한된다.
- 구역 목록은 재사용하고 비활성 bucket 목록은 인덱스당 최대128개 보관한다. 배열/사전 용량의 최대 사용량 보관·구축/정렬 비용이 추가된다. 메모리/CPU의 실제 득실은 미측정이다.
