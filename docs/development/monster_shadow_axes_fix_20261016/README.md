# 몬스터 그림자 정렬·네 방향 보행 수정

후속 사용자 확인: 이 기록의 Y축 검증은 다리 동작만 확인했고, 요구한 위/아래 방향 외형 전환은 빠져 있었다. 방향 전환 누락을 재현하고 앞·뒤 파생 프레임을 연결한 [후속 수정/검증](../vertical_facing_20261016/README.md)을 현재 기준으로 본다. 아래 수치·이미지·테스트 결과는 당시 기록으로 보존한다.

2026-10-16. 복구 기준 `4fe6ad8`. 사용자의 지적에 따라 원인 확인에서 멈추지 않고 런타임 보정과 회귀 검증까지 적용했다. 빌드/실행파일 실행은 하지 않았다.

## 변경

- 원본 캔버스 피벗 대신 양쪽 발바닥의 중점을 지면 기준점으로 쓴다. 좌우 반전과 보행 종료 모두 같은 기준을 사용한다. 그림자나 논리 이동 루트를 따라 흔들지 않고 본체 표시 위치만 보정한다.
- Y± 이동에서는 지면 깊이 보폭을 투영하고, 복귀 발을 드는 높이를 따로 적용한다. 원본 사선 시점과 픽셀 관절 레이어를 유지한다. 새 뒷모습을 그리거나 몬스터를 재디자인하지 않았다.
- X± 기존 보폭·이동 거리 기반 주기와 양발 반 주기 차이는 유지했다. 원본 PNG·파생 레이어 PNG·씬·프리팹·CSV 변경 없음.

## 실제 측정

원본 발바닥 하단 2행에서 추출한 중심을 실제 렌더러 Transform으로 월드 좌표에 옮겨 측정했다. 유형별·방향별 48샘플이다. 단위는 원본 도트, X+는 그림자 오른쪽이다.

| 유형 | 수정 전 우보행 평균 X | 수정 후 우보행 평균 X | 수정 후 우보행 종료 X/Y |
|---|---:|---:|---:|
| 공격형 | -9.13 | -0.13 | 0 / 0 |
| 수비형 | -11.24 | -0.74 | 0 / 0 |
| 버프형 | +4.39 | +0.64 | 0 / 0 |
| 보스 | +0.51 | -0.24 | 0 / 0 |

정지 시 네 방향 모두 발바닥 중점과 그림자 중심 차이 0(부동소수점 오차 이내). 보행 중에는 발을 번갈아 들기 때문에 두 발 평균이 순간 이동하며, 전 유형·방향의 주기 평균 가로 오차는 0.95도트 미만이다. 그림자를 들린 발에 따라 이동시키지 않는다.

상하 이동은 수정 전에도 함수 호출과 관절 변화가 있었으므로 ‘Y 입력이 전혀 전달되지 않았다’고 기록하지 않는다. 수직 보폭과 화면 위쪽 발 들기를 분리해 다리를 펴는 한계에 걸리는 문제를 줄였다. 수정 후 실제 발바닥 Y 변화 폭: 공격형 4.78~5.91, 수비형 3.52~4.71, 버프형 4.99~5.16, 보스 5.14~6.55도트. 자연스러움·아트 승인은 사용자 검토가 필요하며 기능 통과로 대체하지 않는다.

## 검증

- 전체 EditMode **83/83 completed**, [원본 결과](editmode.json). 기존78 + 지면/네 방향 회귀4 + 수직 보폭/발 들기 분리1.
- 전체 PlayMode **15/15 completed**, [원본 결과](playmode.json). 기존14 + 실제 전투 어댑터를 통과하는 정상 적 경로 X±/Y± 연결1. 정상 웨이브 생성과 이동을 사용하며, 첫 적이 네 방향 구간에서 각각12회 이상 동작하고 방향별8개 이상의 실제 다리 자세를 보이는지 확인한다. 격리 테스트의 시간 진행은 기능 검증용이며 밸런스 실측이 아니다.
- 원본 루트/배율·그림자 Transform·스프라이트 참조 보존. 우보행→상행→좌보행→하행→상행 및 정지를 검증한다. 추가 외부 계측은 PNG의 실제 발바닥 픽셀에서 계산하므로 코드의 기준점 상수만 재검사하지 않는다.
- [최종 Unity 상태](final_editor_state.json): Play=false, compiling=false, 기존 전투 씬 dirty=false, URP. 테스트 임시 씬은 Unity 테스트 러너가 정리했다.
- 기존 실행 파일은 이 수정이 포함되지 않는다. 사용자가 요청하기 전 새 빌드/실행하지 않는다. 밸런스·Notion·사용자 미커밋 자료는 변경하지 않았다.
