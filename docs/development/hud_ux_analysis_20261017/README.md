## 2. 문제와 근거

**확인 사실:** 전투 진입에도 구매창·선택 정보창이 남는 코드, UI가 아닌 바닥 클릭이 선택만 해제하는 코드, 떨어진 TopFold/TowerFold/AugmentFold 글자 버튼, 현재값과 구매 버튼을 합친 구조를 확인했다. 증강 접힘은 제한 시간의 표시까지 숨기는 Notion 의도/코드 차이다. 상단 작은 접힘은 72→52px이나 단계판116px는 별도 유지된다.

**확인 사실:** 포탑 정보 Stats.Damage는 지원/타워 증강의 현재 공격력 보정을 합산한 발사 피해 입력과 다르다. Session.Shoot는 발사 시 보정한다. 기존 표시를 무조건 ‘실제 명중피해’로 이름 붙이면 안 된다. 플레이어 증강의 추가탄/둔화도 기존 효과를 설명할 자리가 필요하다.

**배치 계산:** 1920×1080 기준 포탑 정보 사각형은 약12.4%, 플레이어 강화10.3%, 설치 목록10.4%, 피해5.9%다. 패널이 실제 동시에 보이는 조건과 반투명·장식은 별개이며 합산값을 불투명 차폐율이나 플레이 체감으로 사용하지 않는다. playerPanel은 중심+500·폭520이어서 기준 해상도의 우측 끝을 계산상 약20px 넘는다. 다른 비율/CanvasScaler에서의 실제 잘림은 미측정이다.

**UX 가설:** 여러 큰 창의 동시 유지와 전투 중 비활성 구매 행은 전장 확인·설치 칸 찾기를 방해할 가능성이 높다. 이는 사용자의 불편 제보 및 구조상 원인 가설이며 이번 사람이 직접 플레이해 검증한 결과는 아니다.

전투에서 다시 연 플레이어 구매창은 허용하며, 전투가 진행 중이라는 이유로 매 Refresh마다 닫지 않는다. 자동 닫힘은 **단계 진입 1회**로 처리해야 한다. 증강 접힘 시간은 cardsRoot 밖에서 유지해야 한다.

### 클릭 충돌 방지 계약 — 제안

1. 단계 전환을 먼저 확정한다. 그 프레임의 입력이 이전 단계 설치 상태를 사용하지 않게 한다.
2. 포인터 누름과 해제를 같은 제스처로 추적한다. UI에서 시작한 클릭은 UI가 숨겨지거나 포인터가 바닥으로 이동해도 월드 동작으로 넘기지 않는다. 손잡이 클릭도 같은 규칙이다.
3. 증강 단계는 배경 입력 종료. UI 적중/이미 소비한 제스처도 월드 입력 종료.
4. 설치 모드라면 설치/실패 처리 전용. 일반 바닥 닫기 경로를 타지 않는다. 취소는 기존 Esc/명시 취소만 담당한다.
5. 비설치 모드의 포탑 클릭은 그 포탑 스펙 선택. 플레이어 버튼은 플레이어 스펙 선택. 구매창을 열어도 자동 구매 없음.
6. `ground.HasTile`이고 경로·코어·점유칸이 아닌 바닥 클릭만 닫기 대상으로 판정한다. 적/플레이어가 있는 칸도 ‘빈 바닥’에서 제외한다. 열린 일반 상세창이 있으면 닫고 **그 제스처 전체를 소비**한다. 선택ID는 유지하며 설치/구매/파괴는 호출하지 않는다.
7. 닫을 창이 없고 포탑 선택이 남아 있을 때의 다음 빈 바닥 클릭은 선택 해제만 한다. 피해 패널/핵심 상태는 빈 바닥 닫기에서 제외한다.
8. 토글/접기는 표시 상태, 선택 해제는 대상 상태, 취소는 설치 상태다. 설치 목록에서의 명시적 닫기는 기존 분류 초기화 규칙을 보존한다.

이 계약은 현행 코드가 이미 보장하는 기능이 아니다. 현재 코드는 Update의 mouse-down 월드 분기와 UI Button의 클릭 시점이 별개여서 구현 시 제스처 소비/입력 순서 검증이 필요하다. 같은 프레임 라운드 시작·설치 취소·UI 숨김도 검사한다.

## 4. 배치 3안

같은 아트 자산·색감·금속/황동 외형을 유지한다. 동봉 인터랙티브 배치는 **구조 와이어프레임이며 새 Unity 화면/최종 픽셀 아트가 아니다**. 시안 선택은 공통 동작 정책의 자동 확정이 아니다.

### 기존 배치 정돈안 (최소 변경)

- 현재 상단 필수값·하단 설치/시작/플레이어 강화 진입을 유지한다. 상단 안내판을 한 줄로 줄이고 진단/재시작/배속은 ‘개발’ 진입 아래 보관한다.
- 왼쪽 포탑 정보는 기본 현재 스펙만 낮게 표시, 강화 시에만 확장. 오른쪽 아래 플레이어도 스펙→강화. 큰 상세창은 한 번에 하나만 펼친다. 피해는 현재 우측 자리 그대로다.
- 상태 손잡이는 상태판 아래, 포탑/플레이어 손잡이는 각 패널 아래/가장자리에 부착한다. 접힌 대상의 짧은 이름/심볼을 남긴다. 피해 손잡이 자산·위치·집계 규칙은 변경하지 않는다.
- 장점: 익숙한 위치·기존 하단 진입 보존, 변경량 가장 작음. 단점: 스펙 확인 위치가 좌우로 갈리고 패널이 커지면 전장 양끝을 계속 가린다.

### 하단 정보창안 (추천)

- 상단은 작은 필수 상태+단계·보스 정보. 하단은 현재3개 진입을 얇게 유지하고 플레이어 현재 스펙 진입을 추가한다. 포탑 클릭/플레이어 진입은 하단 같은 영역을 교체한다.
- 현재 스펙 기본창과 강화 구매창을 탭으로 구분한다. 기본 높이 약150~180px, 구매 높이 약260~300px는1920×1080 설계 시작값이며 미승인/미실측이다. 긴4행을 가로2열로 재구성하는 안으로 버튼 판독을 확인한다.
- 하단 창 윗변 중앙의 작은 손잡이로 접고, 접힌 뒤에도 대상 이름·심볼과 진입을 유지한다. 피해 패널은 현재 우측 자리/손잡이 그대로 별도 존재한다.
- 장점: 대상 바뀌어도 읽는 위치 동일, 스펙 기본값이 구매와 분리됨, 중앙/양측을 더 확보. 단점: 하단 바닥 설치 칸 가림 가능, 기존 세로 구매행 재배치·입력 상태 설계가 필요. 설치 모드에서는 현재처럼 임시 숨겨 가림을 줄인다.

### 측면 서랍안

- 왼쪽 가장자리 작은 설치/플레이어/선택 포탑 진입을 두고 하나의 서랍을 교대로 연다. 전투에는 설치 진입만 사용불가로 구분한다. 준비 시작/시간은 하단 중앙 유지.
- 서랍 안에 스펙/강화 탭을 둔다. 접힘은 서랍 오른쪽 손잡이, 접힌 뒤에는 왼쪽 가장자리에 같은 손잡이와 선택 대상 표식. 피해는 현재 우측 유지.
- 장점: 세로 스펙/구매 행을 넉넉하게 읽고 화면 아래를 확보. 단점: 왼쪽 적 진입 구간과 직접 경쟁, 좌우에 서랍·피해가 동시에 열리면 중앙이 좁아짐. 익숙한 하단 진입 위치가 바뀐다.

## 6. 추천과 미확정 선택

**하단 정보창안**을 추천한다. 사용자가 원한 스펙 확인과 구매 분리를 가장 명확하게 제공하고, 패널 여러 개를 한꺼번에 유지하지 않으면서 확인 위치를 고정한다. 통합 전투력은 필요하지 않다. 기존4능력치·지원 효과·증강 효과를 읽고, 구매 전후 변화와 실명중 숫자/기존 누적 피해를 각각 확인하면 된다.

표기: 공격력은 기존 HUD 반올림 규칙, 공격속도는 소수·발/초, 사거리/투사체 속도 단위를 유지한다. 공격력의 기본/강화값과 지원·증강 보정은 출처를 구분하고 실제 적 방어/잔여 HP 반영 명중피해라고 쓰지 않는다. 현재값에서 구매로 넘어갈 때 대상ID·골드/수정·현재→다음·증가량·비용을 연결한다. 성공 때만 변화 피드백을 보이며 실패에는 증가 표시가 없다.

검토 대상은 배치안, 전투 진입 구매창/스펙 접기, 빈 바닥 첫 클릭=접기·두 번째=선택 해제, 설치 성공 후 목록 복원+새 포탑 스펙 자동펼침 억제, 증강 카드만 접고 시간 유지다. 마지막 설치 성공 후 새 스펙 자동펼침 억제는 현행 동작 변경 제안임을 명시한다. 확정 아트/피해 HUD를 다시 승인받는 질문이 아니다.
