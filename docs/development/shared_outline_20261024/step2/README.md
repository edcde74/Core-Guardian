# 2단계 검증 — 공유 마스크 윤곽 (토글 ON 비교)

2026-10-24, 사용자 "2단계 진행해" 승인. Editor Play 3회로 진행했다. 1·2회차는 같은 드라이버(`Capture.cs`)로, 2회차는 출력 셰이더 수정 후 재실행이다. 3회차는 `Capture2.cs`다. 매 회 자체 Play 종료·복원을 확인했다. 제품 기본값은 토글 OFF 그대로다.

## 1회차에서 발견해 고친 문제
- **증상:** 토글 ON 화면이 윤곽을 숨긴 화면과 픽셀이 똑같았다(출력 0). 마스크 RT에는 개체 ID가 정상 기록돼 있었다.
- **원인:** 출력 셰이더가 `GetNormalizedScreenSpaceUV`로 화면 좌표를 구했는데, 수동 `camera.Render()`나 RT 렌더에서 `_ScaledScreenParams`가 대상 크기와 달랐다(EditMode 16×16 프로브에서 확인).
- **수정:** 출력 셰이더가 world 좌표를 **마스크 패스와 같은 행렬**(`_CGSharedOutlineVP`)로 다시 투영해 texel을 구하도록 바꿨다. EditMode 단독 프로브로 마스크와 윤곽 정렬이 맞는 것을 확인한 뒤 재실행했다.

## 비교 조건
- 1920×1080, ortho 8.5와 4.25, 고정 dt 1/60. 캡처 직전 `timeScale=0`으로 시뮬레이션을 정지했다.
- 캡처는 `Camera.main`을 1920×1080 RT로 렌더한 것이다(HUD Overlay 미포함). raw RGBA와 PNG를 보존했다.
- 장면 세 가지
  - main: 적128(Attack112/Buff16)·타워15. 기존 계측과 같은 주입 부하라 **적 약 10명씩 12곳에 겹쳐** 있다.
  - var: 4종(Attack/Defense/Buff/Boss) ×4, 일부 겹침
  - spr: 4종 ×2를 넓게 띄움 + 타워15(인접 배치)

- **차이는 모두 개체가 겹치는 곳에서만 나왔다.** 원본은 개체마다 가려진 부분까지 포함한 전체 실루엣으로 윤곽을 만들어 "앞 부품 +3" 정렬에 그린다. 그래서 겹친 무리에서 뒤 개체 윤곽선이 앞 개체 몸 위에 보인다. 공유 방식은 화면에 실제로 보이는 실루엣 기준이라 그 선들이 사라진다. 설계안 4.4에서 예상한 차이다. 시각 비교는 [compare_crops.png](compare_crops.png)(왼쪽 원본 / 가운데 공유 / 오른쪽 차이)에 있다.
- 원본 대 원본: main에서 a와 c(30프레임 간격)는 415px 차이가 났다. 정지 중에도 진행되는 피격 섬광 효과 때문이다. 같은 시점끼리 비교한 a/b와 원본 대 공유 비교에는 영향이 없다(none_a 대 none_shared_a 15프레임 간격 차이 0).

## 동작 회귀 (토글 ON, 시간 진행)
- 적 10명 제거 → 3프레임 뒤 대상·출력 23/23. 10명 재생성(풀 재사용) → 33/33. 줌 4.25 → 33/33. 토글 OFF → 공유 0·원본 33, 다시 ON → 공유 33·원본 0.
- 콘솔 오류 0. 1회차 드라이버가 41/41 단계를 완료했다.
- Play 종료 후 공유 마스크 RT·머티리얼·출력 잔류 0. scene clean 7 roots, Game View 3→3, timeScale 1, captureDeltaTime 0.
- **Restart:** 원본 경로에서도 Restart 뒤 core·PlayerStart의 윤곽 출력 2개가 켜진 채 남는다(기존 동작). 공유 경로도 같은 2개가 남는다. 신규 회귀는 아니지만 기존 동작 자체는 별도 확인 대상이다. 3회차 두 번째 Restart는 드라이버가 파괴된 게임 참조를 다시 써서 예외로 중단됐다(드라이버 오류, 제품 오류 아님). 이후 정상 종료·복원했다.

## 판정
- 고립 개체: 픽셀 동일(확인 범위: spr 고립 7개, 8.5 줌).
- 겹친 개체: 설계에서 예상한 방향의 외형 차이가 있다. **채택 여부는 사용자 시각 판단 대상**이다.
- 아직 안 한 것: 성능 비교(3단계), 4방향 × 4위상 전수, HUD 포함 전체 화면, 정상 30R.
