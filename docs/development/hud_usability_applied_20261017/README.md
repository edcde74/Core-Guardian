# 하단 정보창·사용성 적용

2026-10-17. 사용자 승인: **하단 정보창안 / 빈 바닥 첫 클릭 접기·다음 클릭 선택 해제 / 설치 성공 후 스펙 자동 펼침 생략**. 구현 전 복구 기준 `3b62246`; 주요 게임 파일의 기존 변경이 없어 빈 checkpoint는 만들지 않았다. [승인 전 비교](../hud_ux_analysis_20261017/README.md), [실행 계획](plan.md).

## 적용 범위

- `CoreGuardianHud.cs`와 partial `CoreGuardianHud.Inspector.cs`: 플레이어/포탑 현재 스펙과 강화 구매를 같은 하단 위치의 별도 탭으로 표시. 한 번에 하나의 상세창, 현재값 조회 진입과 구매 진입 분리. 포탑 개체ID/지원·증강 보정 출처/단위를 표시하고 지원 포탑은 버프%·반경으로 설명한다. 새 전투력·밸런스 공식은 없다.
- 하단 정보창과 상단 상태에 기존 금속/황동 자산을 재사용한 부착 손잡이. 접힌 상태는 대상 표식과 재개방 손잡이를 남긴다. 준비/전투에서 선택·게임 상태는 유지한다. 상태 상시 핵심 값은 보존하고 개발용 진단/재시작/배속은 개발 도구 메뉴로 모았다.
- 전투 진입 때 설치/구매/큰 스펙창을 한 번만 정리하고, 전투 중 다시 연 플레이어 구매는 유지한다. 준비만 포탑 구매 허용, 전투 중 파괴/조회 허용은 기존 규칙을 따른다. 일반 안내는 짧게 표시하고 코어 피해는 Notify로 표시 시간을 갱신한다. 코어 B안·숫자 위치·기존 셰이더는 변경하지 않았다.
- `CoreGuardianPrototype.cs`: UI에서 시작한 누름~해제 제스처를 월드로 넘기지 않는다. 월드 클릭은 같은 칸에서 눌렀다 떼고 양쪽 모두 UI에 차단되지 않을 때 처리한다. 일반 유효 빈 바닥은 첫 클릭에 상세창만 접고 선택ID 유지, 다음 클릭에 선택 해제. 경로·코어·점유칸·플레이어·살아 있는 적·보드 밖은 빈 바닥에서 제외한다. 설치 모드의 바닥 입력은 설치 전용이며 취소는 Esc/명시 버튼이다.
- 설치 성공 후 기존 목록을 복원하되 새 포탑 스펙을 자동으로 펼치지 않는다. 같은 포탑 재클릭은 현재 스펙을 열고, 다른 포탑은 구매 탭을 초기화한다. 설치 목록을 명시적으로 닫은 뒤 새로 열면 기존처럼 첫 분류다.
- 증강은 카드 본체만 CanvasGroup으로 접는다. 시간·자동선택 안내·손잡이·배경 입력 차단을 유지하고 공개 코루틴을 취소하지 않는다. 종료 뒤 모든 손잡이 입력을 복원한다.
- 피해 트랙·4px 안쪽 여백·최대항목 대비 비율·역할 심볼·우측 손잡이·접힘 중 집계는 보존했다. 원본/CSV/씬/카메라/후처리/VFX를 수정하지 않았다. 병행 포신/애니메이션 파일 변경은 이번 HUD 커밋에 포함하지 않는다.

## 확인 결과와 한계

- 기본 계약: [최초 실패](red.json) → [통과](hudGreenBasic.json). 별도 스펙 진입/하단 위치/단일창/구매행 분리/접기 소비를 실제 HUD 객체에서 검사했다.
- [흐름 통과](hudFlow.json), [검증기](VerifyFlow.cs): 실제 Session 구매·설치 성공/실패·목록 복원·새 스펙 자동 펼침 없음·첫 바닥 접기/다음 선택해제·같은 포탑 재개방·전투 진입 접기/전투 중 구매 재개방. 증강 접힘 중 공개 연출 완료/타이머/같은 후보/자동선택과 이후 손잡이 복원까지 확인했다.
- [실제 마우스 통과](hudPointer.json), [입력 검증기](VerifyPointer.cs): 임시 InputSystem 마우스로 UI 클릭/누름→숨김→바닥 해제, 설치 진입 클릭 투과0, 바닥 설치1회, 첫 바닥 접기·두 번째 선택 해제, 같은 포탑·실제 손잡이 적중. 임시 마우스 제거·이전 current 복원·TimeScale 복원은 finally로 실행했다.
- 리뷰에서 손잡이 비활성 복원 누락을 발견했고 [실패 상태](handleRed.json)와 실제 마우스 검사 실패를 확인한 뒤 고쳤다. [코어 안내 실패](feedback-red.json) → [최종 통과](feedback-green.json). 리뷰 재조회에서 남은 actionable finding 없음. 기존 작은 버튼의 텍스트가 세로 여백 때문에 사라진 것도 실제 화면 확인 후 수정했다.
- 기존 `VerifyDamageHud.cs`도 실행해 트랙·여백·3심볼·손잡이·접힘 중 값 갱신을 통과했다. 표시425/210/7→70·포탑1001/1002는 표시 주입이며 자연 전투 수치가 아니다.
- 전체 EditMode **115/115** 통과(병행 포신 수정이 포함된 당시 작업 트리). [요약](editmode-summary.json). 집중 설치 HUD PlayMode **4/4** completed: [원본 결과](placement-playmode.json). 마지막 Notify 수정은 별도 위 코어 안내 red/green으로 확인했으며 전체 스위트를 새로 재실행한 것으로 표현하지 않는다.
- [전체 PlayMode](full-playmode-zero.json)·런타임 클래스 필터는0건 반환. 통과가 아니다. 동기 PlayMode 호출은 도메인 재로드로 불가능하다는 실행기 안내 후 비동기로 집중4건을 확인했다. 전체 PlayMode 회귀는 미완료다.
- 검사 도중 기존 실행기 씬복구/정리 오류와 API timeout이 나타났다. 자체 Play Stop API가 시간초과되어 실제 창에서 해당 자체Play의Stop을 누르고 Ctrl+R로 저장된 소스를 새로고침한 뒤 API 응답을 회복했다. 에디터/캐시/패키지/프로세스를 재시작·복구·삭제하지 않았다. 사용자/다른 채팅 Play를 중단한 것이 아니다. 이후 컴파일실패false·Playfalse·TimeScale1/captureDelta0·전투씬1/dirtyfalse·현재 콘솔오류0/경고0을 재조회했다. 과거 오류 버퍼와 현재 콘솔을 구분한다.
- 기능 검사는 진단 재화/강제 처치/임시 마우스·일부 시간0을 사용했다. **사람 직접 플레이·정상 다수 전투 사용성·밸런스 실측·성능·아트 최종 승인과 다르다.** 다른 해상도/많은 피해 항목/키보드 포커스 전체 순회는 후속 확인이다. 빌드/실행파일/push없음.
