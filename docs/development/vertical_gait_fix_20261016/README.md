# 공격형 상하 보행 양발 교대 수정

2026-10-16. 사용자 피드백: 하행 경로의 공격형들이 화면 오른발이 움직이지 않고 절뚝거린다. 복구 기준 `a7ad256`. 시작 시 관련 추적 변경 없음, Unity stopped/compiling=false/전투 씬dirty=false 확인 후 작업했다.

## 원인

기존 상하4프레임은 한 다리를 앞으로 내밀고 반대 다리를 접은 자세를 계속 유지했다. 전체 이미지4장이 다르다는 검사만으로는 양발이 실제로 번갈아 걷는 것을 보장하지 못했다. 이전 접지 원본 수정은 X축에 사용하는 원본/분리 다리를 고쳤으며, 별도 Y축 이미지의 한쪽 다리 고정 문제는 해결하지 않았다. [사용자 피드백](user_feedback.png).

## 수정

- 현재 공격형 상행 뒷모습·하행 앞모습의 기존 도트를 그대로 재사용했다. 몸통·머리·장비는 선택된 Up/Down 이미지의 상단·좌우 부분을 분리해 같은 위치에 렌더한다. 고정된 중앙 다리 부분만 표시 대상에서 제외한다. 원본 PNG를 다시 그리거나 새 팔레트/장비를 만들지 않았다.
- 해당 방향의 기존 부츠/정강이 도트를 좌우 독립 렌더러로 표시한다. 반대쪽은 같은 도트를 좌우 반전해 사용한다. 두 발은 같은3.5원본px 높이의 스윙을 반 주기 차이로 수행한다. 한쪽은 지지하는 동안 다른 쪽이 들렸다 돌아오며 멈추면 양발 모두 지면 자세로 돌아온다. 위/아래 방향 외형과 기존4프레임 순환은 유지한다.
- 공격형에만 적용했다. 사용자가 승인한 X축 보행·앞서 수정한 접지 원본과 다리 기준점·다른 병사/보스·그림자·논리 경로·이동속도는 변경하지 않았다. VerticalWalk PNG/원본 프리팹/씬/CSV 변경 없음.
- 런타임 Sprite는 원본 텍스처의 사각 구역을 참조하고 캐시한다. 매 프레임 텍스처를 만들지 않으며 임시 배열 할당도 피했다. 기존 몸 피격 반응은 새 분리 렌더러도 포함한다.

## 검증

- [수정 전 실패2건](red.json): 상행/하행 모두 독립된 양발 표시·교대가 없음을 재현했다.
- 새 EditMode 검사는 실제 표시되는 양발의 위치 변화가 각각2원본px 이상이며 진폭이 같고 반 주기 차이인지 확인한다. 최종 전체 **95/95 통과**: [결과](editmode_final.json).
- 기존 실제 웨이포인트 PlayMode 검사에 상행/하행 각각 양쪽 발 렌더러의 활성 표시와2px 초과 이동을 추가했다. 최종 전체 **16/16 completed**: [결과](playmode_final.json). X축 기존 관절 보행·상하 방향 이미지·X복귀와 기존 전투/HUD/피격 연결 포함. 기능 회귀이며 밸런스 실측·사용자 자연스러움 승인은 아니다.
- 실제 Unity 격리 렌더48프레임을 수정 전후에 보존했다. [움직이는 전후 비교](before_after.webp): 왼쪽 수정 전/오른쪽 수정 후, 위 하행/아래 상행. 모두 원본3배 동일 배율이다. [수정 후4위상 비교](after_contact.png), [대표 전후](comparison.png). 원본/공통 병사3종 비교판도 작업 전 직접 열어 확인했다.
- [렌더 검사](render_checks.json): 수정 후48개 프레임이 모두 다르며 왼발·오른발 화면 영역이 각각11가지로 변한다. 영상은 비교용 고정 위치 반복이며 실제 게임의 이동속도나 밸런스 계측 영상이 아니다.
- 초기 구현의 GetInstanceID는 현재 Unity에서 컴파일 금지여서 Sprite 참조 캐시로 수정했다. 초기 지오메트리 치환은 EditMode에서 거부돼 원본의 사각 구역 분리 렌더로 바꿨다. 해당 중간 실패/렌더는 compile_rejected/geometry_rejected 접두어로 분리 보존하며 최종 결과로 사용하지 않는다. 과거 콘솔 이력은 삭제하지 않았다.
- [최종 상태](final_editor_state.json): Play=false·compiling=false·기존 전투 씬active/dirty=false. 사용자 Play를 임의 중단하지 않았고 자체 회귀 검사만 실행했다. 원본/씬/프리팹/밸런스·노션 수정, 새 빌드/실행파일 실행/GitHub push 없음.

현재 씬에 적용했으며 기존 실행파일에는 미포함이다. 다른 유형의 상하 다리와 전체적인 자연스러움은 이번 공격형 검증만으로 승인된 것으로 간주하지 않는다.
