# 몬스터 피격 시 몸 밝기 반응 적용

2026-10-16. 사용자 선택: 타격 시안 중 몬스터 몸이 잠깐 밝아지는 반응만 적용. 새 스파크/파편/숫자 반응·사운드는 추가하지 않는다. 수정 전 로컬 복구 기준 `ed71e07`. 처음 확인 당시 사용자 Play 중이어서 중단하지 않았으며, 사용자가 직접 종료했다고 응답한 뒤 stopped/컴파일false/전투 씬dirtyfalse를 다시 확인하고 적용했다.

## 현재 구현

2026-10-16 후속 피드백으로 복귀 시간을65ms→90ms로 소폭 늘렸다. 최대 밝기22%·재점등 제한100ms는 유지한다. [조정·검증 기록](duration_90ms.md). 아래 최초 적용 당시 전체 검사92/16·정적 비교는 이 후속 조정의 재실행 결과와 구분한다.

- `CoreGuardianCombatAnimation`이 실제 `Session.DamageApplied`를 구독한다. 양수 피해를 받고 살아 있는 몬스터의 `CoreGuardianUnitAnimation.ReceiveHit()`를 호출한다. 뷰 생성 전 명중은 해당 개체의 뷰 동기화 때 연결하며 이미 처치된 개체의 보류 기록은 제거한다.
- 공통 `CoreGuardianHitFlash`와 `Resources/CoreGuardian/BodyHitFlash.shader`가 몸 RGB를 따뜻한 밝은 색으로 최대22% 혼합한 뒤90ms 동안 감소시킨다. 첫 프레임에 최고 반응을 표시한다. 100ms 이내 재명중은 반응 시간을 연장하지 않는다. 이는 화면 표시 제한이며 실제 피해·발사·이동·보상에는 관여하지 않는다.
- 일반3종과 보스에 동일 반응. 본체 `2D Sprite` 하위의 관절 보행5레이어/원본/VerticalWalk 앞·뒤 방향 렌더러에 동일 셰이더 파라미터를 전달한다. 그림자와 체력바·버프 표식은 대상 밖이다. 원본 sprite/alpha/방향 반전/색/Transform은 보존한다.
- 재질은 전체 개체가 하나를 공유하며 개체/레이어별 MaterialPropertyBlock을 사용한다. 종료/비활성화 때 원래 재질·기존 property block을 복원한다. 셰이더는 설치 URP17.6 기본 Sprite-Unlit의 Core2D/2DCommon 경로를 따르고 최종 RGB 혼합만 추가했다.
- 기존 B 명중/처치 스프라이트, 피해/골드/코어 숫자, 투사체, 피격 판정은 유지했다. 앞서 만든3종 새 스파크와 숫자 묶음/등장 반응, 사운드는 미적용이다.
- 같은 프레임에 사망해 뷰가 제거되는 몬스터에는 밝기 반응을 남기지 않는다. 기존 처치 표현을 따른다. 죽는 모델을 잠깐 유지하는 기능이나 사망 연출 변경은 하지 않았다.

## 검증

- 구현 전 새 EditMode5건이 `ReceiveHit`/피격 도우미 부재로 모두 실패하는 것을 확인했다. 구현 후5건 통과. 일반3종/보스의 X/Up/Down 표시 동기화, 그림자/체력 렌더러 제외, 원래 재질/색/위치/크기 복구, 연속 명중 제한, 기존 property block 보존을 확인했다.
- 전체 **EditMode92/92 completed**: [원본 응답](editmode.json).
- 새 PlayMode에서 실제 전투 씬의 Session 투사체 발사·명중·피해 이벤트를 통해 생존한 수비형의 몸 반응, 기존 EnemyHit/피해 숫자 유지를 확인했다. 격리 테스트용 적 생성/시간 정지를 사용한 기능 검사이며 정상 사람 플레이/밸런스 계측은 아니다. [단일 결과](playmode_focused.json).
- 전체 **PlayMode16/16 completed**: [원본 응답](playmode.json). 중간에 테스트 실행기가 전체 PlayMode를0건으로 반환했다.0건을 통과로 보지 않았으며 스크립트 도메인 재로드 후 다시 실행해 실제16건 완료를 확인했다.
- 통합 테스트 초안은 TMPro assembly 참조가 없어 컴파일 실패했고, 기존 피해 숫자 GameObject 존재 확인으로 수정했다. 최종 컴파일 성공. 테스트 실행기의 일시적 상태파일 sharing 오류와 과거 콘솔 로그를 삭제하지 않았다.
- `CaptureBodyHit.cs`로 현재 Unity 렌더러/셰이더를 사용하는 격리 PreviewRenderUtility에서 일반3종+보스를 직접 촬영했다. [비교](unity_body_flash.png): 행 공격형/수비형/버프형/보스, 열 정상/피격 최고/복귀. 같은 픽셀3배이며 X 보행/앞뒤 방향 외형을 포함한다. 정적 이미지를 직접 열어 몸 밝기와 그림자 제외·복귀를 확인했다. 일반 게임 화면의 연속 전투 체감 승인과는 구분한다.
- 피격 셰이더 supported=true, shader messages0. 최종 Play=false/컴파일false/TimeScale1/기존 전투 씬dirty=false: [최종 상태](final_editor_state.json).
- 게임 원본PNG·프리팹·씬YAML·CSV와 기존 실행파일을 변경하지 않았다. 빌드/실행파일 실행/Push 없음.
- 별도 읽기 전용 코드 리뷰에서 수명/복구/방향 프레임/셰이더/기존 표현 유지 범위를 점검했으며 actionable finding 없음으로 회신받았다.

## 재개

Unity에서 현재 전투 씬을 Play하면 이 반응이 연결된다. 기존 실행파일은 재빌드하지 않았으므로 포함하지 않는다. 이후 사람 플레이에서 강도/지속/집중 공격 판독을 보고 조정 여부를 결정한다. 사운드와 신규 스파크 적용은 별도 사용자 지시 범위다.
