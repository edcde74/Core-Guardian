# 피해 게이지·황동 손잡이 적용

2026-10-17. 사용자 선택: 기본 트랙형 게이지, 범위=3개 표적 화살표/단일=조준점/기술병=고글 헬멧, 얇은 손잡이의2번 황동 포인트. 수정 전 복구 기준 `2014b38`. 병행 코어 효과 커밋 `8dfacee`는 보존했다.

## 적용

- `CoreGuardianHud.cs`: 고정 폭280×18의 빈 트랙과4px안쪽 여백,272×10영역 안의 피해 채움. 기존 라운드 최대 피해 대비 비율·정렬·집계는 유지했다. 이름과 우측 누적 숫자를 분리하고 숫자 크기는11~17범위에서 맞춘다.
- 역할별3심볼과 어두운 금속/황동 끝장식/흰 화살표 손잡이를 `DamageRoles.png`로 추가했다. 생성 원본은 [source_atlas.png](source_atlas.png). 내장 imagegen에서 기존 선택 시안을 참고해 투명4분할 이미지를 만들고 [ImportHudAtlas.cs](ImportHudAtlas.cs)의Unity SpriteEditorDataProvider로 알파 경계에 맞춰 분리했다. Point/비압축/밉맵없음, 기존 스프라이트 원본은 보존했다.
- 하단 독립 `피해 접기` 글자 버튼을 제거하고28×108손잡이를 피해 패널 왼쪽 중앙에 부착했다. 접으면 패널만 숨기고 같은 높이의 오른쪽 가장자리에 반대 화살표 손잡이가 남는다. 누적 집계와 재화/라운드를 바꾸지 않는다. 기존 설치 중 HUD숨김 정책도 같은 Canvas루트에 적용된다.
- 코드와 신규 HUD PNG/에디터 생성 meta만 게임 변경이다. 씬·원본 캐릭터/몬스터/프리팹·CSV·기존 VFX·Notion·빌드/실행파일은 변경하지 않았다. push없음.

## 검증

- 처음에는 공유 검사가 실행 중이어서 Assets밖 리소스/검증 준비만 했다. 유휴 상태에서 자체 Play를 시작했다. [수정 전 실패](red.json)는 빈 BarTrack이 없다는 요구 조건 실패이며 컴파일 실패가 아니다.
- 임포트 [성공 결과](import.json), 재컴파일 completed/failed=false/errors없음 확인. [집중 검증](green.json)은 실제 전투 씬의 HUD객체에서3개 고정 빈 트랙/채움 여백·서로 다른3스프라이트·손잡이 중앙과 가장자리 정렬·글자 박스 없음·펼침/접힘 양쪽의 실제 EventSystem Raycast최상위 적중·접기/재개방·숨긴 동안 피해값 갱신·세션 보존을 확인했다. [검증기](VerifyDamageHud.cs).
- 수치425/210/7→70과 포탑1001/1002는 **표시 전용 주입QA**다. 정상 구매/전투 계측이나 사람 플레이·밸런스 결과가 아니다. 자체 세션 종료로 폐기했다.
- [실제 Overlay HUD 포함 화면](expanded.png):1920×1080,원래 카메라·1배속·줌변경없음. `ScreenCapture.CaptureScreenshot`로 저장해 손잡이/3심볼/빈 트랙을 직접 확인했다. [first_game.png](first_game.png)는 CLI screenshot의 카메라 렌더로HUD가 빠진 자료이므로 UI검증 근거로 사용하지 않는다.
- 접힘/재개방 기능은 위 집중 검증에서 통과했으나 별도 접힘 PNG저장 단계에서CLI eval/run_script/editor_status가시간초과했다. 이후CLI는서버reachable로보고했지만명령은계속시간초과했다. 원인 확정/패키지 수정/에디터 재시작은 하지 않았다. 기존 테스트 실행기의씬복구/정리 오류가콘솔에남아있어 이번에콘솔오류0이나전체회귀통과로표현하지않는다.
- `computer-use`의실제Unity화면에서 검증용포탑1001/1002가있는자체Play를확인하고UI Stop으로종료했다. 종료화면은Play삼각버튼/원래5개루트/씬이름의미저장별표없음. TimeScale/captureDelta/카메라/입력장치를변경하지않았으며자체입력장치생성없음. 마지막CLI저장상태재조회는시간초과라미확인이고화면관찰과구분한다. 사용자 입력이감지된후 추가UI조작을중지했다.
