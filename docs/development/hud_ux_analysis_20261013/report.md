# 코어가디언 HUD·UX 시험 분석

2026-10-13 · 읽기 전용 분석 · 모든 배치안은 미적용 제안. **추천은 기존 HUD에 강화 전후 비교와 짧은 성장 피드백을 더하는 A안이며, 통합 전투력은 도입하지 않는다.**

## 1. 현재 HUD 구조 요약

기준은 최신 [HUD 기획](https://www.notion.so/3df389dbfc68811f9a87e5a5ff05a571), PC 조작·게임 루프·플레이어 전투/성장·타워·증강·아트 담당 문서다. 직접 조회한 8페이지 원문과 조회 메타는 [notion_sources.json](notion_sources.json)에 보관했다. 이미지 링크의 배치 시안은 구현 화면으로 취급하지 않았다. 반올림 표시·독립 접기 규칙은 HUD 문서에서 확인했다.

| 실제 구성 | 확인한 구현과 역할 |
|---|---|
| Canvas | `CoreGuardianHud.Configure`에서 런타임 생성하는 uGUI. 실제 Play 계층 `/CoreGuardian_Gameplay/CombatHUD`, Overlay, sorting 2000, CanvasScaler 1920×1080 / Match 0.5 확인. HUD 전용 프리팹은 탐색 범위에서 발견하지 못함 |
| 상단 | 코어 현재/최대, 라운드, 골드, 수정, 선택한 증강 수. 접으면 높이 64→40으로 축소 |
| 하단 | 단계·준비 시간/시작, 설치·플레이어 강화 진입. 플레이어 강화는 준비/전투, 타워 설치·강화는 준비 중 허용 |
| 왼쪽 타워 상세 | 선택한 종류·ID·현재 피해/공속/사거리/투사체 속도 또는 지원 효과, 강화 가격·파괴. 독립 접기 버튼은 없음 |
| 아래 설치/플레이어 패널 | 설치 분류/종류 선택. 플레이어는 능력치 이름·가격의 버튼 4개. 두 패널은 접을 수 있음 |
| 오른쪽 누적 피해 | 라운드 실제 체력 감소량, 내림차순 이름·숫자·막대, 스크롤/접기. 막대는 최댓값 대비 비율이며 DPS/총 피해 점유율이 아님 |
| 전장 피드백 | 명중 실제 감소 체력 숫자, 처치 골드 심볼+숫자·이동/페이드. 승인된 Pixelify Sans Bold는 피해 숫자용, 한글 HUD 전체 교체 아님 |
| 최신 증강 UI | 중앙 카드 3장, 제목·남은 시간·등급 색/문구, 전체 화면 배경과 보스 상태 표시 코드가 추가됨. 실제 계층에 생성된 카드 패널을 확인했으나 관측 시점에는 비활성 |

초기 Edit Mode 조회에는 Canvas가 없었지만 생성 경로 추적과 이후 Play의 읽기 전용 계층 조회로 런타임 존재를 확인했다. [unity_snapshot.json](unity_snapshot.json)의 관측 시각은 2026-10-13 02:55:03 KST, 1920×1080, compiling=false다. 보스 `150/300` 표시가 보인 실행 상태이며 자연 진행 10R 완료나 사람 플레이로 간주하지 않았다. 다른 작업이 Play와 소스를 바꾸고 있으므로 스냅샷은 그 순간의 상태만 증명한다. 이후 상태 조회에서는 Play stopped를 확인했고 새 Play를 시작하지 않았다.

직접 본 화면은 2026-10-10의 [자연 전투 캡처](../../../Assets/docs/development/natural_rounds_20261010_coverage.png)와 [골드/피해 표시 검증 캡처](../../../Assets/docs/development/gold_feedback_after_20261010.png), 둘 다 1280×720이다. 전자는 자동 조작 9R, 후자는 역할 검증 화면이다. 마무리 중 다른 작업이 저장한 2026-10-13 [증강 Game View](../augmentation_selection_20261013.png), 1280×720도 직접 확인했다. 중앙 카드 3장·시간·등급·효과가 보이고, 상단 상태는 전체 배경으로 어두워지며 증강 접기 탭은 보이지 않는다. 이 화면은 [강제 처치 흐름 진단](../boss_augmentation_20261013.md)의 결과로, 자연 진행 난이도/성장 체감 검증이 아니다. 해당 작업의 실제 카드 클릭·회귀 결과는 외부 작업 기록이며 이 분석에서 재실행하지 않았다. 저장 씬·Canvas 계층·코드와 촬영 시점/조건을 구분해 사용했다.

## 2. 확인된 UX 문제점과 근거

| 문제 | 근거와 판정 | 영향 |
|---|---|---|
| 플레이어 강화량을 구매 전에 알 수 없음 | `Build`의 네 버튼은 이름+가격만 표시. 현재값·다음값·증가량 없음. 실행 계층의 비활성 패널 라벨에서도 동일 | 돈을 쓴 결과와 성장 선택을 연결하기 어려움 |
| 타워는 현재값만, 전후 비교 없음 | `Refresh`는 현재 스펙, 구매 버튼은 수정 가격. 증가량/강화 단계 비교 없음 | 선택한 타워의 투자 효과를 기억에 의존 |
| 피해 표기 일관성 차이 | 현재 타워 정보 `Damage.ToString("0.##")`는 12.5를 유지. HUD 기획은 피해 12.5→13 표시 | 원시 스펙과 실제 명중 피해가 같은 숫자처럼 보일 위험. 표시 반올림과 실제 방어/초과 피해 차이는 설명을 분리해야 함 |
| 성장 성공 피드백이 구체적이지 않음 | 일반 Notify/LastMessage 사용, 대상별 이전→이후 수치 없음. 라운드/재화 메시지가 같은 영역 사용 | 연속 구매·처치가 겹치면 무엇이 얼마나 올랐는지 재확인 어려움 |
| 누적 피해 패널의 빈 면적·식별 | 피해 집계가 생긴 대상만 행 생성, 이미지 없음. 과거 캡처에서 큰 빈 패널 확인. 기획은 이미지+이름 요구 | 전장 오른쪽을 차지하면서 초반 정보 효용 낮음. 지원 포탑 미집계는 승인된 직접 피해 기준이므로 결함으로 취급하지 않음 |
| 선택한 타워 패널과 왼쪽 진입 시야 겹침 | 1280×720 과거 사진에서 왼쪽 상단 상세 영역이 진입 경로 일부와 겹침. 독립 접기 없음 | 가설: 선택 후 신규 적·피해를 놓칠 수 있음. 실제 놓침률은 미측정 |
| 해상도별 탭 이탈 | 절대좌표 탭과 앵커 패널이 혼재. 정적 계산에서 1920×1200은 DamageFold 화면 밖, 2560×1080은 아래 접기/취소 이탈 | CanvasScaler만으로 다른 비율 안정성이 보장되지 않음. 실기 창 크기 검증은 미실행 |
| 작은 창에서 글자 축소 | 원본 18/19pt 라벨이 1280×720에서 약 12/12.7px, 960×540에서 9/9.5px로 계산됨 | 판독 위험. 읽기 시간/오독은 사람에게 측정해야 함 |
| 증강 선택의 화면 가림·접기 | 최신 코드의 stretch 전체 배경 alpha .94, 카드 1040×430, 독립 접기 없음. 최신 진단 Game View에서도 상단 상태 어두워짐·접기 탭 없음 확인 | HUD 문서의 상단 유지·독립 접기와 차이. 이 분석의 직접 클릭·사람 판독은 미확인 |
| 증강 후 성장량·클리어 시간 없음 | 증강은 제목/설명과 완료 메시지, 적용 전후 수치 없음. `waveTime`은 라운드 시작에 초기화하고 이전 클리어 기록으로 보존하지 않음 | 새 표시를 제안하려면 전후 스냅샷·완료 시간 계측이 필요. 이미 있는 UI로 보고하지 않음 |

`Prototype.Update`는 증강 단계에서 player를 disable한다. HUD 문서는 접기가 전투/WASD를 멈추지 않는다고 한다. 현재는 증강 접기 자체가 없으므로 ‘접기 후 이동 검증 완료’로 결론 낼 수 없다. 선택 단계 이동 규칙과 표시 접기를 구분해 담당 문서와 후속 구현 검증에서 대조해야 한다.

[layout_metrics.json](layout_metrics.json)의 일반 주 패널 사각형 합은 선택 타워 없음 13.26%, 선택 타워 있음 19.63%, 설치/플레이어까지 펼치면 29.44%다. 디버그 버튼·탭·추가 라벨·증강을 제외한 **부분 사각형 합**이며 실제 불투명 차폐율·보드 가림률·전체 HUD 면적이 아니다. 증강 배경 사각형은 화면 100%를 덮지만 alpha .94를 단순 ‘94% 가림률’로 바꾸지 않는다.

## 3. 정보 우선순위 분석

| 상황 | 상시/핵심 | 행동 직후 | 접이식 상세 |
|---|---|---|---|
| 준비 | 코어·라운드·재화·남은 준비/시작, 설치/강화 진입 | 구매 대상·증가량·사용 재화 | 플레이어/선택 타워 현재→다음·차이·비용, 설치 분류 |
| 전투 | 코어 위험·진행 상태, 전장 명중 피해와 골드, 플레이어 강화 진입 | 성공한 플레이어 강화의 짧은 변화 표시 | 플레이어 비교, 선택 타워 스펙/파괴, 누적 피해 |
| 증강 | 기존 상단 상태·선택 시간·카드 3장과 효과/등급 | 선택한 효과의 적용 대상·변화. 재화/코어 효과는 해당 값으로 | 접기 후 재열기와 선택 상태 보존, 보유 효과 재확인 위치 |
| 라운드 종료→준비 | 보상·다음 행동 | 이번 전투 시간과 결과를 짧게 표시 | 비교 조건·이전 기록·적 구성 등 자세한 설명 |

피해 숫자는 공격 결과, 전후 스펙은 성장 원인, 시간은 전투 결과다. 서로를 대체하지 않는다. 더 큰 피해가 같은 처치 발수로 끝날 수 있고, 라운드가 달라지면 적·스폰 간격 때문에 클리어가 더 느려질 수도 있다. 전투시간 정의는 전투 시작→마지막 적 제거로 제안하되 준비/증강 시간을 제외하고 동일 라운드·배치·조건에서만 성장 비교한다.

## 4. 개선 배치안 3가지

배치도는 이전 1280×720 Game View의 경로·주 패널 위치를 참고한 **분석용 개념도**다. 새 UI를 구현하거나 씬을 변경하지 않았다. [A안](wireframe_a.png) · [B안](wireframe_b.png) · [C안](wireframe_c.png).

**A — 기존 패널 안에서 전후 비교 + 사건 피드백.** 상단/하단 진입 위치 유지. 오른쪽 아래 플레이어 패널에 능력치별 `현재→다음 / 증가량 / 단계 / 골드`를 표시하고, 왼쪽 타워 상세에 선택 종류·ID와 같은 형식의 수정 비교를 넣는다. 타워 상세에도 독립 접기를 제공하는 제안으로 왼쪽 시야를 확보한다. 성공 직후 하단 구매 영역 가까이 대상·증가량을 짧게 표시하고 최종 숫자는 즉시 읽을 수 있게 한다. 계속 확인할 수치는 패널에 남겨 일시 메시지를 놓쳐도 재확인 가능하게 한다. 전투력/전체 스펙을 상시에 추가하지 않는다. 라운드 종료 시간은 다음 준비 하단의 짧은 결과 영역에 제안한다.

**B — 성장 상세를 하단 좌우로 정리.** 플레이어는 오른쪽 아래 유지, 선택 타워 상세는 왼쪽 아래로 이동하여 왼쪽 적 진입 시야를 비운다. 설치 패널은 기존 하단 중앙 왼쪽, 독립 접기/선택 유지. 각 패널에 전후 비교·가격을 넣고 공통 하단 영역에서 짧은 성장/완료 피드백을 제공한다. 동시에 펼칠 때 패널 폭·문장 길이·설치 영역과 간격을 실제 화면으로 검증한다. 한 탭으로 통합하거나 자동 닫아서 기존 독립 조작 규칙을 바꾸지 않는다.

**C — 작은 성장 요약 상시 + 세부 패널.** 하단 버튼 위에 플레이어의 핵심 현재 스펙 1~2개와 선택 타워 종류/핵심 스펙을 구분한 두 줄을 상시 제안한다. 강화 직후 그 줄에 증가량을 잠깐 강조하고 세부 능력치/비용은 기존 접이식 패널에 둔다. 선택 타워가 없으면 타워 요약을 숨긴다. 공격/지원에 동일한 공격력 줄을 강제하지 않는다. 완료 시간은 준비 단계에서만 요약 줄을 잠시 활용한다.

세 안 공통: 증강의 카드 수·등급·시간·자동 선택 규칙을 유지한다. 선택 전 카드 설명에 효과 대상과 기존 스펙 변화가 계산 가능한 경우만 보조 비교를 넣고, 선택 후 짧은 대상별 변화 피드백을 제공한다. 지원·추가타·처치 효과를 무조건 ‘DPS +N%’로 바꾸지 않는다. 숫자 변화 애니메이션은 짧게, 실제 성공 뒤에만 실행하는 제안이다. 피드백 보존/중첩 방식·접기·상단 유지의 구현은 별도 승인 후 대상이다.

## 5. 각 배치안의 장단점

| 안 | 장점 | 단점·필요 검증 |
|---|---|---|
| A | 기존 조작 위치와 시야 유지, 구매 원인/결과를 같은 곳에서 이해, 상시 숫자 추가 적음 | 기존 타워 상세의 진입 가림은 펼친 동안 남음. 비교 행 추가 시 작은 창에서 높이·글자 재배치 필요 |
| B | 왼쪽 진입 적·타워를 보기 쉬움, 성장 정보가 하단에 모임 | 타워 상세 위치 학습 필요, 하단 설치·여러 패널·긴 라벨 동시 표시 혼잡 위험 |
| C | 강화 후 숫자 성장을 계속 확인, 패널을 닫아도 기본 스펙 판독 가능 | 상시 면적/주의 분산 증가, 제한된 스펙만 대표하면 지원·사거리 빌드 가치 누락 가능 |

공통 새 데이터 요구: 능력치 현재값/강화 Delta/가격/단계는 기존 데이터에서 읽고 계산 가능하지만 표시 자체는 미구현이다. 성공 사건의 전후 기록·증강 변화 내역 보존·완료 시간 기록은 추가 계측/표시 작업이다. 현재 실제 실측 DPS·클리어 개선량은 확보하지 못했다.

## 6. 가장 추천하는 안과 이유

**A안을 우선한다.** 현재 가장 명확한 결손은 ‘플레이어 가격만 보임 / 타워 현재값만 보임’이다. 기존 패널의 전후 비교와 짧은 성공 피드백이 이를 직접 해결하며 전장 위 새 상시 계기판을 늘리지 않는다. 기존 접기 규칙을 유지하고 타워 접기를 보완한 뒤에도 진입 적 놓침이 남으면 B를 비교한다. 닫힌 패널에서 자신의 현재 성장을 찾기 어렵다는 플레이테스트 결과가 있으면 C의 작은 요약을 재검토한다.

**통합 전투력은 지금 필요하지 않다.** 공격력·공속·사거리·투사체·지원·증강의 조건부 효과를 하나로 합칠 승인된 공식이 없고, 단일 점수가 배치/타깃/지원 가치를 숨길 수 있다. 플레이어와 타워 스펙을 분리해 보여주고 실전 피해와 조건이 같은 완료 시간으로 결과를 확인한다. 필요하면 상세 패널에만 `단일 대상·연속 명중 가정의 예상 화력` 같은 조건부 보조값을 검토하되 총 전투력으로 표현하지 않는다. 이는 새 능력치 도입 없이 성장 체감을 강화하는 방향이다.

## 7. 직접 플레이테스트로 검증할 항목

| 항목 | 조건·측정 | 제안 반증/수정 기준 |
|---|---|---|
| 전후 비교 이해 | 강화 전 현재·다음·증가량·가격을 설명하고 1회 구매. 플레이어/타워/지원 각각 | 어느 대상/재화/수치가 바뀌는지 오답이면 행/표현 수정 |
| 전투 중 구매 피드백 | 이동·명중·골드가 겹친 때 성공/부족 재화/연속 구매 | 증가량 놓침·메시지 덮임·실패 시 가짜 증가가 나오면 사건 표시 수정 |
| 경로 시야 | 같은 배치·웨이브에서 상세 열림/접힘, A/B 비교 | 신규 적·코어 위험 놓침 증가 또는 UI가 이동 클릭을 가로채면 위치/크기 재검토 |
| 수치 만족감 | 같은 적·공격 조건에서 강화 전후 명중 숫자·처치 발수·시간 기록 | 더 강해졌다는 판독이 없으면 강조/비교 개선. 숫자만 크고 결과 변화 없음을 숨기지 않음 |
| 증강 | 10R 실제 완료→3카드→선택/시간초과→다음 준비. 접기/재열기 포함 | 시간/등급/효과·상단 재화 못 읽음, 상태 초기화, 조작 규칙 충돌이면 수정 |
| 다양한 창 | 1280×720, 1920×1080, 1920×1200, 2560×1080; 추가 작은 창은 지원 여부 별도 결정 | 접기/취소 화면 밖, 문장/큰 재화 잘림, 폰트 오독이면 앵커·최소 레이아웃 조정 |
| 완료 시간 의미 | 동일 라운드·적/스폰·배치·조건·배속에서 성장 전후 비교 | 다른 라운드 시간을 성능 개선으로 해석하면 표시의 조건/설명 수정 |

**확인한 범위:** 최신 노션 8개 담당 문서, HUD/세션/조작/효과/성장 데이터 코드, 프리팹 경로 탐색, 열린 전투 씬과 실행 Canvas/비활성 상세·증강 계층, 과거 Game View 2장과 최신 증강 진단 화면 1장, 일반 패널 6해상도 계산, 독립 스킬 사용 시험. 원문/계층/소스 기록과 [검증 기록](validation.md)을 함께 보관했다.

**확인하지 못한 범위:** 자연 진행 증강 완료·자동 선택의 직접 조작, 사람의 가독성/만족감/시야 놓침, 최신 화면의 해상도 변경 시험·정확한 보드 가림률, 성장 전후 실측 DPS/클리어 시간. 노션 이미지 자산 자체는 내려받아 검토하지 않았으며 원문 규칙과 Game View를 기준으로 삼았다. 게임 회귀/새 Play를 실행하지 않았고 게임·노션·UI를 변경하지 않았다. 분석과 배치 제안은 구현/UX 승인과 구분한다.
