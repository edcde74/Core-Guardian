# 역할과 상태
<mention-date start="2026-10-20"/> 기준 대량 전투의 성능 목표·최적화 후보·동등성 검증 기준을 관리합니다. 전투/경제 수치는 해당 기획서, 시각 규격은 <mention-page url="https://app.notion.com/p/3fb389dbfc68813ab657f4600eeae76f"/>, HUD 표시 규칙은 <mention-page url="https://app.notion.com/p/3df389dbfc68811f9a87e5a5ff05a571"/>, 상세 계측·검사 이력은 <mention-page url="https://app.notion.com/p/3df389dbfc6881fc9f1bd004adfc5999"/>가 담당합니다.
사용자는 현30R 성장·물량 방향이 더 재미있다고 평가하고 강한 최적화를 요청했습니다. 이후 **측정 결과부터 보고 결정**을 선택했습니다. 현재는 사전계측 완료·최적화 구현 미착수·제안 검토 단계입니다. 이번 기획서 작성은 구현 승인이나 최적화 완료를 뜻하지 않습니다.
# 목표와 보존 조건
- 적 수·출현 간격·체력/방어·공격·가격·수입·증강 효과/확률·선택 타이밍을 유지합니다. 최적화를 이유로 현재 압박과 성장 빈도를 낮추지 않습니다.
- 기존 원본/방향 보행·사진 그림자·체력바·상시 강조·선택선·피격/강화/국소 발광·금화 심볼·피해 숫자의 표시 수와 지속시간을 유지합니다. 효과 삭제·표시 수 제한·사운드 생략을 기본 해결책으로 삼지 않습니다.
- 풀 재사용 시 현재 타깃/알파/색/수명/애니메이션/그림자/체력 표시·이벤트 구독을 초기화하고 재시작/씬 종료 후 잔여 객체·중복 효과음·지원 전투 효과음이 생기지 않아야 합니다.
- HUD는 피해 누적·최대 피해 대비 막대 비율·역할 심볼·접힘 중 집계·다시 펼침·동적 정렬을 보존합니다. WASD가 버튼 탐색으로 새지 않도록 현재 입력 분리를 유지합니다.
- 성능 목표치는 대상 PC·해상도·1/2/3배속·일반/최대 동시 적 수를 명시한 뒤 확정합니다. PC60FPS/16.7ms는 검토 가능한 목표이며 합의/달성으로 표시하지 않습니다.

# 구현 후보와 순서 — 미적용
## 1. HUD·전투 표시 객체 재사용과 뷰 캐시
피해 행을 매번 삭제·재생성하지 않고 값/막대/정렬만 갱신합니다. 피해/골드 숫자·탄환·명중/처치 효과는 기존 표시를 유지하는 재사용을 검토합니다. 반복 GetComponent·컴포넌트 탐색·활성ID 집합 생성도 캐시 가능성을 확인합니다. 목표는 생성/삭제 피크와 지속 할당을 줄이는 것입니다. 메모리 잔류·풀 초기화·이벤트 중복 회귀를 확인합니다.
## 2. 개체 표현·외곽 강조 렌더 작업 통합
같은 외형을 유지하면서 개체별 마스크/재질/렌더 타깃 작업과 SetPass를 줄이는 방안을 비교합니다. 마스크 공유/아틀라스/배칭은 후보이며 구현 방법은 미확정입니다. 상시 강조를 끄거나 본체 조각·애니메이션·그림자를 삭제하는 안은 아닙니다. 장면/자세/피격/강화/선택 중첩의 픽셀·동작 검사가 필요합니다.
## 3. Session 반복 계산·임시 할당 감소
버프 공급자만의 목록·사거리 후보·우선순위 top3·투사체 목록 정리를 검토합니다. 최초 조준/유지/일반 적 진입 시 보스 조준 해제·같은 HP/거리/ID 타이브레이크·같은 Tick 순서·투사체 이벤트/음성 횟수를 유지합니다. 이것만으로 화면 성능 문제가 해결된다고 단정하지 않습니다.
추천은1부터 적용하고2를 이어가는 것입니다.3은 보조 과제입니다. 실제 구현 범위/방법은 사용자의 측정 후 결정을 받은 다음 진행합니다.
# 검증 계약
1. 비교 전 HEAD/코드/CSV 해시, Unity/플랫폼/해상도·VSync/프레임 제한·배속·카메라·활성 효과·실제 설치 수를 기록합니다. 반복할 때마다 조건을 바꾸지 않습니다.
2. 각 단계마다 같은 적 수/종류·위치·포탑·공격·워밍업·관측 길이를 사용하고 충분한 표본의 중앙/p95/p99·최대·GC할당·GC회수·DrawCalls/SetPass·메모리와 프레임 진행을 기록합니다. 현재 소표본의 최고값을 p99로 부르지 않습니다.
3. Session 변경 시 같은 로직·정책 버전·대응 시드/시간 간격으로 생성/이동/타깃/발사/명중/피해/골드/수정/코어/증강/승패와 이벤트 순서를 비교합니다. 기존 미지정 시드8회는 결정론적 대조가 아닙니다.
4. UI/효과 재사용은 실제 씬 구매·접기/펼치기·정렬·실패/재시작·지원 무음·발사당1회 사운드를 검사하고 기존 표현의 동등성을 확인합니다. 기능QA·사람 체감·성능 결과를 구분합니다.
5. 게임 빌드 성능은 사용자가 별도로 빌드/실행을 요청할 때 측정합니다. 기존 Editor 진단을 배포 성능 통과로 승격하지 않습니다.
6. 사용자 Play/다른 채팅 검사를 중단/중복하지 않습니다. 자체Play·입력 장치·TimeScale/captureDelta·백그라운드·카메라/표시 토글은 복원하고 씬 하나/저장 상태를 확인합니다.
