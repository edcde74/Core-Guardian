# Y축 이동 시 실제 앞·뒤 보행 프레임 전환

2026-10-16. 복구 기준 `6590138`. 사용자 확인: ‘걷기는 하지만 위·아래 방향 동작으로 바뀌지 않음’. 별도 방향 원본은 없으며 ‘현재 원본 기준으로 제작’을 지시했다.

## 원인과 수정

이전 수정은 Y축 속도 전달과 다리 관절 움직임만 검증했다. `CoreGuardianUnitAnimation.Direction`이 상/하로 바뀌어도 `CoreGuardianOriginalWalk`는 이전 좌우 외형을 유지했다. 따라서 이전 ‘네 방향 확인’은 사용자가 요구한 실제 앞·뒤 모습 전환을 증명하지 못했다.

- 실제 웨이포인트 월드 변위의 주축으로 표시 방향을 선택한다. Y+에서는 `Up_0..3` 뒷방향, Y-에서는 `Down_0..3` 앞방향을 사용한다. 방향별4프레임, 몬스터3종+보스 총32프레임이다.
- X축으로 돌아오면 원래의 원본 픽셀 관절 보행으로 즉시 복귀한다. 기존 X 보행/좌우 반전/지면 중심 보정을 변경하지 않았다.
- 이동 거리 기반 주기를 유지한다. Y 방향에서 정지하면 그 방향0번 프레임을 유지하며, 본체 원본 PNG/원본 프리팹/씬을 덮어쓰지 않았다.
- 파생 프레임은 `Assets/Resources/CoreGuardian/VerticalWalk/{Attack,Defense,Buff,Boss}`에 별도 저장했다. Unity API로 임포트, 96×112 캔버스·PPU32·지면 피벗48,3·Point·무압축·mipmap없음.

## 원본 기준 제작·비교

[생성 원본](Source/)은 현재 적용 원본 PNG를 편집 참조로 사용했다. 이미지 생성 스킬을 사용했고, 원본3종 비교판을 공통 화풍 참조로 넣었다. 새 캐릭터/장비를 추가하지 않았다. 생성 원본만 보고 픽셀 일치를 완료 처리하지 않았다.

[정규화 스크립트](NormalizeVertical.cs)는 유형별 원본 팔레트로 색을 맞추고, 투구~발 높이 기준의 공통 배율을 양방향/전체 프레임에 적용한다. 깃발/무기 전체 높이로 본체가 축소되지 않게 했다. 버프형의 떨어진 생성 잡점이 발 중심 계산을 오염시키는 것을 제거했다. 원본 PNG에는 정규화/제거를 적용하지 않았다.

- [같은3배 픽셀 비교판](native3x_comparison.png): 원본 / 상행4 / 하행4. 모든 칸 같은 원본3배 격자이며 새 이미지만 임의 확대하지 않았다.
- [실제 Unity 움직이는 비교](four_directions.webp), [대표 프레임](four_directions.png): 원본 / X+ / X- / Y+ / Y-, 행 공격/수비/버프/보스.
- 파생 시점의 투구 뒤/앞, 방패/창/깃발/망치의 해부학적 손 방향을 비교했다. **방향 전환 기능 적용과 새 파생 아트의 최종 사용자 승인은 구분한다.** 뒷모습은 기존에 없던 새 시점이며 기존 원본과 픽셀이 전부 같다는 의미가 아니다.
