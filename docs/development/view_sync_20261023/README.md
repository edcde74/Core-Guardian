## 판정: 변동 범위 내, 후보 미채택·제품 원본 복구

적 본체와 애니메이션에 현재 world 좌표를 전달하는 후보를 구현·대상 검증·일반 비교했다. 직접 CPU 평균은 조금 낮았지만 실행별 범위와 겹치고 전체 프레임/FPS 개선이 없었다. 호출 수 감소를 성능 성공으로 채택하지 않았다. 두 제품 파일은 시작 백업으로 바이트 복구했고 HEAD 대비 해당 파일·Session diff는 0이다. 고정 마커도 제품에는 남기지 않았다. 후보와 테스트는 이 폴더에 격리했다.

- [계획](../../superpowers/plans/2026-10-23-view-synchronization.md) Task1+2만. 적/포탑/포탄 고정 마커, 개체 좌표 재사용, 관련 회귀, 일반 `warm15+sample90 × 3` 각각. 유효 구간은 총630프레임(워밍업90+표본540)이다.
- 호출 수 진단은 성능 계측과 분리한15프레임씩이다. 처음의 aura 재사용 후보는 콜백 회귀로 폐기했고 최종 축소 후보의15프레임 진단을 따로 보존했다. 진단 증가 코드는 성능 실행 전에 원복했다. Session의 최종 hash는 시작과 같다.
- Task3·렌더/셰이더/전투 판정 변경 없음. 사용자 설정/씬/미추적 및 기존 강조/그림자/TMP 변경 보존. A 보류/B 제한, 아틀라스 보류, 원본/fallback, native batch OFF 유지. 빌드·실행파일 실행·커밋·push 없음.

## 구현과 콜백 안전성

후보는 `SynchronizeViews`에서 적 currentWorld를 계산해 본체와 `Enemy(enemy,view,currentWorld)`에 전달했다. 기존 두 인자 API는 유지했다. previousEnemies에는 tile을 보존하고, 이전 tile을 현재 Grid에서 변환했다. 수식/표시 주기/적·포탄 목록/포탑 live API·타깃/지원 검증/보행·조준을 바꾸지 않았다.

aura 자신의 활성 전환뿐 아니라 애니메이션 `Present`가 하위 rig를 SetActive하며 실행하는 콜백도 Grid/모델을 바꿀 수 있다. 초기 aura 재사용은 실제 회귀에서 3.605551 위치 오차로 실패했다. 최종 후보는 **Present 뒤 aura 생성·배치의 World 재계산을 전부 유지**했다. 포탑 좌표 재사용도 같은 안전한 경계를 입증하지 못해 제외했다. 최초 Attach 이후는 전달된 좌표를 신뢰하지 않고 기존 live 계산을 보존했다. [검토와 보강](REVIEW.md).

## 검증과 실패 기록

- 최초 신규 테스트2개: API 없는 상태1실패/1통과. 테스트 fixture의 비교 범위(원본 prefab에는 런타임 HP bar 없음)와 timeScale 변경 후 player-loop 시간 갱신 대기를 바로잡았다. 이후 aura 생성 콜백 회귀1실패→보강 후3/3통과.
- 독립 소스 검토에서 Present 자식 콜백 누락 확인. [실행 RED](present_callback_red.json)→최종 [신규5/5](green_candidate_final.json). 네 역할·세 Grid 변형·네 이동 방향의 같은 위상 rig sprite/위치/회전/색/enabled 비교, dt=0, 직접 Release, 실제 풀 재대여·같은 ID 새 세대, aura 생성/활성/Present 콜백을 확인했다.
- 기존 보행 `CoreGuardianOriginalGaitTests`21/21, 조준 `CoreGuardianSingleTowerAimTests`8/8 통과. 신규 포함34개다. 이 결과는 후보 상태의 대상 검증이며 복구 후 후보 테스트를 다시 실행한 것이 아니다.
- 초기 마커 삽입에서 LF/CRLF 처리로 생긴 중괄호 컴파일 오류를 수정했다. 이후 컴파일 정상. 실패를 숨기지 않으며 최종 재컴파일 compilationFailed=false, 현재 consoleErrors0.
- 첫 후보 시작 요청은 메인 스레드5초 timeout으로 실행 여부가 불명확했다. 사용자 승인 상태 조회에서 자체 작업/Play 없음·복원 상태를 확인한 뒤 재개했다. 사용량 제한으로 자동 승인 검토가 실패한 요청도 실행하지 못한 것으로 구분했다.
- 후보2는1920×1080/ortho8.5 조건 guard에서 표본0·종료/복원. 실패를 확인한 호출에서 후보3 요청까지 보낸 절차 오류를 보고했다. 후보3은 정상90표본. 사용자가 **후보2만1회 재실행**을 명시 승인해 완료했다. [실패 원본](failed_after_2_benchmark_completion.json)과 복원을 보존했다. 화면·카메라 선택을 변경하지 않았다.
