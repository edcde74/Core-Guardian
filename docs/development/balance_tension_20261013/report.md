# 긴박함을 높이는 밸런스 분석

2026-10-13. core-guardian-balance 사용. 게임 데이터·코드·씬·노션은 변경하지 않았다. 새 Play/전투 시뮬레이션/회귀 검사 없음. 현재 1~11R 데이터 로딩을 에디터에서 읽기 확인했고 기존 정적 도구를 재사용했다. [출처·현재 상태](sources.json), [정적 계산](static/rounds.csv), [성장 계산](static/growth.json). 재미 평가는 분석자의 미검증 가설이다.

## 1. 현재 상태

일괄 난이도 상승보다 압박이 몰리는 순간과 대응 후 해소를 만드는 방향을 우선한다. 과거 자동 Play에서는 고정 배치/구매 정책에 따라6R·7R 패배와9R 코어20 완료가 갈렸다. 모든 배치가 쉽다는 근거는 없으며 포탑·기술병 위치를 함께 바꿔 배치 하나의 단독 효과도 확정할 수 없다. 보스/증강은 현재 구현됐지만 자연 진행10~11R 난이도/사람 체감은 미측정이다. 노션의 과거 구현 현황1~9R은 오래된 상태이며 이번에 수정하지 않았다.

## 3. 원인 가설과 반증

- 균일한 유입 때문에 고정 배치가 막으면 반복 대응할 이유가 적을 수 있다. 같은 구간에서도 사람 이동/강화 대응이 충분히 발생하면 이 가설은 약해진다.
- 초반 구매 공백·기술병 미기여가 긴박함 대신 기다림을 만들 수 있다. 실제1배속에서 이동·배치 학습이 활발하면 기다림이라는 평가는 수정한다.
- 적 누수가 실패 압박과 함께 라운드를107~114초로 늘린 과거 사례가 있다. 체력만 높이면 해결해야 하는 상황보다 잔여 적 기다림이 증가할 위험이 있다.
- 보스 위협은 현재 코어 절반 손실+120골드/첫 증강 상실로 이미 크다. 손실을 더 키우기 전에 보스가 실제로 얼마 남은 거리에서 반피가 되는지 확인한다.

## 5. 추천

A를6R 한 구간에서 먼저 비교한다. 첫 강화/추가 설치가 가능한 시점과 압박을 연결하고 일반 적 총량/성장 비용/보상을 고정해 한 변수로 검증할 수 있다. 기술병이 빈 구간을 보완하고 범위 포탑의 다중 대상 가치가 생기는지를 확인한다. 동시에 모든 라운드 압축/가격 변경/적HP 증가를 적용하지 않는다. 강한 빌드가 대응을 잘하면 여전히 편하게 돌파하도록 유지한다. 11R은 이미 생성밀도가 높고 첫 증강 보상 확인 구간이므로 먼저 유지한다. B는 자연 보스 플레이에서 위협이 부족하다고 확인될 때 비교, C는 실제 준비 체류가 길 때 후속 비교.

## 6. 실제 플레이 검증

- 1배속, 같은 배치·강화·구매·시작 버튼 정책으로 기존6R과A를 비교하고 각3회 이상 탐색한다. 소규모 표본이며 통계적 확정으로 쓰지 않는다.
- 먼저 기술병고정 조건으로 수급/코어손실/동시적/처치시간을 비교하고, 다음 실제 입력 조건에서 이동으로 누수를 줄일 수 있는지 비교한다. 기술병/타워 배치를동시에 바꾸지 않는다.
- 집중구간 동시 생존 적 수, 1마리/2~3마리 타깃 발사 비율, 기술병/타워 실제피해, 잔여적 정리시간, 코어손실·처치골드·실패율 기록. 생성최대와 전장최대를 혼동하지 않는다.
- 행동이 필요했던 순간·그 이유의 이해·대응 후 안정감을 사람에게 확인한다. 코어피해만 증가하고 대응이 불가능하거나 정리시간만 길어지면 가안 중단/간격완화.
- 10R은 보스 반피 시각/위치/잔여거리·버프동행·처치/도착·총전투시간을 자연공격으로 확인. 강제 처치 검사는 난이도 근거에사용하지 않는다.
- 11R은 카드 등급·종류·선택전후 스펙·투자·동일배치 조건을 분리한다. 첫 선택1개에서 복수증강 조합을 가정하지 않고 무피해 보너스는11R 종료 지급으로 처리한다. 강한 카드의압도감 자체는 유지한다.

게임/노션/아트/기존BGM/HUD 변경 없음. 실제로 읽고 계산한 범위만 기록했다.
