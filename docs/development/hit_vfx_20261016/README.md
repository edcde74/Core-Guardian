# 공격별 타격 VFX 시안 3종

2026-10-16. 사용자 요청: 둔화보다 현재 기본 공격의 타격 VFX/피드백을 우선하며, 소리는 별도 사운드 파트에서 검토한다. 다수 타워의 공격에서 시청각 혼잡을 우려했다. 기술병/단일 포탑/범위 포탑을 구별한 시안을 약3개 제작해 보고하도록 요청했다.

## 결과와 범위

**게임 밖의 움직이는 시안과 투명 스프라이트 시트다. Unity 적용/게임 기능 완료/사용자 아트 승인이 아니다.** 게임 Play, 빌드, 실행파일 실행, 씬·프리팹·CSV·기존 코드 수정 없음. 사운드 제작/연결 없음. 둔화 시안은 보관하고 이번 작업에서 제외했다.

| 시안 | 명중 표현 | 시안용 지속/피격 밝기 | 파일 |
|---|---|---|---|
| 기술병 | 황동/금색의 짧은 금속 파편. 크림색 핵심 섬광 뒤 조각이 흩어짐 | 160ms / 최대18% 밝기 혼합,65ms 내 복귀 | 01_engineer.gif / 01_engineer_sheet.png |
| 단일 포탑 | 탄 진행 방향으로 길게 뻗는 청록 수정 스파크. 금속 조각보다 곧은 형태 | 200ms / 최대22%,65ms 내 복귀 | 02_single.gif / 02_single_sheet.png |
| 범위 포탑 | 각 대상에 개별로 표시하는 짧고 작은 수정 파편. 스플래시 원/폭발 없음 | 120ms / 최대14%,65ms 내 복귀 | 03_multi.gif / 03_multi_sheet.png |

세 GIF는 왼쪽부터 공격형/수비형/버프형 원본이다. 모두 같은 원본 도트3배 Nearest 확대이며 종류별로 크기를 따로 맞추지 않았다. 기술병/단일 포탑의 세 열은 서로 다른 적에게 같은 공격을 시험한 비교이며 동시에 세 대상을 공격한다는 뜻이 아니다. 범위 포탑은 실제 구조를 고려해 각 대상의 개별 명중을 같은 시점에 예시했다. 타워/플레이어의 발사 동작을 새로 제작한 영상은 아니다.

피해 숫자는 시안에서만 12를 예시로 썼다. 실제 게임에서 측정한 피해량/공격속도/체력 변화가 아니다. 작은 고정 체력 막대는 겹침 확인용이며 시안 명중에 따라 갱신되지 않는다. 프리뷰 숫자 폰트는 작은 코드 도트로 타이밍을 확인한 것이고 승인 Pixelify Sans를 교체한 것이 아니다.

## 집중 공격 표시 제안

각 `_dense.gif`는 대상마다45ms 간격20회 입력을 준 합성 시각 검사다. 현재 게임 공격속도로 간주하지 않는다.

- 명중 스파크/피격 밝기는 대상별100ms 재표시 간격을 적용하는 후보를 시험했다. 입력 간격45ms 때문에 실제 표시 간격은135ms가 돼20회 입력에서7회 표시된다. 표시 생략은 피해 판정 생략을 뜻하지 않는다. 게임에는 적용하지 않았다.
- 피해 숫자는 대상별200ms 묶음 안의 입력을 합산해 갱신하고 두 가로 위치로 분리하는 후보를 시험했다. 예시 합계240을60/48/60/48/24로 보존한다. 현재 게임의 숫자 정책을 확정한 것이 아니다.
- 히트스톱·넉백·카메라 흔들림·화면 섬광·Bloom 없음. 적의 위치·비율은 고정한 채 약한 밝기 변화만 표시한다.

## 제공물

- `preview.html`: 세 단발 GIF와 접어서 열 수 있는 집중 공격 GIF. 이미지 파일을 같은 폴더에 둔다. 자동 재생 GIF이며 브라우저 UI 재생 조작 기능은 없다.
- `01/02/03...gif`: 단발/집중 공격6개. 864×336,40ms 기반 프레임. 정지 중 중복 프레임은 GIF 인코더가 합쳐 시간은 유지한다.
- `*_poster.png`: 각 시안640ms 시점의 정적 프레임. 세 대상 중 일부는 탄 비행/명중 시점이 다르다.
- `*_sheet.png`: 각192×32 투명 스프라이트 시트. 32×32셀6개, 중앙(16,16) 기준, 좌→우 시간 진행. 아직 Unity 임포트·PPU·최종 크기·피격 조합을 확정하지 않았다.
- `all_phases.png`: 행 기술병/단일/범위, 열240/600/640/720/1200ms. 각 칸에 적3종이 포함된다.
- `specs.json`, `make_previews.cjs`: 원본좌표·색·파편 이동·밝기·시간과 재생성 코드. 새 이펙트는 정수 픽셀의 선/사각 파편을 코드로 작성했다. 고해상도 픽셀풍 생성 이미지가 아니다.

## 확인 근거

- UNITY_HANDOVER와 MONSTER_ART_STYLE를 읽고 현재 병사3종 및 지정 기준 비교판, 승인 CombatB 원본을 직접 열어 확인했다.
- 기준 병사42×64/33×48/35×80 원본 유지. 탄은 승인 CombatB의 EngineerChip/SingleBolt/MultiBolt rect를 읽어 프리뷰용 작은 크기로 Nearest 표시했다. 프리뷰가 기존 PPU/게임 크기와 완전히 같다고 주장하지 않는다.
- 새 정적 포스터3개를 직접 열어 금속/수정 색과 길이, 기존 병사 윤곽이 읽히는지 확인했다. 자연스러움/타격감/아트 승인은 사용자 검토가 필요하다.
- `checks.json`: GIF6개가 실제 다중 프레임으로 인코딩됨, 원본 크기/정수 확대, 효과 종료 후 원본 상태와 렌더 버퍼 일치, 서로 다른 공격 표현, 묶음 숫자 총합 보존을 새 실행으로 확인했다. 브라우저나 Unity의 실제 재생 화면 검사/다수 타워 성능 검증은 아니다.
- `encoding_checks.json`: 최종 GIF6개를 다시 디코딩해 모든 프레임의 양수 지연과 전체 길이(단발1840ms/집중2200ms), 투명 시트3개의192×32/alpha를 확인했다. 실제 인코딩된 GIF에서 프레임을 추출한 `*_encoded_frame.png`3개도 직접 열어 확인했다.
- 이전 file URL 브라우저 접근 거부를 우회하지 않고 로컬 래스터 렌더러/인코더로 자료를 생성했다. 프로젝트 실행이나 UI 자동화가 아니다.

## 다음

사용자 검토에서 각 공격의 형태·크기·명중 순간 강도·잔상 길이를 선택/수정한다. 이후 Unity 연결 시 실제 피해 발생 이벤트를 기준으로 명중을 표시하고, 관절별 SpriteRenderer에 피격 상태를 동기화하며 실제 정상 전투의 집중 공격을 확인한다. 100ms/200ms 표시 정책은 후보이며 임의의 확정 규칙으로 적용하지 않는다. 사운드는 별도 작업으로 남긴다.
