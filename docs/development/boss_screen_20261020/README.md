# 10R 방패병 선행·타워 보스 후순위 적용 · 2026-10-20

사용자가 실제 플레이에서 ‘보스가 먼저 나와 먼저 타깃이 돼 너무 쉽다’고 지적하고 방패병3마리 빠른 순차 생성→보스, 타워 보스 최후순위를 지시했다. 복구 기준 `43562a5`. 다중피해11에 대한 ‘낫베드’는 유지 피드백으로 받아들이며 전체 밸런스 승인으로 확대하지 않는다.

전체15명(보스1+일반14), 보상·적 능력치·다른 라운드·증강·준비 시간은 유지한다. waves.csv 두 행의 시작/간격만 변경했다. 0.25초는 ‘사사삭’ 순차 출현을 위한 첫 적용값이며 실제 화면의 적절한 간격은 사람 확인이 필요하다.

타워 재선택/다중 공격 대상 순서는 **수비형→버프형→공격형→보스**다. 같은 유형은 기존 체력→남은 경로 거리→ID 순이다. 보스 체력이1이라도 일반 적보다 뒤다. 플레이어용 기존 CombatRules.Priority와 조준 유지 규칙은 변경하지 않았다.

- 단일 포탑 최초 획득은 기존 일반 적 첫 도착 순서를 유지하되 보스를 뒤로 둔다. 일반 적 대상은 생존/사거리 안인 동안 유지한다. 보스를 조준하던 중 사거리 안에 일반 적이 들어오면 보스 조준을 풀고 일반 적을 재선택한다. 일반 적이 전부 사거리 밖이면 보스를 공격할 수 있다.
- 다중은 매 공격의 최대3대상과 포신의 TowerTarget 조회가 같은 새 정렬을 사용한다. 일반 적이3명 이상이면 보스가 빠지고, 일반 적이1~2명이면 남는 대상 자리에 보스가 포함될 수 있다. 보스를 무조건 공격 금지한 것은 아니다.
- 이미 발사한 탄환의 대상·공격 주기·탄수·사운드 이벤트는 유지한다. 타깃 전환 시 쿨다운을 초기화해 공짜 공격을 만들지 않는다.

## 검증

구현 후 전체 Edit156/157에서 기존 증강 검사의 ‘첫 적은 보스1명’ 전제가 실패했다. 해당 fixture만 보스 등장까지0.8초 대기/방패병3명+보스1명 검증으로 맞췄고 보상120·다음 라운드/증강 단계 차단·수정340·선택1회·11R종료 주장은 유지했다. 최종 **전체 Edit157/157** 통과다.
