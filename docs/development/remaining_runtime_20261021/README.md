# 남은 런타임 계산·조회 최적화

2026-10-21 Asia/Seoul. 복구 기준 `b1ecb13`. 사용자는 제시된 다섯 후보를 모두 진행하도록 승인했다. Play·자동 테스트·성능 측정 보류는 유지한다. [범위/실행 계획](PLAN.md). 이번 변경은 묶음이며 개별 기법의 성능 기여를 측정/분배하지 않았다.

## 적용한 다섯 항목

1. **포탑 참조·발사 정보 재사용:** TowerState가 정상 양수/0 ID의 `Tower:`/`Support:` 키를 재사용한다. ID 변경 시 갱신하고 음수 ID는 현재 문화권의 부호를 매번 반영한다. Session은 출처의 부호 없는 ASCII 숫자 해석만 최대512개 캐시한다. 포탑 참조 표는 목록 순서/객체/현재ID를 확인하며 첫 중복ID 규칙·교체/철거를 반영한다. Animation/Audio는 이 조회를 쓰며 사운드 선택·횟수·재생 제한·볼륨은 그대로다.
2. **지원 버프 계산 재사용:** 포탑 목록/병종과 지원 포탑의 위치/범위/버프 값을 비교해 위치별 합계·범위 포함 여부를 최대256개 재사용한다. 원래 지원 목록 순서의 double 누산 후 float 변환을 유지한다. 범위 포함과 버프 수치는 분리해 값0인 지원 포탑의 기존 강조 표시도 보존한다. 틱 진입·발사 이벤트 전후에는 변경 확인을 예약하며 공개 뷰 조회에서는 즉시 확인한다.
3. **경로 구간 탐색:** 길이가 정확한 정수이고 전체 길이가2^20 이하인 축 방향 경로는 누적 끝점을 이진 탐색한다. 음수/비유한/범위 밖 진행값과 지원하지 않는 경로는 원래 순차 뺄셈이다. 지원 범위의 누적 길이·국소 길이는 정확한 정수 뺄셈으로 기존 위치/잔여거리·경계의 이전 구간 선택을 유지한다. 이동식·속도·사거리·타깃 순위는 변경하지 않았다.
4. **다중 포탑 화면 조준:** 다중 포탑이 있을 때 뷰 갱신의 포탑 구간에서 별도 구역 인덱스를 구축한다. 조회마다 현재 적 목록/순서/참조/좌표/생존 상태를 확인하고, HP/종류/잔여경로는 현재값으로 비교한다. finally에서 참조를 비운다. 다중 포탑이 없으면 구축하지 않는다. 독립 공개 `TowerTarget(id)`는 현재 상태를 선형 조회한다.
5. **발사 후 공간 탐색 유지:** 콜백 뒤 무조건 선형으로 돌아가던 경로를 바꿨다. 다음 조회 전 적 목록/순서/참조/좌표/생존 상태가 같으면 기존 구역을 유지하고 다르면 재구축한다. 콜백 중 Tick 재진입은 호출별 인덱스를 유지하고, 콜백 전후 모두 변경 확인을 예약한다. 기존 거리 포함식과 열거 순서·임계값/비유한 범위 폴백은 유지한다.

제품 소스5개(Session, CombatData, Animation, Audio, Prototype)·기존 EditMode 소스1개를 변경했다. 씬/프리팹/CSV/전역 설정은 수정하지 않았다. 타입→낮은HP→남은경로, 최초 선택·대상 유지, 발사/피해/사운드/표시 수·수명은 유지하는 구현이다.

## 적용하지 않은 항목과 비용 절충

- **EnemyState/ProjectileState 모델 풀링은 미적용이다.** 객체가 공개 목록·이벤트·타깃 참조로 외부에 탈출한다. 외부의 사용 종료를 증명할 수 없어 다른 개체로 재초기화하면 이전 참조가 새 ID를 가리킨다. 현재 참조 수명 계약과 사용자 전투 규칙을 보존하는 이번 범위에서는 재사용할 수 없다. 기존 적 본체·체력바·표시 탄환·효과 풀은 유지한다.
- 현재 목록을 공개적으로 바꿀 수 있어 포탑 조회에는 O(T) 서명 확인, 이벤트 후/각 다중 조준에는 O(N) 적 상태 확인이 남는다. 반복 문자열/파싱·거리 계산을 줄이는 대신 비교·사전 조회·일부 후보 정렬·인덱스 구축 비용이 추가된다. 적/포탑 구성에 따라 성능이 악화될 수 있다.
- 키/포탑 표/지원 서명·결과, 경로 끝점, 인덱스별 적 상태 목록이 메모리를 사용하고 Clear 후 용량을 보관한다. 지원 결과256·출처 해석512·기존 작업 버퍼8/예비 구역 목록128 제한과 별도로, 참조 서명·사전의 피크 용량 자체는 축소하지 않는다. 사라진 포탑 참조는 다음 해당 캐시 갱신까지 남을 수 있다. 피크/잔류·GC·CPU 모두 미측정이다.
- 추가 렌더링/그림자/HUD 설정 변경은 하지 않았다. 그 분야의 다음 변경은 실제 계측 재개 후 결정한다. 이 기록은 가능한 모든 최적화가 끝났다는 뜻이 아니다.
