# CSV 데이터 검수 (2026-10-29)

**한 줄 요약**: ID 형식, 중복, 참조 무결성, 웨이브 첫 등장 라운드는 모두 정상이다. 문제는 세 가지다. 같은 값이 여러 시트에 따로 적혀 있고(진실 원천 중복), 칸마다 단위·표기가 섞여 있고, "참조 칸도 ID"라는 규칙을 어긴 칸이 남아 있다. 모든 수정안은 **제안**이며 실제로 고친 것은 없다.

기준 문서: `ai_quality_guide/01_기획/08_데이터테이블.md`, `05_밸런스_경제.md`, `00_공통/01_공통원칙.md`, 인수인계의 2026-10-26 확정 ID 규칙.

- 파일 형식은 9개 모두 UTF-8(BOM 없음)이고 줄끝은 CRLF로 통일돼 있다. 따옴표도 정상이다.
- 현재 CSV는 인수인계 '기획 상태(10-26)' 절의 "코드는 아직 포탑 3종·적 4종"보다 앞서 있다. 포탑 6종, 적 8종, 보스 3종, 증강 50장, 숫자 ID가 이미 들어가 있다. 인수인계의 해당 문구가 옛 기록이다.

## 정상 확인

- 모든 시트의 ID가 확정 범위 안에 있고 중복이 없다.
- 웨이브 ID 1,946개가 모두 `41 + 라운드3 + 순번3` 형식이다. 라운드 값과 일치하고 순번도 1부터 끊김이 없다.
- 참조 무결성: waves.enemy, 포탑의 약점·저항, targetPriority, upgrades.target, skills.owner, splitInto, summonInto, defenseRef가 가리키는 ID는 모두 실제로 존재한다.
- 신규 적의 첫 등장 라운드: 돌격병 4, 분열체 7, 장갑병 12, 치유사 16, 비행체 22. 확정 4/7/12/16/22R과 일치한다.
- 증강 등급 확률 60/30/10은 합이 100이다. 리롤 1, 3라운드 주기, 후반 5라운드 주기, 카드 3장도 확정값과 맞다.
- 기술병 스킬(×4, 반지름 2, 쿨 12초, Space, 전투 단계, 라운드 시작 시 초기화)은 확정값과 같다.
- 증강 text의 숫자와 value1~3이 어긋나는 행은 없다. 수치가 text에 드러나지 않는 행은 3개(22023, 22046, 22050)인데, 표현 방식이 다를 뿐 모순은 아니다.

## 검증 스크립트 제안

CSV를 바꿀 때마다 자동으로 돌리는 검사다. EditMode 테스트나 에디터 메뉴 하나로 만든다.

1. **ID 범위·형식**: 시트별 접두어(10/11/12/21/22/31/32/41/42), 자릿수, 중복
2. **웨이브 ID**: `41 + 라운드3 + 순번3`, 라운드 일치, 순번 연속
3. **참조 무결성**: ID를 가리키는 모든 칸(구분자 `|`, `*수` 문법 포함)이 실제로 존재하는지
4. **칸 타입**: 숫자 칸에 문자열이 없는지(effectTags.bossValue 등)
5. **빈칸 규칙**: "빈칸 = 상속" 칸에만 빈칸을 허용
6. **원천 중복 감시**: 같은 개념 쌍(pierceFalloff, 기술병 강화비)의 값이 같은지. 다르면 실패
7. **합계 검산**: 등급 확률 합 100, 증강 등급별 장수 18/20/12, 30R 처치 골드 합이 기준값 ±허용치
8. **첫 등장 라운드**: 신규 적 4/7/12/16/22R
9. **웨이브 시간**: start 오름차순, 라운드당 마지막 출현 시각 상한
10. **텍스트 기호**: augments.text에 금지 기호(→, —, 장식 ·)가 있는지. 문구 가이드와 연동
11. **증강 text와 value 일치**: text의 숫자가 value1~3에서 나오는지(현재 통과)
12. **디버그 값 격리**: diagnostic* 키가 출시 시트에 없는지

## 상위 5개 (먼저 볼 것)

1. **적 능력치 원천 이중화**(#1): waves의 구워진 능력치와 enemies의 기본값·배율 중 어느 쪽이 원천인지 정하고 명시한다.
2. **기술병 강화비 이중 정의**(#3): upgrades와 stage 중 실제로 쓰는 쪽만 남긴다.
3. **증강 value 단위 규칙**(#5): 증강 50장을 구현하기 전에 effect별 단위표를 만든다.
4. **참조 칸 문자열 제거**(#4, #6): towers.tag·requires, effectTags.bossValue `immune`.
5. **진단 값 분리**(#11): diagnostic*을 출시 시트에서 뺀다.

## 판단 보류 (사용자 확인 필요)

- 30R 처치 골드 11,241과 확정 11,923의 차이. waves에 행이 없는 개체(분열 작은 개체, 보스 소환체)를 포함한 기준인지 확인이 필요하다. 코드의 계산 방식을 봐야 확정할 수 있다.
- upgrades 21511(화상 강화)을 21501(공격력)과 같은 group으로 묶은 것이 의도인지.
- 약점·저항이 비어 있는 적(공격형, 보스들, 치유사·장갑병의 저항)이 의도된 빈칸인지.
- waves의 보스 행 interval 1과 다음 start +0.75의 불일치가 실제 게임에서 문제가 되는지. 코드가 start만 쓰면 문제없다.
