# 컨텍스트와 작업 흐름

## 탐색과 도구
- 처음에는 AGENTS·인수인계·해당 작업의 정본만 읽는다. 문서에 적힌 경로를 우선하고, 없거나 불일치할 때 `rg --files`/`rg -n`으로 범위를 좁힌다. 최신 Notion은 해당 시스템의 필요 부분만 조회하며 관측 상태와 충돌을 함께 적는다.
- 같은 파일/스킬을 같은 대화에서 이미 읽었고 변경 징후가 없으면 다시 전부 출력하지 않는다. Git HEAD·diff·파일 변경을 확인하고 바뀐 부분만 읽는다. 압축 후 정보가 불확실하면 필요한 부분을 재확인한다.
- Unity는 공식 `unity@unity-agent-plugin`을 기본 경로로 한다. 같은 이름의 로컬 Unity 스킬을 함께 읽지 않는다. 로컬 고유 스킬은 필요한 경우만 사용한다. 설치 원본/활성화 설정은 이 규칙으로 수정하지 않는다.
- MCP와 CLI 중 현재 정상인 경로 하나로 같은 작업을 수행한다. 실패 원인을 확인한 후에만 대체 경로를 쓴다. 같은 변경을 양쪽으로 중복 실행하지 않는다. 명령 스키마는 연결/버전 변경·불일치 때 해당 명령만 조회한다.
- 전체 도구 카탈로그·원시 Profiler JSON·전체 테스트 성공 목록·Base64를 대화에 출력하지 않는다. 원본은 Assets 밖 파일로 보존하고 요약/실패 항목/경로만 반환한다. 캡처의 실제 저장 경로와 Overlay 포함 여부를 확인한다. 큰 출력은 제한하고, 잘린 결과는 필요한 구간으로 재조회한다.

## 작업 규모와 협업
관련 스킬의 필수 절차와 검증은 유지한다. 단순 조회/문서 수정에 관련 없는 구현·빌드·전체 테스트를 덧붙이지 않는다. 구조 변경에는 필요한 설계/계획/검토를 유지한다. 세션 전체 비용 진단은 사용자가 요청했을 때 해당 스킬로 별도 수행한다.

서브에이전트는 독립 입력/산출물, 병렬화 이점, 전달·검토 비용을 먼저 비교한다. 작은 공유 파일 편집은 직접 처리한다. 사용할 때는 파일/구간/질문/산출물을 명시하고 필요한 맥락만 전달한다. 같은 Unity의 Play·테스트·씬 조작은 한 실행 주체가 순차 수행한다. 안전상 새 확인이 필요한 상황과 이미 승인된 반복 작업을 구분한다.

## 인수인계 형식
`UNITY_HANDOVER.md`에는 갱신일, 현재 목표/승인 범위, 최신 구현/검증, 미완료·차단, 다음 행동, 관련 기록 링크만 유지한다. 숫자 표/실패 이력/명령/오래된 상태는 날짜별 정본에 둔다. 빌드/아트/밸런스 승인·실측/추정·과거/현재를 구분한다. 이미 있는 재개 문서를 연쇄 복사하지 말고 현재 인수인계로 연결한다.

종료 시 변경 범위·실제 확인 결과·한계와 복원을 기록하고 [로컬 Git](LOCAL_GIT.md)을 따른다. 문서만 바꾼 경우 게임 테스트 대신 링크·규칙 보존·변경 범위를 검사한다.
