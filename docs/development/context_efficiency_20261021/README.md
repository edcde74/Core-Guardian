- [작업 흐름](../WORKFLOW.md): 재탐색/스킬 이중 읽기/전체 카탈로그/원시JSON·Base64 출력을 줄이고, 현재 정상인 Unity 경로 하나를 사용한다. 필수 스킬 절차와 필요한 증거는 생략하지 않는다.
- [대상 QA](../TARGETED_QA.md): 기존 테스트24클래스의 선택 경로·실행 상태/건수·0건·재시도·설정 보호를 명시한다. 테스트 실행기를 새로 만들지 않고 공식 CLI 검증 절차를 연결했다. 문서 변경에 Unity Play/전체 테스트를 덧붙이지 않는다.
- [인수인계](../UNITY_HANDOVER.md): 현재 승인/구현/미완료/다음 행동만 유지한다. 기존 재개 문서2개는 여기로 연결해 같은 상태를 세 곳에서 갱신하지 않는다. 과거 가격/실험 상세는 날짜별 정본과 백업에 유지했다.

## 조사한 구성과 중복
조사 대상 사용자 스킬42개(로컬 Unity31개 포함), 공식 Unity32개, Superpowers15개. 같은 이름의 Unity 스킬28쌍은 바이트가 모두 달랐다. 공식 플러그인을 기본 경로로 지정했으며 설치본 삭제/수정/비활성화는 하지 않았다. 로컬 고유 스킬도 보존한다. 공식 CLI SKILL.md는51,374바이트, 로컬은37,029바이트로 양쪽을 함께 읽으면88,403바이트다. 이 전체가 항상 자동 로딩된다는 의미는 아니다.

config.toml에서 활성 플러그인22개, MCP 설정은node_repl/unreal/unity를 확인했다. Unity는 CLI `mcp --project-path CD`, 바이너리1.0.0-beta.13. 공식 Unity/Superpowers 플러그인 manifest에는 별도 MCP 서버 선언이 없다. 이 세션 검색 가능 도구510개 중 Unity151개였으나 이것을 매 턴 전체 스키마가 입력된다는 뜻으로 쓰지 않는다. 검색 가능한 도구 수·설정된 서버·실제 연결/본문 로딩은 서로 다르다. Unreal이 설정에 있다는 이유만으로 현재 Unity 작업에서 연결하지 않는다.

Superpowers의 포괄적 호출 조건과 복수 설계/실행 절차는 작은 작업에서 중복 비용이 생길 수 있다. 필수 절차를 무시하거나 플러그인을 패치하지 않고 관련 작업에 필요한 흐름만 적용한다. 독립 입력/산출물이 없거나 맥락 전달·검토가 더 비싸면 직접 수행하며 같은 Unity 검사는 병렬화하지 않는다. 이번 문서 분리는 공유 상태 의존성이 커 직접 수행했다.

## 전후 비교 방법
[검증/수치 JSON](verification.json), [오프라인 검증기](verify.py). 문자 수는 UTF-8 BOM 제외·CRLF→LF 정규화로 계산하고 바이트 수는 실제 파일 바이트다. 같은 집계 규칙으로 전후를 비교한다. 스킬 목록/도구 스키마/기존 대화·추론·캐시·이미지·도메인 증거는 실제 사용에 따라 달라지므로 전체 토큰/과금 절감으로 환산하지 않는다. 설치된 tokenizer나 실제 요청별 토큰 계측이 없어 실제 토큰 수는 미측정이다.

현재 대화에 이미 들어간 과거 지침/이력은 파일을 줄여도 소급해서 사라지지 않는다. 이후 새 대화에서 짧은 인수인계와 관련 분야만 읽을 때 시작 부담을 줄인다. 안전·사실 확인·품질에 필요한 추가 읽기는 허용한다. 문서 경량화가 검사/검증 생략을 뜻하지 않는다.

정확한 길이·분야별 읽기량은 아래 자동 생성 [측정 표](RESULTS.md)를 따른다. 초기 공통 지침과 각 요청에서 추가할 이 문서들만 비교하며 양쪽에 동일하게 필요한 기존 Notion/아트 원본/전투 소스/필수 스킬은 양쪽 모두 제외한다. 전체 세션 입력량이나 실현된 토큰 절감률이 아니다.

상태/규칙 중복은30R수치·실험 한계·아트/HUD 상세·보존/실행 제약·현재 작업 이력의5그룹으로 분류했다. 상세/상태를 정본에 연결해 중복 갱신을 줄이고, Play/빌드/품질 등 핵심 안전 문구의 필요한 반복은 남겼다. 34개 항목을0개로 없앤 것이 아니다. 설치 스킬28쌍은 유지하며 선택 경로만 하나로 정했다.
