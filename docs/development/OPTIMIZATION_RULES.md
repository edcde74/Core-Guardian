# 최적화 공통 규칙

2026-10-20 사용자 지시. 앞으로 코어 가디언의 모든 최적화 작업에 적용한다. 코드·오브젝트 풀링·캐시·렌더링·에셋 임포트·Unity/URP/Player 설정 변경 모두 포함한다. 작업자는 최적화 시작 전에 이 문서를 읽는다.

## 원칙
1. **변경 전 얼마나 비용이 드는지 먼저 기록하고, 변경 후 같은 조건으로 다시 측정한다.** 원본과 비교 가능한 기준이 없으면 먼저 계측을 준비한다. 과거 사전계측은 조건이 일치할 때만 기준으로 재사용한다.
2. **게임 퀄리티를 최대한 해치지 않는다.** 같은 품질에서 불필요한 작업을 줄이는 방법을 우선한다. 현30R 성장·물량·밸런스, 원본/방향별 외형·애니메이션·그림자·강조·HUD·효과 표시 수/수명·사운드·입력 반응을 보존한다. 품질 저하가 필요한 절충은 근거와 비교 자료를 제시해 별도로 결정하고 임의 적용하지 않는다. 성능만 좋아져도 품질/동작 회귀가 있으면 통과가 아니다.
3. Unity 공식 유튜브·공식 문서와 개발사/Unity의 실제 게임 사례를 먼저 조사한다. 영상 제목·URL·발표자/게시자·버전·확인 범위·배운 점·적용 조건을 남긴다. 설명만 확인한 것을 전체 시청/본문 학습으로 기록하지 않는다. 타 게임의 개선율을 우리 게임의 기대/달성 수치로 사용하지 않는다.
4. 한 번에 원인을 구분할 수 있는 단위로 바꾼다. 여러 변경을 묶으면 묶음 효과라고 명시하고 개별 기법의 성과로 분배하지 않는다. 개선 없음/악화/측정 실패도 그대로 남긴다.

## 엔진 내부 프로파일링 적극 활용
2026-10-20 추가 사용자 지시. Unity 안의 최적화는 **엔진 프로파일링을 기본 절차로 적극 활용한다.** 단순 FPS 표시나 Stopwatch 측정만으로 병목/개선 판정을 끝내지 않는다.
- Unity Profiler의 CPU Usage Timeline/Hierarchy로 비용이 큰 호출·호출 수·대기·GC.Alloc을 구분하고, 작업에 관련된 Rendering·UI·Memory·Audio 등 모듈을 함께 확인한다. 프로젝트에서 실제 제공되는 모듈/카운터와 유효성을 먼저 확인한다.
- 변경 전후 같은 조건의 다중 프레임 캡처를 저장하고, Profile Analyzer를 사용할 수 있으면 분포·마커를 비교한다. 설치가 필요하면 현재 패키지/호환성과 작업 범위를 확인한다.
- 렌더링은 Frame Debugger로 그리기·패스·재질 전환을 조사하고, 메모리/풀링은 Memory Profiler 사용 가능 여부를 확인해 스냅샷·잔류/피크를 비교한다. GPU 시간은 유효한 GPU 계측이 있을 때만 보고한다.
- 기존 마커로 범위를 구분하기 어려우면 승인된 구현 범위에서 ProfilerMarker 등을 추가해 HUD·뷰 동기화·풀 생성/반환·Session 비용을 분리한다. 보조 타이머/ProfilerRecorder는 엔진 캡처와 연결해 해석한다.
- Deep Profile·할당 호출 스택·Frame Debugger·메모리 스냅샷은 원인 조사에 맞춰 사용한다. 진단 부하가 큰 상태의 수치를 일반 성능으로 비교하지 않고, 최종 전후 시간 비교는 같은 계측 설정으로 별도 수집한다.
- 도구 접근/지원이 없으면 이유와 대체 계측의 한계를 남기고 해당 원인을 확정하지 않는다. 프로파일링 활용 지시는 사용자 Play 중단·공유 검사 중복·자동 패키지 설치/빌드/실행 승인이 아니다. 이번 규칙 추가에서는 새 엔진 계측을 수행하지 않았다.

## 실험마다 고정·기록할 조건
- 실험ID/날짜, 변경 전후 커밋과 미커밋 diff, 코드/CSV/관련 설정 해시, 변경 파일/설정의 이전값→이후값, 가설과 병목 근거.
- PC의 CPU/GPU/RAM·OS, Unity/패키지/렌더 파이프라인 버전, Editor 또는 Player·빌드 구성, 해상도/화면비·카메라·VSync/프레임 제한·배속.
- 씬·적 수/종류/위치·실제 포탑 수/편성·공격/효과/사운드 상태, seed·입력·dt/정책 버전. 주입·정지·임시 토글 유무를 명시한다.
- 측정 도구/마커·Profiler/Deep Profile/스크립트 디버깅 상태·계측 오버헤드, 워밍업/측정 구간/프레임 수/반복 횟수. 반복 횟수와 관측 길이는 변경 전후 수집 전에 정하고 같게 유지한다. 기본 반복은 조건당3회 이상이며 불가능하면 이유와 한계를 적는다.
- 프레임 시간을 기본으로 중앙값·평균·p95/p99·최대·표본 수를 기록한다. 유효 표본이 부족하면 해당 백분위는 보고하지 않고 원본/분포를 제시한다. 서로 다른 실행의 최고값을 합쳐 p99로 부르지 않는다.
- **최저·최고·평균 FPS를 변경 전후 필수 기록한다(2026-10-20 사용자 추가 지시).** 프레임 시간도 함께 남긴다. 프레임별 FPS=1000/deltaMs, 최저 FPS=1000/최대 deltaMs, 최고 FPS=1000/최소 deltaMs. 평균 FPS는 관측 프레임 수×1000/관측 deltaMs 합계로 계산한다. 프레임별 FPS의 산술평균이나 중앙 프레임 시간의 역수를 평균 FPS로 바꿔 쓰지 않는다.
- FPS는 측정 구간·표본 수·프레임 누락·유효하지 않은0/음수/비유한 시간의 제외 건수를 명시한다. 최저/최고를 좋게 보이도록 유효 스파이크를 임의 제거하지 않는다. 누락이 있으면 관측된 표본 평균과 전체 연속 구간 FPS를 구분한다. 각 반복값을 보존하고 묶음 평균은 총 프레임 수/총 관측 시간으로 계산한다. 작은 단위 작업만 측정해 FPS를 구할 수 없으면 N/A와 사유를 적고 별도 전체 프레임 계측을 연결한다.

## 비용 지표와 절감량
각 작업에 직접 관련된 지표는 필수 측정하고 전체 프레임과 다른 분야의 회귀도 확인한다. 나머지는 측정값 또는 미측정 사유를 기록한다.
- 전체 프레임 ms, 해당 CPU 마커 ms/호출 수, Main/Render Thread 시간, GPU 시간(지원 도구가 있을 때). 대기 포함 Main Thread와 GPU 시간을 혼동하지 않는다.
- GC 할당 B/frame·갱신당 B·GC 발생 횟수/정지 시간, 메모리 사용/최대/잔류량. 무효 API의0은 미측정이다.
- Draw Calls/Batches·SetPass·Canvas/Layout 재빌드, 생성/삭제 횟수. 풀링은 활성/대기/피크/신규 확장·초기 준비 시간·재시작 후 잔류 메모리를 함께 기록한다. 메모리를 더 쓰는 절충도 숨기지 않는다.
- 비용 절감량 = 변경 전 − 변경 후. 절감률(%) = (변경 전 − 변경 후) / 변경 전 ×100. 원래값0/미측정은 절감률 N/A. 악화는 음수로 남긴다. 단위·통계·조건이 같은 값끼리만 계산한다.
- 단계별 직전 버전 비교와 최초 기준 대비 누적 비교를 구분한다. 단계별 절감률을 합산하지 않는다. 변동폭과 겹치는 작은 차이는 개선 확정으로 쓰지 않는다.
- FPS는 높을수록 좋으므로 증가량=변경 후−변경 전, 증가율=(변경 후−변경 전)/변경 전×100으로 비용 절감률과 구분한다. 시간/할당 비용과 FPS의 증감 부호를 혼동하지 않는다.

## 품질·동작 동등성
- 같은 카메라/해상도/배율/유사 위상에서 전후 화면·동작을 비교한다. 픽셀·마스크·앞뒤 정렬·보행·접지·체력바·선택/피격/강화/발광 중첩을 관련 범위에서 확인한다. 품질 규칙의 정본은 각 담당 문서다.
- 풀 재사용은 타깃·알파/색·수명·프레임·트레일/입자·HP·이벤트 구독·사운드 중복을 초기화하고 신규/퇴장/재시작/씬 종료를 검사한다. 표시 제한이나 조기 소멸로 비용을 줄이지 않는다.
- 로직 변경은 같은 데이터/입력/정책/대응 시드에서 전투 결과와 이벤트 순서를 비교한다. 입력/물리/오디오 설정도 응답·판정·청취 차이를 확인한다.
- 기능QA·화면 비교·실제 청취·사람 체감·주입 스트레스·정상 전투·빌드 성능을 구분해 검증한 것만 적는다. Editor 측정을 실행파일 성능으로 표시하지 않는다.

|---|---|---|---|---|---|---|
|측정 전 예시 행|미측정|미측정|N/A|N/A|미측정|실제값으로 교체|

판정은 미측정/비교 불가/개선 확인/변동 범위 내/악화/품질 회귀로 구분한다. 전체 성능 통과는 합의한 목표기기·해상도·배속·최대 부하의 예산을 충족했을 때만 쓴다. 목표가 미정이면 부분 개선이라고 기록한다.

사용자 Play/다른 검사는 중단·중복하지 않는다. Unity 변경 전 현재 연결/씬/Play/컴파일/저장을 확인하고 자체 임시 상태를 복원한다. 빌드/실행파일 실행·push는 별도 명시 요청이 있을 때만 한다. 로컬 Git은 [LOCAL_GIT](LOCAL_GIT.md)을 따른다.
