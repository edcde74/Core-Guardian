# 최적화 작업 주의점과 실패 방지

2026-10-24. 지금까지 Core Guardian 최적화·검증에서 확인한 주의점이다. **최적화 시작 전에 [공통 규칙](OPTIMIZATION_RULES.md)과 함께 읽는다.** 공통 측정·품질 규칙은 그 문서가 정본이며, 이 문서는 실제 실패를 예방하는 실행 요령을 담당한다. 현재 승인·보류 상태는 [인수인계](UNITY_HANDOVER.md)와 해당 실험 정본에서 확인한다.

## 1. 구현 전에 절감할 비용부터 확인한다

- 최신 동일 조건의 직접 CPU ms로 후보 우선순위를 정한다. 호출 수·소스 중복·Draw 감소만으로 큰 성능 개선을 예상하지 않는다.
- 후보가 영향을 줄 수 있는 구간의 전체 비용을 확인한다. 그 구간 전체를 없애도 목표 절감에 못 미치면 구현 확대 전에 보고한다. 구간 전체 비용을 실제 절감 가능량으로 제시하지 않는다.
- 이미 적용된 최적화의 과거 성과를 새 후보의 기대 효과에 포함하지 않는다. 현재 활성 경로와 보류·OFF·fallback 경로를 구분한다.
- 직접 비용이 줄어도 전체 프레임·FPS·GC·메모리·품질을 함께 본다. 실행별 변동폭과 겹치는 차이는 개선 확정으로 쓰지 않는다.
- 채택·중단 기준을 수집 전에 정한다. 특정 실험의 0.5ms/1ms 기준이나 warm15/sample90을 모든 작업의 고정 기준으로 확대하지 않는다.

근거: [뷰 동기화 실험](view_sync_20261023/README.md), [마스크 준비 실험](mask_cpu_preparation_20261024/README.md).

## 2. 검사 도구가 먼저 같은 원본을 재현해야 한다

- 새 비교 도구나 경로를 고칠 때는 대표 정상/실패 사례를 고정하고 **원본 대 원본**부터 비교한다. 원본끼리 다르면 후보의 회귀·효과를 판정하지 않는다.
- 검사 도구가 실제 제품과 같은 코드 경로를 타는지 소스로 확인한다. EditMode·PlayMode의 분기, 출력 batch 등록, 지연 생산·Flush, fallback 차이를 구분한다. EditMode 통과로 실제 QueuePage 경로까지 검증했다고 쓰지 않는다.
- 원본·후보가 같은 자료를 공유해 우연히 같아지는 검사도 피한다. 서로 독립된 입력/출력과 그 소유권을 확인한다.
- 성공 응답·컴파일 성공·테스트 요청 접수와 실제 실행 완료를 구분한다. 완료 상태·오류·유효 사례/표본 수를 확인한다. 0건은 통과가 아니다.
- 관측 코드의 getter·상태 조회·할당도 결과에 영향을 줄 수 있다. 비교 도구 변경은 기록하고, 관측 조건이 바뀐 실행을 그대로 동일 실험으로 취급하지 않는다.

근거: [출력 불일치 원인 분리](mask_cpu_preparation_20261024/diagnosis/README.md).

## 3. 렌더 비교 대상은 실제 Renderer 집합으로 제한한다

- “윤곽만 비교”라면 mask 준비 뒤 본체의 **모든 Renderer**를 끄고, 실제 활성 Renderer 집합이 의도한 윤곽 출력 집합과 정확히 같은지 검사한다. SpriteRenderer만 꺼서는 MeshRenderer인 발광·음영이 남는다. 임시 fixture에만 적용하고 제품 효과를 끄는 최적화로 바꾸지 않는다.
- 전체 합성 화면 비교에서는 반대로 발광·음영·그림자·본체를 포함한 상태와 위상을 명시한다. 격리 검사와 전체 화면 검사를 서로 대신하지 않는다.
- mask, quad 정점/UV, 출력 영역, 재질/PropertyBlock, 텍스처, 행렬, 정렬, 최종 픽셀을 단계별로 남긴다. **마스크가 같아도 최종 출력이 같다는 뜻은 아니다.**
- 실패 사례의 raw RGBA·PNG·픽셀 차이 수/좌표/채널 차이·차이 이미지를 보존한다. 해시만 저장하면 이전 차이의 위치와 크기를 복구할 수 없다.
- alpha0 픽셀의 RGB를 일괄 무시하지 않는다. additive 출력 등이 들어갈 수 있으며, PNG를 화면에 표시한 모습과 raw 값의 의미를 구분한다.
- 동일 sorting layer/order·깊이의 겹침, 재질과 객체 생성 순서를 기록한다. 순서가 원인이라는 주장은 실제 대조로 입증하기 전까지 가설로 표시한다.
- 비교에서 제외한 값과 이유를 명시한다. 객체 identity와 셰이더 시간은 서로 다른 종류의 정보이며, 시간 값을 사용하는 셰이더에서 시간을 임의 제외하면 안 된다.
- 두 사례 통과는 그 두 사례의 결과다. 전체 역할·방향·위상·줌·겹침·HUD·정상30R까지 통과한 것으로 확대하지 않는다.

근거: [수정한 격리 검사](mask_cpu_preparation_20261024/isolation_check/README.md). 기존 검사에 포탑 발광·음영이 남았고, 이를 제외하자 같은 원본의 관측 픽셀도 달라졌다. 지난74건 각각의 정확한 렌더 순서 원인까지 입증한 것은 아니다.

## 4. 좌표·렌더 입력 재사용은 콜백과 수명을 보존한다

- SetActive·Attach·자식 생성·EnsureResources·Present가 외부 콜백을 유발할 수 있다. 그 앞에서 읽은 좌표/색/변환이 콜백 뒤에도 유효하다고 가정하지 않는다. 안전한 읽기 경계를 증명하지 못하면 기존 live 계산을 유지한다.
- 이전 tile을 현재 Grid에서 변환하는 의미와 이전 world 좌표 저장은 다르다. Grid 이동/회전/스케일 변경·dt=0·풀 재사용·같은 ID의 새 세대를 관련 회귀에 포함한다.
- 수집 버퍼는 명시한 호출 범위 안에서만 재사용한다. 캐시 record·지연 Draw가 다음 Capture로 바뀔 목록을 빌려 보관하지 않도록 필요한 값을 소유하게 한다.
- sprite·texture update·alpha·flip·transform·bounds·정렬·활성/부품 변경을 구분한다. 값 복사로 동적 텍스처나 atlas revision의 기존 갱신 계약까지 고정하지 않는다.
- 공개 API·기존 overload·fallback의 의미를 유지한다. CPU 절감을 위해 공개 live 검증을 삭제하거나 다른 소비자까지 일괄 캐시하지 않는다.
- 단순 값 테스트와 실제 지연 생산 경로 테스트를 구분한다. 테스트 개수보다 callback 경계·Release/재대여·queued 입력 소유를 실제로 지나갔는지가 중요하다.
- 구조체 목록·owner별 버퍼·풀은 메모리를 더 쓸 수 있다. 용량·피크·잔류·할당을 측정하지 않았다면 메모리 무회귀라고 쓰지 않는다.

근거: [뷰 동기화의 콜백 회귀](view_sync_20261023/REVIEW.md), [마스크 입력 소유 검증과 한계](mask_cpu_preparation_20261024/README.md).

## 5. 측정 조건과 통계의 뜻을 유지한다

- 실제 Game View 해상도·카메라·부하·dt·워밍업·표본 수·반복 수를 guard로 확인한다. UI의 선택 표시만으로 실제1920×1080이라고 단정하지 않는다. 조건 실패 실행은 유효 비교에서 제외하고 실패 기록은 남긴다.
- 화면 임시 고정이 승인됐으면 기존 선택을 보관·복원하고, 실제 적용도 확인한다. 조건을 맞추려고 승인 없이 씬·카메라·화면 설정을 바꾸지 않는다.
- ProfilerRecorder는 해당 마커/카운터의 지원·단위·Valid·Count·스레드 범위·관측 프레임 대응을 확인한다. 미지원0은 비용0이 아니다. 프레임 누락을 숨기지 않는다.
- 중첩 마커를 합산하지 않는다. PlayerLoop·EditorLoop·대기 포함 Main Thread·wall frame·GPU 시간을 같은 비용으로 취급하지 않는다.
- 호출 수 진단·Deep Profile·할당 스택 등 무거운 진단과 일반 성능 비교를 분리한다. 성능 실행 전에 진단용 변경이 남아 있지 않은지 확인한다.
- 첫 sample 직전의 GC 기준을 갱신해 warmup 수거를 표본 수거로 세지 않는다. 유효 GC/스파이크 프레임을 개선을 위해 제거하지 않는다. Editor/관측 도구 할당을 후보의 인과 효과로 단정하지 않는다.
- 평균 FPS는 **표본 수×1000/유효 프레임 ms 합**이다. 프레임별 FPS의 산술평균과 구분한다. 보조 스크립트가 만든 요약도 공통 규칙과 대조하고, 과거 표를 재사용할 때 계산 정의를 확인한다.
- 단회·반복 합산·백분위의 표본 집합을 밝힌다. 부족한 표본의 p99나 서로 다른 실행의 최고값을 조합한 수치를 만들지 않는다.
- GPU 계측 미지원·Editor 측정·주입 부하·대상 기기 미검증을 명시한다. 호출/Draw 감소를 GPU ms나 목표기기60FPS 달성으로 바꾸지 않는다.

정확한 지표·계산·기록 양식은 [공통 규칙](OPTIMIZATION_RULES.md)을 따른다.

## 6. 실패하면 먼저 종류를 구분한다

|관측|판정과 다음 행동|
|---|---|
|연결 거절·검사 요청 실패·0표본|실행/도구 문제. 제품 회귀라고 쓰지 않는다. 실제 시작·정리 여부부터 구분한다.|
|같은 원본끼리 불일치|비교 재현성 미확보. 후보 판정 중단, 작은 고정 사례로 원인을 분리한다.|
|조건 오류·프레임 누락|비교 불가. 다음 반복을 자동 시작하지 않는다.|
|출력만 불일치|픽셀과 중간 상태에서 처음 달라지는 경계를 찾는다. 마스크 일치만으로 품질 통과 처리하지 않는다.|
|직접 ms 차이가 변동폭과 겹침|개선 미확정. 호출 수 감소만으로 채택하지 않는다.|
|품질 통과·성능 미측정|동등성 검증 결과만 보고한다. 최적화 성공으로 쓰지 않는다.|

- 한 번에 가설 하나를 검증하고 결과를 확인한 뒤 다음으로 간다. 미확정 원인을 확정처럼 설명하거나 통과 사례만 골라 보고하지 않는다.
- 재로딩 완료 직후 Pipeline 연결이 끊길 수 있다. 후속 실행 전에 재로딩 상태와 연결을 확인한다. 연결 실패를 같은 요청의 반복 전송으로 해결하지 않는다.
- 실패/timeout/예상 밖 부하 이후의 중단·추가 승인 경계는 [AGENTS.md](../../AGENTS.md)를 따른다. 임의120초·무제한 대기·조건 실패 후 다음 반복·다른 검사로 우회하지 않는다. 승인받은 재실행만 수행한다.
- 이미 유효한 원본 측정은 조건이 유지되면 재사용한다. 실패한 특정 실행만 승인된 범위에서 보충하며 불필요한 전체 재검사를 하지 않는다.

## 7. 시작 원본과 사용자 상태를 보존한다

- 실제 HEAD/diff와 **working-tree 시작 원본**을 보관한다. 사용자 미커밋이 있으면 HEAD 복원이 그 원본 복원이 아니다.
- Play·다른 검사·씬 dirty·컴파일·Profiler 상태를 먼저 확인하고, 자체 임시 조작과 정상 종료·복원 방법을 정한다. 한 Unity의 조작은 한 주체가 순차 수행한다.
- 종료 요청과 실제 종료를 구분한다. 복구 후 컴파일 완료·Play/씬/Profiler·관련 파일 hash/diff를 실제로 확인한 범위만 보고한다.
- 미채택 후보와 신규 helper/테스트/meta는 Assets 밖에 격리해 자동 컴파일·활성화를 막는다. 기존 사용자 파일·설정·미추적·폰트 도구 접근오류는 임의 정리하지 않는다.
- 보류 후보·아틀라스·native batch를 자동 활성화하지 않는다. 현재 승인 상태는 인수인계가 담당한다. 빌드·실행파일·커밋·push·Notion 갱신을 최적화 승인의 부수 작업으로 실행하지 않는다.
