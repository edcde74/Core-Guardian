# 설치 버튼·테스트 배속·HUD 표시 순서

2026-10-13. 수정 전 복구 기준: `28320e1`. 기존 BGM 제작 및 HUD 분석 변경은 보존하고 이번 커밋에 포함하지 않는다.

## 구현

- 개별 단일/범위/지원 포탑 선택 버튼은 수정이 설치 비용 이상이고 준비 단계일 때만 활성화한다. 지원은 기존 공격 포탑 선행 조건도 유지한다. 비활성 버튼은 비용과 ‘수정 부족’ 또는 ‘공격 포탑 필요’를 표시한다. 비용은 기존 CSV에서 읽고 수치를 바꾸지 않는다.
- 구매·강화·철거·라운드 보상 이후 HUD 갱신으로 사용 가능 여부가 바뀐다. 메뉴 진입/분류 버튼은 열어 비용을 확인할 수 있다. 직접 ChooseTower 호출에도 비용과 지원 조건을 검사해 미리보기·설치 모드 진입을 차단하고 부족 메시지를 표시한다.
- 오른쪽 위 재시작 아래 ‘테스트 배속 ×1’ 버튼 추가. 클릭마다 1→2→3→1배. Time.timeScale을 사용하므로 이동·전투·준비·증강 제한시간과 전투 효과에도 배속이 적용된다. 재시작/배속을 사용한 런타임 파괴 시 1배 복귀. 정식 적용 여부는 미확정이며 노션 정식 기능으로 추가하지 않았다.
- 단일 Overlay Canvas의 첫 자식 WorldFeedback 아래에 피해·골드·코어 피해 숫자를 생성한다. 이후 형제인 HUD 패널·버튼·증강 모달이 전투 피드백 위에 그려진다. 전투 피드백은 raycastTarget=false로 클릭을 차단하지 않는다. Canvas 개수/씬/원본 프리팹은 변경하지 않았다.
- 노션 [HUD 화면 및 표시](https://www.notion.so/3df389dbfc68811f9a87e5a5ff05a571)의 개별 포탑 버튼과 HUD 표시 순서 규칙을 수정하고 재조회로 확인했다. 설치 비용·판정은 기존 담당 포탑 문서를 참조한다.

## 검증

- 실제 씬 API 검사: 시작 수정100에서 비용100 버튼 활성화 → 실제 설치 후0에서 비활성화/부족 문구 → 직접 선택 차단. 철거50+1R보상20=70에서는 비활성 유지, 3R 완료 후110에서 재활성화. 라운드 진행 검사에는 강제 처치를 사용했다. [결과](hud_controls_checks_20261013.json).
- 배속 2→3→1에서 속성/Time.timeScale 일치 확인. 2배에서 재시작 후1배·1R·수정100 복귀 확인.
- 실제 생성한 GoldFeedback/CoreDamageNumber가 WorldFeedback의 자식이고 WorldFeedback이 첫 형제임을 확인. 자식 Graphic 클릭 차단 없음. HitDamage도 같은 FloatingNumber 생성 경로를 사용한다.
- EditMode73/73, PlayMode6/6 통과. [EditMode](hud_controls_editmode_20261013.json), [PlayMode](hud_controls_playmode_20261013.json). 이후 문구 줄바꿈/폰트 크기만 조정하고 재컴파일 및 실제 화면으로 확인했다.
- 1920×1080 화면에서 부족 문구 세 줄/비활성 색/테스트 배속 버튼을 확인했다. [화면](hud_controls_20261013.png). 다른 해상도와 사람 입력으로 전체 라운드를 다시 플레이하지 않았다.
- BuildCombatPrototype.Verify 통과: 기존 A길·3종 적/포탑 원본 참조·플레이어 시작(15,10) 보존. 종료 시 ready/Play stopped/compiling=false/domainReload=false, 전투 씬 dirty=false, timeScale1. 현재 콘솔 groundTruth 오류0/컴파일 실패false.
- 빌드·실행파일 실행 없음. 밸런스 및 테스트 배속의 정식 기능 채택 승인은 별개다.
