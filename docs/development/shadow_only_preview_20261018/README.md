# 원본 렌더 + 별도 그림자 시안 — 2026-10-18

사용자가 생성형 시안의 잘못된 플레이어 비율을 지적한 뒤, 원본을 두고 별도 그림자만 합성한 시안을 요청했다. 기존 생성형 전체/개체 시안은 원본 보존 검증이나 적용 기준이 아니다.

## 이번 시안

- 이미지 생성기로 본체를 다시 그리지 않았다. 실제 전투 씬이 참조하는 병사3종/플레이어/포탑3종과 `2D Sprite`의 core를 임시 복제해 같은 맵·카메라 배율로 렌더했다. 플레이어는 실제 `PlayerFacing/D5` 몸통·팔·양다리를 쓰는 런타임 정지 자세다. 병사·포탑도 기존 실제 애니메이션 생성 경로의 정지 Present를 사용했다.
- 본체 SpriteRenderer 합집합을 기존 마스크 코드로 추출하고, 별도 메시를 바닥 방향(x+=높이*.50, y-=높이*.28)에 투영했다. 투명 그림자는 가까운 쪽.38→먼 쪽.22이며 기존 중앙 접촉 그림자를 유지하고 바깥/고정 발 복제/이전 짧은 투사 그림자만 임시 비교 대상에서 숨겼다. 본체 색/형태/도트/자세는 전후 동일한 렌더러를 유지한다.
- 코어 원본에 포함된 청색 바닥 표현·기존 포탑 하단 명암 등 현재 본체 표현은 바꾸지 않았다. 바닥의 반투명 표현 아래로 새 그림자가 비치는 부분은 합성 결과의 차이다.
- 그림자만 켜기 전후를 같은 카메라/자세에서 촬영했다. [원본 렌더](current_actual.png), [별도 그림자 합성](shadow_only_actual.png), [8종 비교2배](all_originals_shadow_only_2x.png), [실제 플레이어4배](player_shadow_only_4x.png).
- 화면 확대는 실제1920×1080 카메라 캡처를 Nearest2배/4배 한 것이다. 카메라 줌이나 원본 픽셀 배율을 새로 바꾼 것이 아니다. 전체8종은 비교용 임시 나열이며 실제 정상 배치/전투 화면·HUD 포함 촬영이 아니다. 보스/보행/방향별 투사 추종은 이번 시안 범위 밖이다.

## 확인·복원 범위

- 최초 성공 촬영은 Play=false/compilingfalse/씬1dirtyfalse에서 실행했고, finally에서 임시 루트·마스크·메시·재질·메모리 셰이더·렌더타깃을 제거했다. 성공 반환은 씬1/dirtyfalse/Playfalse다. [촬영 수치](capture.json), [재현 코드](CaptureShadowOnly.eval.cs), [그림자 셰이더 문자열](ShadowPreview.shader.txt), [비교판 생성](compare.py).
- 후속 보강 기록 재촬영에서 core 이름을 공유하는 그림자 리소스가 먼저 선택되어 중단됐다. 조회 조건을 `2D Sprite`로 보강했다. 이후 재실행은 공유 에디터가 Play로 바뀌어 시작 가드에서 중단했다. 기존 성공 촬영본을 사용했고 사용자/다른 검사 Play는 멈추지 않았다. 현재 스크립트의 mask 좌표 보강은 성공 촬영본 JSON에는 없음을 구분한다.
- 이미지 단순 차이 검사에서7종의 발 위16px를 제외한 상단 사각 영역은0픽셀 차이다. 코어 해당 영역은 기존 반투명 청색 바닥도 포함해268픽셀 차이이며 본체 불투명 픽셀 전수 비교로 표현하지 않는다. [구체 범위](image_checks.json). 플레이어 체형은 원본 실제 렌더로 직접 확인했다.
- 게임 Assets/원본/씬/프리팹 저장·Play 진입/정지·전투 수치·시간·기존 카메라 설정·Notion 변경 없음. 새 자동검사/빌드/사람 플레이/최종 아트 승인 없음. **시안만 제작했으며 게임 적용은 하지 않았다.** 움직임/높이별 길이/다수 중첩/성능과 실제 전투 시각 검토는 구현 시 별도다.
