# 적 버프 원천 목록 재사용

2026-10-21 Asia/Seoul. 복구 기준 `05b9974`. 사용자가 이동 전 살아 있는 버프형 적만 한 번 추리고 기존 최대 버프/거리/적용 순서를 유지하는 구체안에 수정 승인했다. Play·자동 테스트·성능 측정 보류는 유지한다.

제품 변경은 `Assets/Game/Scripts/CoreGuardian/Session.cs` 하나다. 기존 호출별 `StepWork`에 `BuffSources` 목록을 추가했다. 스폰 후·이동 전에 Enemies의 원래 순서대로 살아 있는 Buff만 담고, 각 생존 적의 원천 검사에 이 목록을 사용한다. self 제외·`Vector2.Distance <= BuffRadius`·최대값 선택(음수/NaN 처리 포함)·버프 선계산 후 이동·전투 수치/CSV/이벤트 순서는 바꾸지 않았다. 기존 finally 정리에서 목록 참조를 Clear하므로 중첩 Tick의 작업 버퍼도 분리된다.

전체 적 N, 생존 적 E, 살아 있는 버프형 B일 때 원천 후보 열거는 기존 E×N에서 N+E×B 형태로 바뀐다. 이는 코드 구조 설명이며 실측 시간/절감률이 아니다. B가 N에 가까우면 같은 차수에 사전 순회 비용이 더해질 수 있다. 추가 목록은 호출별 최대 사용 용량을 보관하므로 메모리 절충도 있다.

## 실제 확인

- 소스 diff: 6줄 추가/3줄 제거, scoped `git diff --check` 통과.
- 독립 읽기 전용 리뷰: 버프 계산 중 콜백/이동이 없어 원천 구성·순서가 동일하며, 호출별 버퍼·finally 정리에 수정 필요 사항 보고 없음. 실행 동등성 검증은 아니다.
- 공식 Unity MCP 재컴파일 completed/failed=false/errors=[]/compilationFailed=false. Console 오류0, 현재 경고116. 이번 cursor 이후 기존 UAC0005 36건·CS0618 79건이 재출력됐고 변경한 Session 소스 경고는0이다. 경고0 또는 새 테스트 통과로 표기하지 않는다. [실제 조회·해시](verification.json).
