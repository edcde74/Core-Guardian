## 비교와 강도

[CompareHorde.cs](CompareHorde.cs)는 기존 비교기를 재사용해 같은 CombatData.Load/Session 로직, 고정제자리(13,14)·단일강화/단일증설/다중증설3정책·시드20261020 한 개·Tick0.05초로 기존/0.8/0.6/0.5초를 비교했다. 라운드3~9일정과10R공격형 간격만 후보로 바꾸고 플레이어 전투 중 공격력 구매/준비 중 포탑 구매를 사용했다. 라이브 Session·씬을 변조하지 않았고 정상 수지/합법 구매를 사용했으며 강제 처치·재화 주입은 없다. 렌더·실제 이동·사람 입력·준비 체류는 모형 밖이다.

**강한 압박의 실험값**으로0.8초를 선택했다. 0.5초보다 첫 관문이 덜 급격하면서 사용자가 원한 몰림을 만든다. 그래도 제자리 정책은3~4R에 모두 패배하므로 사람 플레이에서 막힐 위험은 남는다. 적체로90초대 전투도 생겼고40분 목표 달성은 확인하지 않았다. 다음은 실제 이동·배치·첫 강화 선택으로 대응 가능한지 보는 것이다. 다른 후보는 적 수 증가(재화/후반 파급), HP추가 증가(전투 장기화)이며 이번에는 수량/HP를 유지하고 등장 시간만 바꿨다. 강한 빌드를 결함으로 보지 않는다.

## 전투 전용 배속

기존 개발도구 TestSpeed가1/2/3배를 준비·전투·증강 전체에 적용하던 것을 변경했다. 선택값은 기억하고 실제 **Combat에서만 선택 배속**, Preparation/Augmentation/Victory/Defeat에서는1배속이다. 준비·증강 중2/3배를 선택해도 해당 단계는1배속이며 다음 수동/자동 전투 시작에 복원한다. 버튼 표시를 ‘전투 배속’으로 바꿨고 위치·크기·HUD구조는 유지한다.

CoreGuardianPrototype의 시작/진단 전환·전투 Update 전후에 단계별 속도를 동기화한다. 버튼을1배로 되돌릴 때도 즉시1배로 복원한다. 기본선택1에서는 외부 계측/검사가 직접 설정한 TimeScale0/5 등을 강제로 덮어쓰지 않는다. 이는 기존 계측·임시 정지 보존을 위한 구분이며 사용자 배속 버튼 경로는 위 단계 제한을 따른다. 새 정식 배속 UI나 옵션 저장 기능은 추가하지 않았다.
