# HUD 본문·용어·상단 접기 후속 수정

2026-10-17 사용자 첨부3화면 피드백 적용. 복구 기준 `dcaef9d`. 기존 HUD 관련 파일은 깨끗했고 병행 OriginalMotion/TowerGlow/UnitAnimation 변경은 보존했다. 별도 빈 checkpoint는 만들지 않았다. 기본 상호작용/피해 표시의 담당은 [기존 적용 기록](../hud_usability_applied_20261017/README.md)이며 아래가 최신 변경이다.

## 변경

- 현재 능력치: 왼쪽220×56 탭2개와 오른쪽612px본문으로 재배치. 본문은 위쪽 정렬·플레이어22px/포탑20px로 표시한다. 강화 화면은 두 탭을426px씩 같은 폭으로 늘려 구매행과 맞췄다. 포탑 철거 버튼도 남는 가로 폭에 맞췄다. 새 아트/색감 변경 없음.
- 사용자가 지적한 ‘기술병 · 스펙’ 접힌 바는 제거했다. 플레이어는 기존 하단 ‘플레이어 능력치’로 다시 연다. 포탑의 접힌 개체 표식/재개방은 유지한다. 첫 빈 바닥 접기/다음 선택 해제·설치 성공 후 자동 펼침 생략은 유지한다.
- 화면 문구: 플레이어 스펙→플레이어 능력치, 현재 스펙→현재 능력치, 강화 구매→능력치 강화, 투사체 속도→탄환 속도, 보정 반영→버프 적용 공격력, 실제 지출 환급→사용한 수정 반환. 전투 종료의 검증 완료도 라운드 완료로 정리했다. 개발 메뉴의 진단 용어와 기존 데이터/계산은 구분한다. 내부 오브젝트/메서드 이름은 기존 검사 연결을 위해 유지했다.
- 상단 손잡이는 단순72→52px높이 변경을 담당하지 않는다. 전투 안내판(StagePlate)의 라운드·전투·살아 있는 적 표시를 실제로 숨긴다. 펼침=안내판 아래, 접힘=자원 상태줄 바로 아래로 손잡이를 이동한다. 수동 선택은 Refresh/다음 전투에 유지된다. 코어·라운드·골드·수정의 상단 행과 준비·증강 제한 시간은 유지한다. 준비/증강 중에는 이 전투 전용 손잡이를 표시하지 않는다.

## 검증

- [실패](red.json)→[통과](green.json): 실제 HUD에서 오른쪽 본문·능력치 문구·플레이어 중복바 없음·전투 안내판 숨김/복원·상태행 유지·손잡이 이동·Refresh 접힘 유지 확인.
- [실제 InputSystem 입력](pointer.json): UI 누름→숨김→바닥 해제 투과 방지·설치1회·바닥2단계·같은 포탑 재개방·실제 손잡이 적중을 확인했다. 추가로 이동한 상단 손잡이의 접기/재개방을 실제 마우스 입력으로 검사했다. 임시 마우스/TimeScale0/IgnoreFocus는 finally에서 모두 복원했다. [검증기](VerifyPointer.cs).
- 첫 입력 검사는 Unity가 비활성 창이고 backgroundBehavior=ResetAndDisableNonBackgroundDevices인 조건에서 UI 클릭부터 실패했다. 설정 변경만으로도 성공하지 않아 이를 제품 결함이나 통과로 기록하지 않았다. Unity 창을 활성화한 뒤 같은 집중 입력 검사가 통과했다. 제품의 입력 설정은 변경하지 않았다.
- 집중 설치 HUD PlayMode **4/4 completed**: [원본](playmode.json). 컴파일 오류 없음. 이전115 EditMode 결과는 과거 적용 당시 결과이며 이번 재실행으로 쓰지 않는다. 전체 PlayMode/사람 직접 플레이/밸런스 실측을 새로 실행하지 않았다.
- 최종 확인은 별도 아래 종료 메모를 따른다. 기존 씬·카메라·후처리·원본·피해HUD·병행코드 보존. 빌드/실행파일/push없음.
