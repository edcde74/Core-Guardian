# 1~9라운드 진행 연결 — 2026-10-10

현재 전투 씬: `Assets/Scenes/CoreGuardian_CombatPrototype_20261008.unity`

확정된 편성을 실제 라운드 진행에 연결했습니다. 모든 등록 적의 생성이 끝나고 전장에 적이 없으면 완료 수정을 한 번 지급합니다. 1~8라운드 완료 후에는 다음 라운드의 50초 준비로 전환합니다. 라운드 시작 버튼 또는 준비 시간 만료로 전투를 시작합니다. 코어가 파괴되면 패배하고 보상·다음 준비를 진행하지 않습니다.

완료 보상은 최신 재화 기획서 가안에 맞춰 1~4라운드 20수정, 5~9라운드 25수정입니다. `stage.csv`의 `waveReward`가 기본값이고 `waveReward5`~`waveReward9`가 라운드별 값을 지정합니다. 골드는 기존처럼 실제 처치 때 즉시 지급합니다.

다음 라운드에서 기존 포탑·포탑 강화·기술병 강화·재화·코어 에너지·기술병 위치를 유지합니다. 설치·포탑 강화는 준비에서만 허용하고 플레이어 강화는 준비·전투에서 가능합니다. 적·투사체를 정리하고 다음 전투 시작 시 생성 일정·공격 대상·공격 대기 시간·라운드 누적 피해를 초기화합니다. 완료한 라운드 피해는 다음 준비 중에도 확인할 수 있습니다.

HUD는 라운드 / 9와 현재 준비·전투·완료 상태, 완료 보상을 표시합니다. 기존 Canvas에서 표시만 수정했습니다. 9라운드 완료는 현재 구현의 검증 종료이며 전체 목표 1~11라운드 완성이나 최종 게임 승리가 아닙니다. `처음부터 다시 시작`은 1라운드·시작 재화·코어·포탑 상태를 초기화합니다. 별도 역할 검증은 정식 진행과 분리하고 완료 보상을 지급하지 않습니다.

변경 파일: CombatData.cs(라운드별 보상 로딩), Session.cs(라운드 전환·공격 상태 초기화), CoreGuardianPrototype.cs(전환 알림), CoreGuardianHud.cs(진행 표시), stage.csv(보상 값). 씬 YAML과 원본 아트는 수정하지 않았습니다.

- EditMode 28개 모두 통과: 전체 9개 편성의 순차 진행과 보상, 상태 유지·다음 준비 조작·시간 만료, 미래 생성 대기 중 조기 종료 방지, 코어 패배, 역할 검증 분리.
- PlayMode 6개 모두 통과: 실제 씬의 자동 공격으로 1라운드 처치→다음 준비, 기존 발 앵커·타일 점유·이동, 1~9 진행 시 포탑/HUD 유지 및 완료 후 전체 재시작.
