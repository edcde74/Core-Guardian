# B 사운드 실제 연결·종류별 음량 분리

2026-10-19. 실제 적용 커밋 `4c774c3`, 복구 기준 HEAD `77523ad`. 사용자 후속 지시 “프로젝트에 다 연결”과 “연결 전에 종류별로 분리해서 나중에 설정에서 음량 조절”을 적용했다. 이전 청취 선택만 완료·미연결 상태를 대체한다. 기존 PackageManagerSettings 변경, 미추적 자료, font_tools_vendor 접근 오류 삭제 표시는 보존했다. 관련 변경이 없어 빈 복구 커밋은 만들지 않았다.

## 연결과 정본

선택23·잠정2·멀티정책1의 정본은 [선택 manifest](../audio_selection_final_20261019/selection_manifest.json) 그대로다. 멀티만 승인된 재구성1·2·3발 파일을 사용해 런타임 WAV는28개다. [원본→런타임 매핑·SHA256](runtime_mapping.json)의28개 모두 원본과 바이트 해시가 같다. 원본/BGM 제작자료·기존14개 리소스는 삭제하지 않고 보존했다. 지원 포탑 전투는 계속 무음이다.

현재 데이터 담당은 `Assets/Resources/CoreGuardian/Audio/SelectedB/catalog.json`이다. 사운드 ID마다 category/resourcePath/gain/priority/important/protectCore를 둔다. `CoreGuardianAudioCatalog`가 실제 로드·분류를 담당하며, 기존 경로 상수는 호환 검사에만 남겼다. 골드·플래티넘5차①, 실버2차③, 전투BGM B72①, 증강BGM2차③ 등 선택을 변경하지 않았다. 철거3차②·시작2차③은 연결했으나 음색 선택의 잠정 상태는 유지한다.

## 음량 분류와 향후 설정 연결

| 분류 | 저장 키 | 포함 |
|---|---|---|
| 전체 | `CoreGuardian.SoundVolume` | 모든 분류에 곱하는 기존 사용자 음량 |
| 배경음악 | `CoreGuardian.Audio.Music` | 전투/증강 선택 BGM |
| 포탑 효과 | `CoreGuardian.Audio.Tower` | 단일/멀티 발사·설치 완료·철거 |
| 플레이어 효과 | `CoreGuardian.Audio.Player` | 플레이어 공격 |
| 몬스터·코어 효과 | `CoreGuardian.Audio.MonsterCore` | 피격·처치·코어 피해 |
| UI | `CoreGuardian.Audio.UI` | 클릭·열기/닫기·설치 실패/취소·강화 성공/실패·증강 공개 |
| 진행 알림 | `CoreGuardian.Audio.Progress` | 보스 등장/가속·라운드 시작/완료·최종 승리·패배 |

`CoreGuardianSoundSettings.Volume`은 기존 키/검증을 유지한다. `GetCategoryVolume(category)` / `SetCategoryVolume(category,value)` / `EffectiveVolume(category)`가 설정 화면용 API다. **실제 음량 = 전체 × 분류 × 데이터 gain × 음악 전환/덕킹 배율**이다. 전체/분류0은 음소거이고 다른 분류 값을 바꾸지 않는다. 분류 범위0~1, 비정상 값은1로 처리한다. 새 분류 기본값은1이며 읽기만으로 키를 만들거나 기존 값을 초기화하지 않는다. 설정 변경은 즉시 재생 중인 소리에도 반영한다. 테스트 임시 값은 전부 복구했다.

별도 설정 화면/슬라이더는 이번에 만들지 않았다. 기존 개발 도구의 음량 슬라이더는 전체 음량으로 이름을 정정했고 승인 공격음 듣기를 유지했다. 나중에 설정 UI의 각 슬라이더를 위 API에 연결하면 된다. 효과음 기본 gain .55는 유지, 새 BGM gain .35는 초기 믹스 값이며 정상 다수전투 청취로 최종 승인된 값은 아니다. AudioMixer 에셋을 새로 도입하지 않고 공통 코드에서 종류별 배율을 적용한다.

## 실제 이벤트

- 기존 발사/피격/처치/코어/보스/설치/강화/라운드/승리14개 이벤트를 새 정본에 연결했다.
- 멀티는 `Session.AttackLaunched(source,count)`로 한 공격의 실제 생성 수를 전달한다. 타깃마다 전체3연타를 재생하지 않으며 지원은 이벤트를 만들지 않는다. 모델의 공격 속도/탄환/피해는 유지하고 각1·2·3발 WAV 안의 기존85ms 리듬을 그대로 쓴다.
- 실패한 설치 요청, 성공한 철거, Esc 설치 취소, 유효 UI 버튼/패널 변화, 실제 카드 Flip 시작에서 각각 해당 소리를 재생한다. 카드의 옛 합성음을 제거하고 승인3등급을 쓴다. Busy 중 중복 클릭에는 공개음을 추가하지 않는다. 반복 월드 클릭으로 이미 열린 조회창은 재개방음을 내지 않는다.
- 마지막 라운드 전체 승리와 일반 라운드 완료를 분리한다. 패배는 실제 비진단 코어 파괴에서1회, 진단 종료에는 승리/패배 결과음을 추가하지 않는다. 보상/증강 규칙·타이머는 바꾸지 않았다.
- 효과음4음성 풀을 유지한다. 데이터 우선순위는 결과100/코어90/진행60/그 외 중요40/일반10이다. 코어 피해가 같은 프레임의 패배음을 끊던 리뷰 지적을 실제 어댑터 흐름으로 재현해 수정했다. UI/하위 중요도가 결과음을 밀어내지 않는다.
- 음악은 `CoreGuardianMusicAudio`의 별도2음성으로 준비/전투BGM→증강BGM→준비/전투BGM을 .35초 교차 전환한다. 돌아올 때 전투 음악 재생 위치를 이어가며, 최종 승리/패배 때 .35초 페이드 후 멈춘다. 중요음 동안 음악 배율을 .4까지 낮췄다가 복귀한다. 전환과 시간 계산은 unscaledDeltaTime이며 전투 수치/타이머를 변경하지 않는다.
