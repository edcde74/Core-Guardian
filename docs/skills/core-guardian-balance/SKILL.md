# 코어가디언 게임 밸런스 분석

## 판단의 중심

핵심 재미는 플레이어·타워의 지속 성장과 증강 조합으로 비정상적으로 강력한 빌드를 완성하는 것이다. 성장 차이를 체감하면서 편하게 즐기고 상황에 맞는 의미 있는 선택을 하게 한다. 강한 빌드 자체는 결함이 아니다. 획득 난도·투자·성립 시점·보상감을 평가하고, 약한 선택의 회복 가능성·반복 지루함·선택이 결과를 바꾸는지부터 살핀다. 모든 빌드 평준화나 일괄 난이도 상승·하향을 기본 해법으로 삼지 않는다.

## 권한과 근거

- 코어가디언 프로젝트 전용이다. 현재 사용자 지시와 적용되는 `AGENTS.md`를 따르고 작업 시작/종료·로컬 Git·인수인계 규칙은 재정의하지 않는다. `UNITY_HANDOVER.md`와 필요한 담당 기록을 먼저 읽고 종료 시 실제 확인 범위/남은 검증/분석 링크만 갱신한다. 게임 구현과 분석 기록 정리를 구분한다.
- 기존 Notion 연결의 검색/fetch, 현재 Unity CLI/MCP의 상태·씬·참조 조회, 기존 계측 JSON·테스트 실행기를 우선 재사용한다. 기능/계측기가 이미 있으면 새 구현을 만들지 않는다. 테스트 재실행은 사용자 요청 범위와 상태 변경 권한을 확인한 뒤에만 한다. HUD 배치·조작성 분석은 `core-guardian-hud-ux` 담당이며 이 스킬에 중복 구현하지 않는다.
- 기본은 읽기 전용. 게임 데이터·코드·씬·노션 기획서를 수정하지 않는다. 분석용 스크립트와 산출물은 Assets 밖에 저장하고 원본을 덮어쓰지 않는다. 분석 권한이 밸런스 적용 권한으로 확장되지는 않는다.
- 프로젝트 루트에서 `docs/development/UNITY_HANDOVER.md`를 먼저 읽고 사용자 지시와 최신 담당 노션을 우선한다. [sources.md](references/sources.md)의 링크·위치는 탐색 출발점이며 현재 상태나 고정 수치가 아니다. 노션 연결이 없으면 읽은 자료와 미확인 범위를 명시하고 가능한 분석을 계속한다.
- 노션은 의도·규칙의 기준, 현재 로딩되는 Unity 데이터와 실행 코드는 구현 동작의 근거다. 충돌은 양쪽 값과 출처를 나란히 보고한다. 기획 가안·승인된 규칙·실행 반영·최종 밸런스 승인 상태를 구분한다.
- 기본값 파일만 읽지 말고 열린 씬의 참조→데이터 로더→실행 계산 경로를 추적한다. 에디터 연결·씬·Play·컴파일·저장 상태는 읽기 도구로 확인한다. 연결 실패 시 디스크 정적 분석과 실행 확인의 차이를 남긴다. 씬 YAML은 수정하지 않는다.
- Play 실행이나 재시작으로 사용자 세션을 바꾸지 않는다. 새 실측이 필요하면 조건과 계측안을 제시한다. 실제 실행이 요청되면 기존 상태·기록을 보존하고 정상 구매·이동·공격 경로를 사용한다. 강제 처치/재화 주입 검사는 난이도 실측에 쓰지 않는다.
- 읽기 전용 서브에이전트는 독립된 자료 조사·검증에 활용할 수 있다. 각 에이전트의 출처와 누락을 취합한다. 부족한 값을 추측으로 채워 확정하지 말고 최신 노션을 먼저 확인한다. 이미 승인된 내용을 반복 질문하지 않는다.

## 분석 흐름

1. 요청 라운드·문제·현재 구현 범위를 정하고, 각 담당 노션과 실제 적용 데이터의 근거 목록을 만든다. 미구현 라운드/증강은 기획 시나리오로 분리하고 현재 실측 그래프에 섞지 않는다.
2. 웨이브 구성·순서·간격, 적 체력·방어·속도·버프·코어 피해, 플레이어/타워 화력·사거리·타깃·투사체, 재화 획득/지출, 증강 확률/조합/중첩을 함께 연결한다. 골드와 수정은 서로 다른 수지로 추적한다.
3. [analysis-method.md](references/analysis-method.md)에 따라 라운드별 위협, 성장 전후 DPS·처치 발수·클리어 시간, 강화 가능 시점과 기회비용을 계산한다. 값마다 **기획 / 구현 / 정적 계산 / 시뮬레이션 / 실제 Play 계측 / 사람 플레이**를 표시한다. 시뮬레이션에는 가정·배치·구매 정책·시간 단위·검증 범위를 쓴다.
4. 약한/강한 구간과 선택이 무의미해지는 구간을 비교한다. 초반 문제는 첫 의미 있는 선택·첫 강화·첫 증강까지의 대기와 실제 조작/무행동 시간을 먼저 본다. 사거리 노출, 둔화, 발수 경계, 재화 손실의 악순환 등 원인을 분리한다.
5. 해결안은 적용하지 않고 제안한다. 현재 승인 규칙을 바꾸는 안에는 변경되는 담당 문서와 규칙을 표시한다. 증강 획득 앞당기기 같은 안을 현행 규칙으로 오인하지 않게 한다.

현재 CSV 형식이 유지되는 경우 `scripts/analyze_rounds.py --project <root> --through 10 --out <Assets 밖의 새 폴더>`를 실행할 수 있다. **먼저 현재 CombatData/Session 계산과 스키마가 일치하는지 확인한다.** 이 도구는 정적 수급·발수·화력 계산이며 전투 시뮬레이터가 아니다. 누락 라운드는 null로 출력한다. 증강·보스·다른 스키마는 최신 자료에 맞춰 별도 계산한다.

## 보고 순서

다음 여섯 항목을 사용자 지정 순서로 보고한다.

1. 현재 밸런스 상태 요약: 핵심 재미 관점의 판단, 구현 범위, 확실성.
2. 수치와 근거에 기반한 문제점: 라운드 표/그래프, 기획-구현 차이, 확인 자료·미확인 자료.
3. 원인 가설: 사실과 추론을 분리하고 반증 조건 제시.
4. 해결 방안 **3가지**: 각각 기대 효과·장점·단점·변경 범위.
5. 가장 추천하는 해결책과 이유: 강한 빌드의 보상감 및 의미 있는 선택과 연결.
6. 실제 플레이테스트 검증 항목: 비교 조건, 기록 지표, 관찰할 성공/실패 기준.

표·그래프는 출처와 근거 유형, 단위, 가정을 표시하고 모르는 값은 빈칸/미확인으로 둔다. 각 결론은 **확인 데이터(기획/구현/계측) / 추정(정적 계산/시뮬레이션/원인 가설) / 주관적 평가(재미/지루함/선택 체감)**로 구분한다. 주관적 평가는 평가자·관찰 조건과 미검증 여부를 적는다. 숫자만으로 재미·지루함을 확정하지 않는다. 스킬/분석 완료는 게임 밸런스나 아트 승인과 구분한다.
