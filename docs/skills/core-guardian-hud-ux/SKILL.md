# 코어가디언 HUD/UX 분석

## 목표와 범위

증강·강화로 비정상적으로 강력한 빌드를 완성하는 재미를 HUD가 잘 전달하는지 분석한다. **명중 피해 / 강화 전후 스펙 증가량 / 클리어 시간**을 성장 체감의 세 축으로 사용한다. 플레이어는 얼마나 강해졌는지 이해하면서 전투·이동·설치 시야를 유지해야 한다.

기본은 읽기 전용이다. 승인 없이 UI·코드·프리팹·씬·노션을 변경하지 않는다. 분석 문서와 와이어프레임은 Assets 밖의 새 폴더에 작성한다. 기존 기능·조작·허용 단계·능력치·아트 승인을 유지하고 새 게임 시스템, 능력치, 전투력 공식을 임의로 확정하지 않는다. 디자인 제안과 구현 완료를 구분한다.

## 실제 구조부터 확인

1. 프로젝트의 `docs/development/UNITY_HANDOVER.md`를 먼저 읽고, [sources.md](references/sources.md)에서 최신 담당 노션과 실제 HUD 소스를 찾는다. 노션은 의도/규칙의 기준이며 실행 코드와 열린 씬은 구현의 근거다. 과거 인수인계를 현재 상태로 가정하지 않는다.
2. Unity 연결·프로젝트·열린 씬·Play·컴파일·저장 상태를 읽기 도구로 확인한다. Canvas/UIDocument, 계층, 앵커·피벗, 크기, 스케일러, 폰트/숫자, 이벤트/레이캐스트, prefab 참조와 런타임 생성 경로를 확인한다. Edit Mode에 Canvas가 없으면 Start/Configure 생성 코드를 추적하고 **저장 씬에서 없음**과 **런타임 미구현**을 구분한다.
3. 준비·설치·전투·플레이어 강화·타워 선택/강화/파괴·증강 선택·라운드 결과·접힌 상태의 흐름을 조사한다. 접기는 표시 상태인지 취소인지, 다시 열 때 분류 초기화, Esc 의미, 전투/WASD 지속, 스크롤/선택 유지·클릭 차단을 담당 문서와 대조한다. 없는 기능은 미구현으로 표시한다.
4. 가능한 실제 Game View 화면을 본다. 캡처 날짜·해상도·준비/전투/역할검증·주입 여부·패널 상태를 기록한다. ScreenSpaceOverlay 캡처는 이를 포함하는 화면 경로를 사용한다. 카메라 렌더만으로 HUD 전체를 확인했다고 말하지 않는다. 현재 Play를 켜거나 재시작·정지·화면 해상도를 바꾸지 않는다. 과거 캡처만 있으면 날짜와 현재 코드의 차이/미확인을 밝힌다. 새 실행을 사용자가 요청한 경우에만 상태를 보존하며 검증한다.

필요한 읽기 전용 서브에이전트에 코드/기획/화면 조사를 나눌 수 있다. 부족한 자료는 최신 노션부터 확인하고 이미 확정된 내용을 반복 질문하지 않는다. 동시 작업의 미커밋 변경은 보존하고 관측 시점을 기록한다.

## 판단 기준

- **정보 우선순위:** 코어 위험·라운드/단계·재화·가능한 행동을 먼저, 구매 시 전후 스펙·비용, 사건 직후 성장 변화, 상세 분석은 펼친 패널로 나눈다. 준비/전투/증강/완료에 따라 역할을 평가한다. 고정된 우선순위만 기계적으로 적용하지 않는다.
- **가독성과 시야:** 현재 화면/보드/경로와 UI 겹침, 글자 실효 픽셀 크기, 숫자 자리 증가, 목록/라벨 순서 변동, 배경 대비·아이콘/이름·색 외 구분, 클릭 영역과 가림을 확인한다. 코드 사각형 면적을 실제 불투명 차폐 면적이나 사용성 실측으로 바꾸어 쓰지 않는다.
- **해상도:** CanvasScaler만으로 안정성을 확정하지 않는다. 같은 종횡비의 축소와 다른 종횡비의 앵커/절대좌표 불일치를 나누고, 적절한 창 크기·16:9·16:10·울트라와이드에서 패널과 접기 탭 모두 살핀다. 계산상 잘림은 실측과 별도 표기한다. 새로 약속할 지원 해상도는 제안으로 남긴다.
- **성장 체감:** 현재값→다음값, 증가량과 단위, 강화 대상 이름/타워ID, 재화 종류를 연결한다. 성공한 구매/선택 직후 변화량을 보여주되 장시간·큰 팝업으로 전투를 가리지 않는 안을 비교한다. 숫자 애니메이션은 목표값을 즉시 읽을 수 있고 연속 구매/골드 획득에 덮이지 않는지 평가한다. 클릭 실패에도 증가 표시가 나오는 안은 배제한다.
- **지표의 정직성:** [growth-metrics.md](references/growth-metrics.md)에 따라 피해 입력값, 반올림 명중피해, 실효 감소 체력, 누적 피해, 이론 DPS, 실전 계측 DPS, 클리어 시간을 구분한다. 통합 전투력은 필요성·계산근거·역할 누락·오해를 먼저 평가하고 새 공식을 승인된 능력치처럼 도입하지 않는다.
- **기존 HUD 유지:** 정보 추가에 앞서 기존 여백·상세 패널·접기·라운드 전환을 활용할 방법을 찾는다. 기존 상단 필수정보·하단 진입 버튼을 유지하는 최소안도 반드시 비교한다. 자동 접기/탭 통합은 선택/설치 상태 및 독립 패널 조작을 바꾸는지 밝힌다.

## 보고와 제안

다음 **7항목 순서**로 보고한다.

1. 현재 HUD 구조 요약: 실제 계층, 상태별 표시, 확인 자료/날짜와 미확인 범위.
2. 확인된 UX 문제점과 근거: 노션-구현 차이, 코드/화면 관찰, 가설·해상도 계산·실측 구분.
3. 정보 우선순위 분석: 준비·전투·증강·완료별 상시/사건 피드백/상세 패널 매핑.
4. 개선 배치안 **3가지**: 플레이어/타워 성장 위치, 상시와 접이식, 명중/증가량/시간 피드백.
5. 각 안의 장단점: 시야·인지·조작·기존 규칙 유지·구현 범위/필요 데이터.
6. 가장 추천하는 안과 이유: 통합 전투력 필요성에 답하고 핵심 재미·현재 근거와 연결.
7. 직접 플레이테스트 항목: 조건·지표·성공/실패/반증 기준, 아직 확인 못 한 상호작용.

가능하면 실제 Game View를 기준으로 간단한 와이어프레임/배치도를 제공한다. 원본 화면과 **미적용 제안**을 분명히 구분하고 해상도·패널 상태를 적는다. 새로운 측정 표시나 시간 계측은 UI 분석 제안이며 기존 구현에 이미 있는 것으로 쓰지 않는다. 구현은 별도 요청/승인 전까지 수행하지 않는다.
