# AI 협업 프로세스

파트와 상관없이 AI에게 일을 맡길 때의 흐름이다.

## 4단계 `[영상]`

1. **규칙을 파일로 정리한다.** 레퍼런스, 숫자 스펙, 금지 목록, 용어집을 파일로 만든다. 대화로만 말한 규칙은 다음 세션에 사라진다.
2. **작은 테스트를 먼저 한다.** 전체 50개를 만들기 전에 1~3개로 규칙이 먹히는지 본다. 규칙이 틀렸으면 여기서 고친다.
3. **본 작업을 진행한다.** 같은 규칙 파일을 매번 넘긴다.
4. **평가를 쉽게 만든다.** 사람은 판정만 하면 되게 만든다.
   - 후보 A/B를 나란히 놓은 비교 이미지나 비교 영상
   - 전후 수치 표
   - 체크리스트 통과 여부

## 요청서 기본 틀

```
[목표] 무엇을, 어디에 쓰려고 만드는가
[맥락] 장르 / 장면 / 플레이어가 느낄 감정 / 화면에서 차지하는 크기
[레퍼런스] 파일 경로 또는 이미지 (중간 레퍼런스 포함)
[숫자 스펙] 크기, 색 수, 선 두께, 길이, 프레임 수 등
[금지] 이번 작업에서 쓰지 말 것 (공통 금지 + 파트 금지)
[검증] 완료 전에 스스로 확인할 항목과, 사람에게 보낼 결과물(스크린샷/비교 이미지)
[산출물] 파일 형식, 경로, 이름 규칙
```

## 결정 기록

사람이 고른 것과 버린 것, 그 이유를 짧게 남긴다. 다음 판단의 기준이 되고 AI에게 넘길 규칙이 된다. `[영상]`

```
- 날짜 / 파트 / 결정 / 고른 안 / 버린 안 / 이유
```

제안과 확정은 구분한다. 사람이 고른 것만 확정으로 쓴다.

## 자동화 우선순위 `[영상]`

콘텐츠보다 잡일 자동화가 효과가 크다.
- 스토어 설명 작성, 스크린샷 비율 맞추기
- 업데이트 후 에디터를 조작해 확인하고 스크린샷 찍는 QA
- 자동화 테스트(테스트 프레임워크 + 훅)로 구현 속도 올리기

## 잘 안 될 때

| 증상 | 먼저 볼 것 |
|---|---|
| 결과가 매번 다름 | 레퍼런스가 고정돼 있는가, 숫자 스펙이 있는가 |
| 특정 대상만 화풍이 깨짐 | 중간 레퍼런스가 필요한가 |
| 수정할수록 이상해짐 | 수정 턴이 너무 많음. 처음부터 다시 생성하거나 업스케일러로 정리 |
| 기능은 되는데 보기 안 좋음 | 화면 검증(스크린샷)을 안 했음 |
| 무난하지만 기억에 안 남음 | 게임 맥락과 개성 요소가 요청에 빠졌음 |
