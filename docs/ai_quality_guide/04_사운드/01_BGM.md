# 사운드 / BGM

> 범위: 배경음악(타이틀, 필드, 전투, 보스, 결과 화면)의 기획·생성·편집·적용. 효과음은 다루지 않는다.
> 함께 볼 파일: [02_SFX](02_SFX.md), [03_보이스](03_보이스.md), [06_QA/03_재미지표_플레이테스트](../06_QA/03_재미지표_플레이테스트.md)

## 1. 이 파트에서 AI 티가 나는 이유
"슬픈 피아노 BGM"처럼 장르와 감정만 넣으면 AI는 가장 흔한 편곡을 낸다. 어디서 들어본 것 같은 무난한 곡이 나오고, 게임의 장면이나 리듬과 따로 논다. AI는 소리를 직접 듣고 게임과 맞는지 판단하지 못하기 때문에, 맥락과 지표를 사람이 넣어줘야 한다. `[영상]`

## 2. AI 티 패턴
| 패턴 | 왜 티가 나나 | 대신 이렇게 | 출처 |
|---|---|---|---|
| 장르+감정만 넣은 요청("슬픈 피아노 BGM") | 가장 흔한 답이 나옴 | 장면, 템포, 악기 편성, 연주법(아르페지오, 스타카토 등)까지 적는다 | `[영상]` |
| 프롬프트를 AI에게 대신 쓰게 하고 게임 맥락은 빠짐 | 일반론적인 프롬프트가 됨 | 게임 기획서 요약을 같이 넘기고 프롬프트를 만들게 한다 | `[영상]` |
| 곡마다 악기와 믹스 톤이 다름 | 사운드 정체성이 없음 | 프로젝트 공통 악기 편성과 리버브 공간을 정해 모든 곡에 쓴다 | `[실무]` |
| 인트로가 길고 루프 지점이 어색함 | 게임용이 아니라 감상용 구조 | 루프 구간을 정하고, 인트로는 짧게 분리한다 | `[실무]` |
| 처음부터 끝까지 같은 밀도 | 전개가 없어 금방 질림 | 2~4개 구간으로 밀도 변화를 준다 | `[실무]` |
| 과한 서사적 합창, 에픽 드럼 | AI 트레일러 음악의 기본값 | 게임 규모와 분위기에 맞는 편성으로 줄인다 | `[실무]` |
| 반복할수록 거슬리는 리드 멜로디 | 플레이 중 집중을 방해 | 플레이 중 곡은 멜로디보다 리듬과 패드 비중을 높인다 | `[실무]` |

## 3. 작업 전에 정할 것 (프로젝트 설정값)
- 음악 장르와 기본 악기 편성 (예: 피아노 + 현악 4성부 + 가벼운 퍼커션)
- 장면별 BPM 범위 (예: 필드 80~95, 전투 120~140)
- 조성 규칙 (장면별 장조/단조, 전환 시 조 관계)
- 루프 길이 (마디 수, 초)
- 기준 음량 (예: 통합 -16 LUFS 근처, 피크 -1 dBTP). 플랫폼 기준에 맞춘다
- 금지 음색 목록
- 파일 형식 (샘플레이트, 압축 방식)

값은 [프로젝트 설정](../00_공통/03_프로젝트설정_템플릿.md)에 적는다.

## 4. 작업 규칙
1. 곡 목록을 장면 단위로 만든다. 장면마다 "플레이어가 하는 일, 느껴야 할 감정, 화면 템포"를 한 줄씩 적는다.
2. 레퍼런스 곡을 정하되, 그대로 모방하지 않고 "템포·편성·분위기" 같은 속성만 뽑아 적는다.
3. 요청에는 게임 맥락을 반드시 넣는다. 장르, 장면, 반복 재생 여부, 위에 깔릴 효과음 밀도까지. `[영상]`
4. 연주 특징을 구체적으로 적는다. 리듬 위주인지 아르페지오 위주인지, 어떤 악기가 앞에 나오는지. `[영상]`
5. 후보를 2~4개 뽑아 **실제 게임 화면에서** 효과음과 함께 들어본다. 단독 청취로 고르지 않는다. `[실무]`
6. 피드백은 "더 세련되게"가 아니라 구체적으로 준다. "베이스가 효과음 대역을 가린다", "후반 8마디가 너무 밝다"처럼. `[영상]`
7. 루프 지점을 편집하고 이음새에 클릭음이나 박자 어긋남이 없는지 확인한다.
8. 음량을 기준값에 맞춘다. 곡끼리 체감 음량 차이가 없어야 한다.
9. AI가 들을 수 없는 부분은 지표로 보여준다. 스펙트로그램, 음량 그래프, BPM 측정값. `[영상]`

### 장면 전환 `[실무]`
- 같은 스테이지 안에서 긴장도가 바뀌면 곡을 갈아끼우기보다 층(stem)을 더하고 빼는 방식을 먼저 검토한다.
- 층 구성 예: 기본 패드 / 리듬 / 멜로디 / 긴장 층. 각 층은 같은 BPM, 같은 길이로 만든다.
- 곡을 바꿔야 하면 마디 경계에서 바꾸고 크로스페이드 길이를 정한다 (예: 1마디).
- 보스 등장, 승리, 패배 같은 짧은 곡(스팅어)은 다음 곡과 조성이 이어지게 만든다.

### 자주 하는 실수
- 생성 결과가 좋아서 확정했는데 게임 안에서는 효과음에 묻힌다. 반드시 게임 안에서 고른다.
- 곡마다 다른 도구·프롬프트로 만들어 사운드트랙이 이어지지 않는다. 편성표를 고정한다.
- 압축 설정 후 루프 이음새에 틈이 생긴다. 최종 형식으로 변환한 파일로 다시 확인한다.

## 5. 금지
| 금지 | 이유 | 예외 |
|---|---|---|
| 맥락 없는 한 줄 요청 | 무개성 결과 | 없음 |
| "더 멋있게/세련되게" 피드백 | 개성을 깎는 방향으로 수렴 `[영상]` | 없음 |
| 효과음 없이 단독 청취로 확정 | 실제 플레이에서 겹침을 놓침 | 메뉴 전용 곡 |
| 특정 기존 곡이나 아티스트를 그대로 흉내내라는 요청 | 저작권과 표절 위험 | 없음 |
| 곡마다 다른 음량 | 플레이 중 볼륨 조절 강요 | 연출상 의도한 경우 |

## 6. 요청서 예시
```
[목표] 2D 디펜스 게임 3스테이지 전투 BGM, 반복 재생
[맥락] 플레이어는 몰려오는 적을 막으며 포탑을 배치한다. 긴장되지만 조급하지 않아야 한다. 효과음(타격, 폭발)이 많이 깔린다.
[편성] 피치카토 현악 + 마림바 + 낮은 신스 패드 + 가벼운 킥/셰이커. 리드 멜로디는 8마디에 한 번만 짧게.
[숫자 스펙] 128 BPM, D 단조, 32마디 루프, 인트로 4마디 분리, 중저역(200~500Hz)은 비워둘 것
[금지] 합창, 에픽 드럼, 일렉 기타 리드
[검증] 루프 이음새 확인, 통합 음량 측정값 함께 제출
```

## 7. 검증 체크리스트
- [ ] 루프 이음새에 클릭음, 박자 어긋남, 음량 점프가 없다
- [ ] 통합 음량과 피크가 기준값 안에 있다
- [ ] BPM과 조성이 요청과 같다
- [ ] 실제 게임 화면에서 효과음과 함께 들었을 때 효과음이 묻히지 않는다
- [ ] 같은 프로젝트의 다른 곡과 악기 편성·공간감이 이어진다
- [ ] 10분 이상 반복 재생해도 거슬리지 않는다 (사람 판단)
- [ ] 생성 도구의 상업 이용 조건을 확인했다
