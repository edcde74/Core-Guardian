# 사운드 / SFX

> 범위: 타격, 발사, UI 클릭, 획득, 상태 변화 등 효과음의 생성·편집·적용. 음악과 대사는 다루지 않는다.
> 함께 볼 파일: [01_BGM](01_BGM.md), [02_아트/09_VFX](../02_아트/09_VFX.md), [03_개발/01_클라이언트_게임플레이](../03_개발/01_클라이언트_게임플레이.md)

## 1. 이 파트에서 AI 티가 나는 이유
효과음을 하나씩 따로 생성하면 음색, 공간감, 음량이 제각각이 된다. AI는 손맛을 느끼지 못하기 때문에 "타격감 좋게"라고 해도 화면의 동작 타이밍과 맞추지 못한다. 결국 사람이 실제 플레이에서 듣고 맞춰야 하고, AI에게는 시간과 음량을 숫자로 줘야 한다. `[영상]`

## 2. AI 티 패턴
| 패턴 | 왜 티가 나나 | 대신 이렇게 | 출처 |
|---|---|---|---|
| 효과음마다 리버브와 음색이 다름 | 같은 세계의 소리로 안 들림 | 공통 공간(리버브 길이)과 재질 규칙을 정한다 | `[실무]` |
| 앞부분에 무음이나 느린 어택 | 입력과 소리가 어긋나 둔하게 느껴짐 | 어택 시작을 0~10ms 안으로 자른다 | `[실무]` |
| 같은 소리 반복 | 기계적으로 들림 | 변형 3~5개 + 피치·음량 무작위화 | `[실무]` |
| 과하게 화려한 UI 효과음 | 앱·광고 톤, 반복 시 피로 | UI 소리는 짧고 작게, 게임 재질과 맞춘다 | `[실무]` |
| 모든 소리가 같은 음량 | 중요한 정보가 안 들림 | 우선순위별 음량 계층을 정한다 | `[실무]` |
| 여러 소리가 같은 대역에 몰림 | 동시에 나면 뭉개짐 | 소리 종류별로 주 대역을 나눈다 | `[실무]` |
| "타격감 있게" 같은 형용사 요청 | 기준이 없어 검증 불가 | 길이, 어택, 감쇠, 주 대역을 숫자로 | `[영상]` |

## 3. 작업 전에 정할 것 (프로젝트 설정값)
- 효과음 목록과 우선순위 (예: 1순위 피격·코어 피해, 2순위 공격, 3순위 UI)
- 우선순위별 음량 범위 (dBFS 또는 상대값)
- 공통 공간감 (리버브 길이, 건조함 정도)
- 재질 규칙 (나무, 금속, 마법 등 세계관 재질 목록)
- 길이 상한 (예: UI 0.15초 이하, 타격 0.3초 이하)
- 동시 재생 제한 수, 변형 개수
- 파일 형식

값은 [프로젝트 설정](../00_공통/03_프로젝트설정_템플릿.md)에 적는다.

## 4. 작업 규칙
1. 효과음 목록을 이벤트 단위로 만들고, 각 이벤트에 "플레이어가 알아야 할 정보"를 적는다. 소리는 장식이 아니라 정보다.
2. 재질과 공간 규칙을 먼저 정하고 모든 요청에 같이 넣는다.
3. 숫자 스펙을 준다. 길이, 어택, 감쇠 시간, 주 대역. `[영상]`
4. 후보를 여러 개 만들어 **실제 동작과 동시에** 재생해 고른다. 애니메이션의 타격 프레임과 소리 시작을 맞춘다.
5. 앞 무음을 자르고, 끝은 페이드아웃해 클릭음을 없앤다.
6. 자주 나는 소리는 변형을 만들고 피치(±3~5%)와 음량을 무작위화한다.
7. BGM과 같이 틀어놓고 우선순위대로 들리는지 확인한다.
8. AI에게 결과를 설명할 때는 파형, 스펙트로그램, 입력과 소리의 ms 오차를 보여준다. `[영상]`

### 소리 묶음 설계 `[실무]`
- 하나의 행동을 여러 층으로 나눈다. 예: 타격 = 접촉음(짧고 높음) + 몸통음(중역) + 꼬리(잔향).
- 층을 따로 만들면 무기별로 접촉음만 바꿔 재사용할 수 있고, 음색이 통일된다.
- 같은 계열(같은 포탑, 같은 적)의 소리는 같은 기본 층을 공유한다.

### 동시 재생 관리 `[실무]`
- 같은 소리가 한 프레임에 여러 번 나면 1회로 합치고 음량만 조금 올린다.
- 이벤트별 최대 동시 재생 수를 정하고, 넘으면 가장 오래된 것부터 끊는다.
- 피격·코어 피해처럼 놓치면 안 되는 소리는 동시 재생 제한에서 우선권을 준다.

### 자주 하는 실수
- 단독으로 들으면 좋은데 수십 번 겹치면 귀가 아프다. 실제 물량에서 확인한다.
- UI 소리를 화려하게 만들어 전투 소리보다 크게 들린다.

## 5. 금지
| 금지 | 이유 | 예외 |
|---|---|---|
| 어택 앞 무음 방치 | 입력 지연처럼 느껴짐 | 의도한 딜레이 연출 |
| 자주 나는 소리를 변형 없이 1개만 | 반복 피로 | 드물게 나는 소리 |
| 단독 청취로 확정 | 실제 겹침을 놓침 | 없음 |
| 저작권 불명확한 소스 사용 | 출시 후 분쟁 | 라이선스 확인된 경우 |
| 우선순위 낮은 소리가 높은 소리를 가림 | 정보 전달 실패 | 없음 |

## 6. 요청서 예시
```
[목표] 마법 포탑 공격 효과음, 초당 최대 6회 재생
[맥락] 2D 디펜스, 손그림 판타지 세계. 공격은 2순위, 피격음과 코어 피해음보다 작아야 한다.
[재질] 유리 + 바람. 금속성 없음.
[숫자 스펙] 길이 0.18초, 어택 5ms 이내, 주 대역 2~5kHz, 리버브 0.3초 이하
[변형] 4개, 같은 계열에서 음색만 조금씩
[금지] 레이저, SF 신스, 저역 쿵 소리
[검증] 공격 애니메이션 발사 프레임과 함께 재생한 영상 첨부
```

## 7. 검증 체크리스트
- [ ] 어택 시작이 기준 이내다 (파형으로 확인)
- [ ] 끝에 클릭음이 없다
- [ ] 길이가 상한 이내다
- [ ] 우선순위별 음량 계층이 지켜진다
- [ ] 같은 소리 연속 재생 시 기계적으로 들리지 않는다
- [ ] 동작 타이밍과 맞는다 (영상으로 확인)
- [ ] 실제 플레이에서 손맛이 있다 (사람 판단)
- [ ] 소스 라이선스를 확인했다
