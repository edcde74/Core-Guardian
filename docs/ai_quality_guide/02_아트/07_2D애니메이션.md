> 범위: 스프라이트 시트 프레임 애니메이션, 2D 본(스켈레탈) 애니메이션. 3D 리깅은 [08_3D모델링_리깅](08_3D모델링_리깅.md), 이펙트는 [09_VFX](09_VFX.md).

## 1. 이 파트에서 AI 티가 나는 이유
이미지 모델에 "스프라이트 시트 만들어줘"라고 하면 특정 프레임에서 팔다리가 세 개가 되거나, 시작과 끝이 안 맞아 덜컹거리거나, 몸이 캔버스 밖으로 나가 잘린다. `[영상]`
프레임마다 따로 그려지는 것과 같아서 색, 비율, 외곽선이 프레임마다 흔들린다.

## 2. AI 티 패턴
| 패턴 | 왜 티가 나나 | 대신 이렇게 | 출처 |
|---|---|---|---|
| 특정 프레임에 팔다리가 늘어남 | 프레임별 구조 일관성 없음 | 잘 만들어진 스프라이트 생성 스킬(예: SpriteGen) 사용, 프레임 검수 | `[영상]` |
| 루프 시작과 끝이 안 맞아 덜컹 | 순환을 고려하지 않음 | 첫 프레임 = 마지막 다음 프레임 규칙, 루프 검사 | `[영상]` |
| 몸이 캔버스 밖으로 잘림 | 동작 범위 계산 없음 | 동작 최대 범위 기준 캔버스 여백 | `[영상]` |
| 프레임마다 색·크기가 흔들림 | 독립 생성 | 팔레트 양자화, 기준선·피벗 고정 | `[실무]` |
| 너무 부드러운 보간 | 모든 프레임 같은 간격 | 예비 동작·타격 정지 등 타이밍 규칙 | `[실무]` |
| 발이 바닥에서 미끄러짐 | 이동 속도와 보폭 불일치 | 보폭(px)과 이동 속도 연동 | `[실무]` |

## 3. 작업 전에 정할 것 (프로젝트 설정값)
- 프레임 레이트: 예) 도트 8~12fps, 일반 2D 12~24fps `[실무]`
- 동작별 프레임 수: 대기 4~6, 걷기 6~8, 달리기 6~8, 공격 4~8, 피격 2~3, 사망 6~10 `[실무]`
- 동작별 길이: 예) 점프 0.11초처럼 숫자로 고정 `[영상]`
- 타이밍: 예비 동작 프레임 수, 타격 정지(hit stop) 2~4프레임 또는 50~80ms `[실무]`
- 캔버스: 동작 최대 범위 + 여백 8px, 모든 동작 같은 캔버스 `[실무]`
- 피벗과 기준선: 발 위치 고정 `[실무]`
- 보폭: 걷기 한 주기 이동 거리(px)와 이동 속도 연동 `[실무]`
- 시트 배치: 행=동작, 열=프레임, 파일 이름 규칙

## 4. 작업 규칙
1. 스펙을 먼저 고정한다. 몸 형태와 비율을 통일하고 동작 길이·각도를 숫자로 정한다. `[영상]`
2. 한 캐릭터에서 잘 된 동작은 같은 체형 캐릭터에 재사용한다. 스펙 고정이 재사용을 가능하게 한다. `[영상]`
3. 스프라이트 시트 생성은 검증된 스킬을 쓴다. 그냥 이미지 모델에 시트를 부탁하지 않는다. `[영상]`
4. 각 프레임을 같은 기준선에 겹쳐(어니언 스킨) 비율·팔다리 수를 확인한다. `[실무]`
5. 루프 동작은 마지막 프레임 → 첫 프레임 전환을 따로 확인한다. `[영상]`
6. 모든 프레임을 팔레트로 양자화하고 외곽선 두께를 통일한다. `[실무]`
7. 캔버스 경계에 닿는 불투명 픽셀이 있는지 스크립트로 확인한다(잘림 검사). `[영상]`
8. 게임 속도로 재생한 GIF·영상을 만들어 사람이 본다. 정지 시트만 보고 확정하지 않는다. `[실무]`
9. 걷기·달리기는 실제 이동 속도로 배경 위에서 재생해 발 미끄러짐을 본다. `[실무]`

## 5. 금지
| 금지 | 이유 | 예외 |
|---|---|---|
| 이미지 모델에 시트를 한 번에 부탁하고 그대로 사용 | 팔다리 이상, 루프 깨짐 `[영상]` | 검증 스킬 + 프레임 검수 |
| 동작마다 다른 캔버스·피벗 | 동작 전환 시 튐 | 없음 |
| 정지 시트로만 확정 | 움직임 문제를 못 봄 | 없음 |
| 모든 프레임 같은 간격 | 손맛 없음 | 기계적 동작(의도) |

## 6. 요청서 예시
```
[목표] 근접 적 걷기·공격 애니메이션
[맥락] 탑다운, 화면 높이 64px. 묵직하고 느린 느낌
[레퍼런스] chr_enemy_brute_down_idle.png, palette_v1.gpl
[숫자 스펙] 12fps, 걷기 8프레임(보폭 24px/주기, 이동 속도 36px/s),
           공격 7프레임(예비 3 / 타격 1 / 정지 2 / 복귀 1), 캔버스 128×128, 피벗 (0.5, 0)
[금지] 프레임별 색 변화, 캔버스 잘림, 루프 끊김
[검증] 어니언 스킨 겹침 이미지, 루프 전환 2프레임 확대, 잘림 검사 리포트,
       배경 위 실제 속도 재생 GIF
[산출물] enemy_brute_walk.png, enemy_brute_attack.png (시트) + GIF
```
```
이 걷기 시트 8프레임을 검수해줘.
1) 프레임별 팔다리 수와 실루엣 면적(px) 표
2) 7→0 프레임 전환 확대 비교
3) 캔버스 경계에 닿는 불투명 픽셀 위치
4) 실제 이동 속도로 배경 위 재생한 GIF
문제가 있는 프레임 번호와 수정 지시를 같이 줘.
```

## 7. 검증 체크리스트
- [ ] 프레임 수·fps·길이가 스펙과 같다
- [ ] 모든 프레임 팔다리 수와 비율이 맞다
- [ ] 루프 전환에서 튀지 않는다
- [ ] 캔버스 잘림이 없다
- [ ] 팔레트 외 색이 없다
- [ ] 이동 속도와 보폭이 맞아 미끄러지지 않는다
- [ ] 게임 속도 재생을 사람이 봤다
