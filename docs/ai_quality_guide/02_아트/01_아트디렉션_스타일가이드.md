# 아트 / 아트디렉션·스타일가이드

> 범위: 게임 전체 화풍을 고정하는 기준 문서와 레퍼런스 관리. 개별 에셋 제작 방법은 각 세부 파일에서 다룬다.
> 함께 볼 파일: [02_2D원화_컨셉](02_2D원화_컨셉.md), [06_2D_UI_아이콘](06_2D_UI_아이콘.md), [공통원칙](../00_공통/01_공통원칙.md)

## 1. 이 파트에서 AI 티가 나는 이유
아트디렉션이 없으면 AI는 자기 기준의 "멋진" 결과를 낸다. 그 결과가 보라색 네온, 그라데이션, 과한 디테일이다. `[영상]`
레퍼런스가 있어도 대상이 크게 바뀌면 화풍이 깨진다. 게임 막바지에 그림이 하나로 묶이지 않는 느낌이 가장 큰 문제다. `[영상]`
스타일가이드는 이 두 문제를 막는 문서다.

## 2. AI 티 패턴
| 패턴 | 왜 티가 나나 | 대신 이렇게 | 출처 |
|---|---|---|---|
| 보라·청록 네온, 그라데이션, 발광 띠 | "미래적", "예쁘게"의 기본값 | 팔레트 HEX를 고정하고 글로우 금지를 명시 | `[영상]` |
| 에셋마다 다른 화풍 | 대상별로 레퍼런스를 다르게 해석 | 대상·테마별 중간 레퍼런스를 만든다 | `[영상]` |
| 스테이지가 바뀌면 UI·이미지가 안 어울림 | 바다 스테이지 기준으로 만든 규칙이 불 스테이지에 안 맞음 | 테마별 중간 레퍼런스 추가 | `[영상]` |
| 모든 면에 과한 디테일과 질감 | AI 투고 이미지의 기본 성향 | 디테일 밀도 상한을 정한다 | `[영상]` |
| 완벽한 대칭과 매끈한 선 | 사람 손맛이 없음 | 비대칭, 노이즈, 선 흔들림을 규칙으로 넣는다 | `[영상]` |
| 광원 방향이 에셋마다 다름 | 생성마다 조명을 새로 정함 | 광원 방향을 하나로 고정 | `[실무]` |
| 채도가 전부 높음 | 시선 유도가 안 됨 | 채도 단계를 역할별로 나눈다 | `[실무]` |

## 3. 작업 전에 정할 것 (프로젝트 설정값)
값은 [프로젝트 설정](../00_공통/03_프로젝트설정_템플릿.md)에 적는다.
- 메인 레퍼런스 이미지 1~3장과 각각 "무엇을 따를지"(선, 색, 형태 중 무엇)
- 팔레트: 전체 색 수(예: 16~32색), 역할별 HEX(배경, 아군, 적, 강조, UI)
- 명도 구간: 배경 명도 20~50%, 상호작용 대상 60~90% 같은 범위 `[실무]`
- 채도 상한: 배경 채도 40% 이하, 강조색만 80% 이상 `[실무]`
- 광원 방향: 예) 좌상단 45도, 그림자 색은 검정이 아닌 팔레트 내 어두운 보색 `[실무]`
- 외곽선: 있음/없음, 두께(px), 색(검정 또는 대상색의 어두운 톤)
- 셰이딩 단계 수: 예) 플랫 1단 + 그림자 1단
- 디테일 밀도: 화면 크기 64px 대상에 내부 디테일 선 최대 몇 개
- 화면 비율별 실제 표시 크기: 캐릭터 화면 높이 대비 8~12% 등
- 사람 손맛 규칙: 선 흔들림 여부, 종이·노이즈 질감 강도(예: 불투명도 3~6%)
- 금지 요소 목록과 예외 조건

## 4. 작업 규칙
1. 레퍼런스 이미지를 먼저 고정한다. 모든 작업은 이 이미지를 기준으로 한다. `[영상]`
2. 레퍼런스만으로는 부족하다. 숫자로 된 아트 디렉션을 붙인다. 예) 테두리 2px, 글로우 금지, 팔레트 8~16색. `[영상]`
3. 숫자가 100% 지켜지지 않아도 의도는 전달된다. 그래도 넣는다. `[영상]`
4. 성격이 크게 다른 대상(배경 ↔ 소품, 생물 ↔ 기계)이나 테마(물 ↔ 불)마다 중간 레퍼런스를 만든다. `[영상]`
5. 금지 규칙은 메모리나 규칙 파일에 넣어 매번 넘긴다. `[영상]`
6. 새 에셋은 단독으로 평가하지 않는다. 실제 게임 화면에 올려 다른 에셋과 같이 본다. `[영상]`
7. 스타일가이드는 한 장짜리 보드로도 만든다. 팔레트, 선 예시, 셰이딩 예시, 금지 예시를 한 이미지에 모은다. `[실무]`
8. 회색조로 바꿔 명도 구조가 읽히는지 확인한다. 색을 빼도 주인공과 위험 요소가 구분돼야 한다. `[실무]`
9. 스타일가이드를 바꾸면 버전과 날짜를 남기고, 바뀐 규칙을 적용할 에셋 목록을 만든다. `[실무]`

## 5. 금지
| 금지 | 이유 | 예외 |
|---|---|---|
| 레퍼런스 없이 "예쁘게/멋지게/미래적으로" 요청 | AI 기본값이 나온다 `[영상]` | 없음 |
| 의미 없는 네온·그라데이션·발광 | AI 티의 대표 `[영상]` | 네온이 컨셉인 게임 |
| 대상마다 다른 레퍼런스 사용 | 화풍 분열 | 중간 레퍼런스로 연결된 경우 |
| 팔레트 밖 색 추가 | 일관성 붕괴 | 스타일가이드 개정으로 추가한 경우 |
| 형용사만 있는 피드백("더 세련되게") | 개성을 깎는다 `[영상]` | 없음 |

## 6. 요청서 예시
```
[목표] 2D 액션 게임 스타일가이드 보드 1장
[맥락] 어두운 숲 배경, 플레이어는 작고 빠른 캐릭터. 긴장감과 따뜻함이 같이 있어야 함
[레퍼런스] refs/main_01.png (선과 형태), refs/main_02.png (색감)
[숫자 스펙] 팔레트 24색, 외곽선 2px 진갈색 #2B1D14, 셰이딩 2단, 광원 좌상단 45도,
           배경 채도 35% 이하, 강조색 #F2B33D만 채도 80% 이상
[금지] 네온, 그라데이션 하늘, 글로우, 이모지, 완전 대칭
[검증] 회색조 버전도 같이 출력. 강조색이 화면의 5% 이하인지 표시
[산출물] style_board_v1.png, palette_v1.gpl
```
```
이번 에셋이 기존 화풍에서 벗어나는 지점을 3개 찾아줘.
기준: style_board_v1.png, palette_v1.gpl
비교 대상: 실제 게임 스크린샷 위에 새 에셋을 올린 이미지
결과는 문제 위치를 박스로 표시한 이미지와 수정 지시 목록으로.
```

## 7. 검증 체크리스트
- [ ] 사용 색이 팔레트 안에 있다 (스크립트로 색 추출해 비교)
- [ ] 외곽선 두께가 규칙과 같다
- [ ] 회색조에서 주인공·적·상호작용 대상이 구분된다
- [ ] 강조색 면적이 규칙 이하다
- [ ] 실제 게임 화면 위에서 다른 에셋과 같이 봤다
- [ ] 테마가 다른 스테이지에서도 어울린다
- [ ] 사람이 보드와 화면을 보고 승인했다
