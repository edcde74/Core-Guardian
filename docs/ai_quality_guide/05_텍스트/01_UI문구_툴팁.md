# 텍스트 / UI 문구·툴팁

> 범위: 버튼, 메뉴, 알림, 툴팁, 스킬·아이템 설명, 튜토리얼 안내 문구. 긴 이야기 텍스트는 [02_스토리텍스트](02_스토리텍스트.md)에서 다룬다.
> 함께 볼 파일: [03_용어집](03_용어집.md), [04_번역_현지화](04_번역_현지화.md), [03_개발/02_UI구현](../03_개발/02_UI구현.md)

## 1. 이 파트에서 AI 티가 나는 이유
UI 문구는 짧아서 AI 특유의 기호와 문형이 바로 눈에 띈다. 게이머가 툴팁에서 엠대시나 가운뎃점을 보면 "그냥 딸깍해서 만든 게임"이라고 판단한다. AI는 같은 효과를 문장마다 다른 말로 바꿔 쓰는 경향도 있어서, 규칙을 정확히 전달해야 하는 게임 문구에서 특히 문제가 된다. `[영상]`

## 2. AI 티 패턴
### 기호
| 패턴 | 왜 티가 나나 | 대신 이렇게 | 출처 |
|---|---|---|---|
| 엠대시(—) | 사람은 키보드로 거의 안 침 | 쉼표, 마침표, 괄호로 바꾼다 | `[영상]` |
| 장식용 가운뎃점(·) 나열 | 데이터 나열에 AI가 습관적으로 넣음 | 쉼표나 줄바꿈 | `[영상]` |
| 화살표(→) | 같은 이유 | "~하면", "~에서 ~로" | `[영상]` |
| 별표(*) 강조 | 옛 모델 흔적이 남은 것 | 강조가 필요하면 UI 색·굵기로 | `[영상]` |
| 장식 이모지 | 웹·SNS 톤 | 아이콘 이미지로 대체하거나 뺀다 | `[실무]` |

### 한국어 문형
| 패턴 | 왜 티가 나나 | 대신 이렇게 | 출처 |
|---|---|---|---|
| "단순히 ~가 아니라" | 중요하다는 걸 과장 | 무엇을 하는지만 쓴다 | `[영상]` |
| "A가 아닌 B" | AI의 대표 대조 문형 | B만 쓴다 | `[영상]` |
| "핵심은 ~입니다" | 결론 강조 습관 | 핵심 내용을 바로 쓴다 | `[영상]` |
| "찌르다", "축을 세운다", "경계" 같은 비유 | 문맥과 상관없이 자주 나옴 | 평범한 동사로 | `[영상]` |
| "조용히 ~했다", "~하다가 멈췄다" | 분위기용 상투구 | 뺀다 | `[영상]` |
| "박았습니다", "죽었습니다" (작업·시스템 보고 말투) | AI 작업 로그 말투가 문구에 섞임 | 게임 세계 말투로 | `[영상]` |
| "~를 통해", "~에 있어서", "~함으로써" | 번역투, 길어짐 | "~로", "~하면" | `[실무]` |
| "강력한", "압도적인", "궁극의" 남발 | 과장 형용사, 정보 없음 | 수치로 보여준다 | `[실무]` |
| 문장마다 같은 효과를 다른 말로 | 규칙이 헷갈림 | 용어집 단어만 쓴다 | `[영상]` |

### 영어 문형 `[실무]`
| 패턴 | 대신 이렇게 |
|---|---|
| delve, tapestry, testament, realm, embark, unleash, elevate | 평범한 동사·명사 |
| "It's not just X, it's Y" | Y만 쓴다 |
| "Whether you're A or B, ..." | 대상이 하나면 그 대상만 |
| 세 개씩 나열하는 습관 (fast, fun, and fierce) | 필요한 개수만 |
| "seamless", "cutting-edge", "game-changer" | 구체적인 기능 |

## 3. 작업 전에 정할 것 (프로젝트 설정값)
- 말투: 존댓말/반말, 명령형("배치하세요"/"배치")
- 문구 종류별 최대 글자 수 (버튼, 툴팁 제목, 툴팁 본문)
- 숫자 표기 규칙 (단위, 퍼센트, 소수점, 증감 기호)
- 효과 설명 문장 틀 (예: "[대상]에게 [수치] [효과]. [지속 시간]")
- 허용 기호 목록
- 용어집 경로

## 4. 작업 규칙
1. 용어집을 먼저 넘긴다. 효과·상태이상·자원 이름은 용어집 단어만 쓴다. [03_용어집](03_용어집.md)
2. 효과 설명은 정해진 문장 틀을 따른다. 같은 종류 효과는 같은 문장 구조로 쓴다.
3. 형용사보다 숫자. "강력한 공격" 대신 "피해 30".
4. 생성 후 금지 기호와 금지 문형의 **개수를 센다.** 하나라도 있으면 고친다. `[영상]`
5. 번역투가 남았으면 교정 단계를 한 번 더 돌린다. 번역투 교정용 스킬을 써도 좋다. 다만 문장 구조 위주로 보기 때문에 단어 목록 확인은 따로 한다. `[영상]`
6. 실제 UI에 넣고 스크린샷으로 확인한다. 글자 넘침, 줄바꿈 위치, 가장 긴 언어 기준. [06_QA/02](../06_QA/02_시각_해상도.md)

## 5. 금지
| 금지 | 이유 | 예외 |
|---|---|---|
| 위 기호·문형 | AI 티 | 프로젝트 표기 규칙으로 정한 경우 |
| 용어집에 없는 효과 이름 | 규칙 혼동 | 용어집에 먼저 추가한 경우 |
| 수치 없는 효과 설명 | 플레이어가 판단 못함 | 의도적으로 숨긴 정보 |
| 이미지 안에 글자 굽기 | 수정·번역 불가 | 로고 |

## 6. 요청서 예시
```
[목표] 포탑 업그레이드 툴팁 8개
[말투] 존댓말 없이 짧은 명사형. 툴팁 제목 8자, 본문 40자 이내
[문장 틀] "[효과] [수치]. [조건]" 예: "공격 속도 +20%. 3초 동안"
[용어] 첨부한 용어집 단어만 사용
[금지] 엠대시, 가운뎃점, 화살표, 별표, 이모지, "A가 아닌 B", "강력한"
[검증] 금지 기호·문형 개수를 세서 0개임을 표로 보고
```

## 7. 검증 체크리스트
- [ ] 금지 기호 개수 0 (검색으로 확인)
- [ ] 금지 문형 개수 0
- [ ] 용어집 밖 효과 이름 0
- [ ] 글자 수 기준 이내
- [ ] 같은 종류 효과는 같은 문장 구조
- [ ] 실제 UI 스크린샷에서 넘침·잘림 없음
- [ ] 처음 보는 사람이 읽고 효과를 설명할 수 있다 (사람 판단)
