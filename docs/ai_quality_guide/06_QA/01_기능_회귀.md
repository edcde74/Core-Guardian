## 1. 이 파트에서 AI 티가 나는 이유
AI는 자기가 만든 코드를 자기가 검사하면서 "모든 테스트 통과"라고 보고한다. 테스트가 정상 경로만 확인하거나, 실패하는 테스트를 고치는 대신 기대값을 바꾸거나, 테스트를 아예 돌리지 않고 통과했다고 쓰는 경우가 있다. `[실무]`

## 2. AI 티 패턴
| 패턴 | 왜 티가 나나 | 대신 이렇게 | 출처 |
|---|---|---|---|
| 실행 안 하고 "통과" | 보고와 사실 불일치 | 테스트 결과 파일·로그 첨부 | `[실무]` |
| 정상 경로만 테스트 | 경계값 누락 | 0, 최대, 중복, 동시 발생 케이스 | `[실무]` |
| 실패 시 기대값 수정 | 버그를 테스트에 맞춤 | 기대값 변경은 사람 승인 | `[실무]` |
| 기능만 보고 화면 미확인 | 코드 기반 검증만 함 | 스모크 테스트 + 스크린샷 | `[영상]` |
| 바뀐 기능만 확인 | 회귀 누락 | 핵심 흐름 회귀 세트 매번 실행 | `[실무]` |
| 매번 수동 QA | 반복 실수·누락 | 에디터 조작 자동 QA, 훅 + 테스트 프레임워크 | `[영상]` |

## 3. 작업 전에 정할 것 (프로젝트 설정값)
- 테스트 종류별 위치(EditMode / PlayMode / 빌드 스모크)
- 핵심 흐름 회귀 세트(예: 시작 → 설치 → 웨이브 → 승리/패배 → 재시작)
- 결과 파일 형식·저장 위치
- 자동 실행 시점(커밋 전 훅, 빌드 전, 수동)

## 4. 작업 규칙
1. **완료 조건을 먼저 쓴다.** 무엇이 보이면 통과인지 한 줄.
2. **규칙 계산은 단위 테스트로 고정한다.** 데미지, 경제, 확률, 스폰 순서.
3. **흐름은 스모크 테스트로 확인한다.** 실제로 씬을 돌려 처음부터 끝까지 지나가는지 본다. `[영상]`
4. **스크린샷을 남긴다.** 동작 확인과 화면 확인을 같이 한다. `[영상]`
5. **회귀 세트를 매번 돌린다.** 작은 수정도 핵심 흐름은 확인한다.
6. **자동화한다.** 훅과 테스트 프레임워크로 자동 테스트를 걸어두면 구현 속도가 빨라진다. 업데이트 후 에디터를 조작해 확인·스크린샷·코드 확인까지 하는 에이전트 QA도 쓸 수 있다. `[영상]`
7. **보고는 사실만.** 실행한 것, 결과, 실행하지 못한 것을 구분한다.

## 5. 금지
| 금지 | 이유 | 예외 |
|---|---|---|
| 실행 없는 통과 보고 | 거짓 보고 | 없음 |
| 기대값 임의 수정 | 버그 은폐 | 기획 변경 승인 |
| 실패 테스트 삭제·비활성 | 회귀 은폐 | 사유 기록 + 승인 |
| 사용자의 플레이·검사 중단 | 작업 방해 | 없음 |

## 6. 요청서 예시
```
[목표] 포탑 판매 기능 회귀 확인.
[테스트] EditMode: 환급 금액(설치비 50%, 업그레이드 포함), 판매 후 칸 재사용.
         PlayMode 스모크: 설치→업그레이드→판매→같은 칸 재설치.
[검증] 결과 XML 경로, 실패 목록, 각 단계 스크린샷. 실행 못 한 테스트는 따로 표시.
[금지] 실패 시 기대값 수정. 실패하면 원인 분석만 하고 멈춰라.
```

## 7. 검증 체크리스트
- [ ] 테스트 결과 파일·로그 첨부
- [ ] 경계값 케이스 포함
- [ ] 핵심 흐름 회귀 세트 통과
- [ ] 스모크 테스트 스크린샷
- [ ] 실행 못 한 항목 명시
- [ ] 사람이 직접 한 번 플레이
