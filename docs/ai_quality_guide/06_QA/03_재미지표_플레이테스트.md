# QA / 재미 지표·플레이테스트

> 범위: "재미있는가", "손맛이 있는가"를 판단하는 방법. AI가 볼 수 있는 지표 설계와 사람 플레이테스트. 밸런스 수치 설계는 [01_기획/05_밸런스_경제](../01_기획/05_밸런스_경제.md)에서 다룬다.
> 함께 볼 파일: [00_공통/01_공통원칙](../00_공통/01_공통원칙.md) 7번, [01_기획/03_전투](../01_기획/03_전투.md)

## 1. 이 파트에서 AI 티가 나는 이유
AI는 손맛을 느끼거나 소리를 들을 수 없다. 그래서 결과물이 무난하지만 개성 없는 쪽으로 간다. 재미 판단을 AI에게 맡기면 "균형 잡혀 있다" 같은 일반론이 나온다. 반대로 지표를 주면 AI도 많은 것을 판단할 수 있다. `[영상]`

## 2. AI 티 패턴
| 패턴 | 왜 티가 나나 | 대신 이렇게 | 출처 |
|---|---|---|---|
| AI가 "재미있다"고 판정 | 체감 불가 | 재미 판단은 사람 | `[영상]` |
| 감각적 요소를 말로만 설명 | AI가 확인 불가 | 지표로 바꿔서 제공 | `[영상]` |
| 평균값만 보는 밸런스 | 긴장·완급이 사라짐 | 시간축 그래프(위기 구간, 여유 구간) | `[실무]` |
| 결과 보고가 긴 글 | 판정하기 어려움 | A/B 비교 영상·이미지 | `[영상]` |
| 플레이테스트 메모가 흩어짐 | 다음 판단에 못 씀 | 결정과 이유를 기록 | `[영상]` |

## 3. 작업 전에 정할 것 (프로젝트 설정값)
- 플레이어가 느껴야 할 핵심 감정 3개 [프로젝트 설정](../00_공통/03_프로젝트설정_템플릿.md)
- 감정별 측정 지표(아래 예시)
- 자동 시뮬레이션(봇) 가능 여부와 봇 전략
- 플레이테스트 질문지
- 결정 기록 위치

## 4. 작업 규칙
1. **감각을 지표로 바꾼다.** `[영상]`
   - 소리: 스펙트로그램(소리를 이미지로)
   - 타이밍: 박자와 입력 사이 ms 오차
   - 움직임: 봇이 얼마나, 몇 칸 안에서 움직였는지
   - 그 밖의 예 `[실무]`: 위기 구간 비율(코어 체력 30% 이하 시간), 선택지 사용 분포, 첫 실패까지 시간, 한 판 길이, 결정 횟수/분
2. **지표로 먼저 거른다.** 봇 시뮬레이션으로 너무 쉽거나 어려운 안을 걸러낸다. 지표를 쌓으면 검증 상당 부분을 자동화할 수 있다. `[영상]`
3. **판정은 비교로 만든다.** A안·B안 비교 영상이나 나란히 놓은 그래프로 사람이 고르기만 하게 한다. `[영상]`
4. **사람이 직접 플레이한다.** 재미 판단은 사람이 한다. 이미 재미가 검증된 고전 게임 복각 같은 경우가 아니면 자동화할 수 없다. `[영상]`
5. **외부 플레이테스트는 말보다 행동을 본다.** 멈춘 곳, 다시 시도한 곳, 그만둔 곳. `[실무]`
6. **결정과 이유를 기록한다.** 다음 판단의 기준이 되고 AI에게 넘길 규칙이 된다. `[영상]`

## 5. 금지
| 금지 | 이유 | 예외 |
|---|---|---|
| AI 판정으로 재미 확정 | 체감 불가 | 없음 |
| 지표 없이 "느낌상 좋아짐" 보고 | 재현 불가 | 사람의 플레이 소감(명시) |
| 테스터에게 유도 질문 | 결과 왜곡 | 없음 |
| 기록 없는 밸런스 결정 | 같은 고민 반복 | 없음 |

## 6. 요청서 예시
```
[목표] 웨이브 1~10 긴장감 비교.
[지표] 봇 30판 시뮬레이션: 라운드별 코어 체력 최저값, 체력 30% 이하 시간 비율, 패배 라운드 분포.
[산출물] A안(현재)·B안(초반 적 +10%) 지표를 같은 축 그래프로 나란히. 웨이브 5 장면 A/B 비교 영상 10초.
[금지] 어느 쪽이 더 재미있다는 판정. 수치 차이만 설명해라. 선택은 내가 한다.
```

## 7. 검증 체크리스트
- [ ] 핵심 감정마다 지표가 하나 이상 있음
- [ ] 지표가 시간축으로 보임(평균만 아님)
- [ ] A/B 비교 자료가 판정하기 쉬운 형태
- [ ] 사람이 직접 플레이함
- [ ] 결정과 이유가 기록됨
