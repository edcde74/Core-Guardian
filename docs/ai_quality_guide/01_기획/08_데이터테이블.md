# 기획 / 데이터테이블

> 범위: 기획 데이터를 표로 관리하는 규칙(ID, 스키마, 참조, 검증). 수치 목표는 [05_밸런스_경제](05_밸런스_경제.md), 코드에서 읽는 방식은 [../03_개발/01_클라이언트_게임플레이](../03_개발/01_클라이언트_게임플레이.md)에서 다룬다.
> 함께 볼 파일: [02_컨텐츠](02_컨텐츠.md), [../05_텍스트/03_용어집](../05_텍스트/03_용어집.md), [../03_개발/03_에디터툴_자동화](../03_개발/03_에디터툴_자동화.md)

## 1. 이 파트에서 AI 티가 나는 이유
AI가 만든 테이블은 열이 많고 그럴듯하지만 규칙이 없다. ID가 행마다 다른 형식이고, 같은 의미의 열 이름이 테이블마다 다르다.
다른 테이블을 참조하는 값이 실제로 존재하는지 확인하지 않는다.
사람이 볼 때는 멀쩡해 보여도 코드가 읽는 순간 깨진다.

## 2. AI 티 패턴
| 패턴 | 왜 티가 나나 | 대신 이렇게 | 출처 |
|---|---|---|---|
| ID 형식이 섞임(tower_01, Tower1, T-001) | 행마다 새로 생성 | ID 규칙을 문서로 고정하고 검증 스크립트로 확인 | `[실무]` |
| 같은 의미의 열 이름이 테이블마다 다름(hp, HP, health) | 테이블을 따로 생성 | 공통 열 사전을 만든다 | `[실무]` |
| 존재하지 않는 ID 참조 | 참조 무결성 확인 안 함 | 참조 열을 표시하고 자동으로 확인 | `[실무]` |
| 설명 열에 효과 문구를 자유롭게 씀 | 텍스트와 데이터 혼합 | 효과는 태그 ID, 문구는 텍스트 테이블 키로 분리 | `[실무]` |
| 효과 이름이 행마다 다름 | 같은 개념을 다른 말로 | 효과 태그는 용어집 단어와 1:1 | `[영상]` 용어집 원칙 |
| 근거 없는 수치로 빈칸 채움 | 빈칸을 그럴듯하게 채움 | 미정은 빈칸 또는 `TBD`로 두고 확정 여부 열을 둔다 | `[실무]` |

## 3. 작업 전에 정할 것 (프로젝트 설정값)
값은 [프로젝트 설정](../00_공통/03_프로젝트설정_템플릿.md)에 적는다.
- 원본 형식 (스프레드시트, CSV, JSON)과 원본 위치(하나만)
- ID 규칙: 접두어, 구분자, 자릿수, 대소문자 (예: `TWR_0001`, `ENM_0001`)
- 공통 열 사전 (열 이름, 타입, 단위, 허용 범위)
- 참조 관계 (어느 열이 어느 테이블 ID를 가리키나)
- 텍스트 키 규칙 (예: `TWR_0001.name`, `TWR_0001.desc`)

## 4. 작업 규칙
1. **ID 규칙을 먼저 고정한다.** 접두어는 테이블 종류, 숫자는 고정 자릿수. ID는 한 번 쓰면 바꾸지 않는다. 삭제된 ID는 재사용하지 않는다. `[실무]`
2. **스키마를 문서로 둔다.** 열마다 이름 / 타입 / 단위 / 범위 / 필수 여부 / 참조 대상. AI에게 테이블 작업을 맡길 때 항상 같이 넘긴다. `[영상]` 규칙을 파일로
3. **데이터와 텍스트를 나눈다.** 데이터 테이블에는 텍스트 키만 두고 실제 문구는 텍스트 테이블에 둔다. 번역할 때 이 구조가 필요하다. `[실무]`
4. **검증 스크립트를 만든다.** 아래 항목을 자동으로 확인한다. 사람이 눈으로 찾지 않는다. `[실무]`
   - ID 형식과 중복
   - 필수 열 빈칸
   - 타입과 허용 범위
   - 참조 ID 존재 여부
   - 효과 태그가 용어집에 있는지
   - 텍스트 키가 텍스트 테이블에 있는지
5. **변경은 diff로 본다.** 테이블을 고치면 바뀐 행과 열만 표로 보여주게 한다. `[실무]`
6. **확정 여부 열을 둔다.** `제안` / `확정`. 사람이 고른 값만 `확정`. `[실무]`

## 5. 금지
| 금지 | 이유 | 예외 |
|---|---|---|
| 원본을 여러 곳에 둠 | 어느 것이 최신인지 모름 | 내보낸 사본은 읽기 전용으로 표시 |
| ID 변경·재사용 | 저장 데이터와 참조가 깨짐 | 출시 전 일괄 정리를 사람이 승인 |
| 데이터 테이블에 문구 직접 기입 | 번역·수정 불가 | 내부 메모 열 |
| 근거 없는 값으로 빈칸 채우기 | 가짜 확정값이 됨 | 없음 |
| 검증 스크립트 통과 전 반영 | 런타임 오류 | 없음 |

## 6. 요청서 예시
```
[목표] 적 테이블에 신규 적 3종 추가
[입력] 스키마 문서, 기존 enemies.csv, 효과 태그 목록, 용어집
[규칙] ID는 ENM_ + 4자리, 마지막 번호 다음부터. 문구는 텍스트 키만. 수치 미정이면 빈칸 + 확정여부=제안
[검증] 검증 스크립트 실행 결과(오류 0) 첨부. 바뀐 행만 diff 표로
```
```
[목표] 검증 스크립트 작성
[입력] 스키마 문서
[요청] ID 형식/중복, 필수 빈칸, 범위, 참조 존재, 태그-용어집, 텍스트 키 존재를 확인하고 오류를 파일:행:열 형식으로 출력
```

## 7. 검증 체크리스트
- [ ] 검증 스크립트 오류 0
- [ ] 모든 ID가 규칙을 따르고 중복이 없다
- [ ] 참조 ID가 모두 존재한다
- [ ] 효과 태그가 모두 용어집에 있다
- [ ] 텍스트 키가 모두 텍스트 테이블에 있다
- [ ] 바뀐 부분을 diff로 사람이 확인했다
- [ ] 미정 값이 `제안`으로 표시돼 있다
