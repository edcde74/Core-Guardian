# 기획 / 전투

> 범위: 공격·피격·상태이상·대상 선정·타이밍 같은 전투 규칙과 손맛 설계. 수치 목표는 [05_밸런스_경제](05_밸런스_경제.md), 구현은 [../03_개발/01_클라이언트_게임플레이](../03_개발/01_클라이언트_게임플레이.md)에서 다룬다.
> 함께 볼 파일: [02_컨텐츠](02_컨텐츠.md), [../02_아트/09_VFX](../02_아트/09_VFX.md), [../04_사운드/02_SFX](../04_사운드/02_SFX.md), [../06_QA/03_재미지표_플레이테스트](../06_QA/03_재미지표_플레이테스트.md)

## 1. 이 파트에서 AI 티가 나는 이유
AI는 전투를 숫자 계산으로 설계한다. 데미지 공식, 방어 감소율, 치명타 확률은 잘 쓰지만 "때리는 맛"은 모른다.
AI는 손맛을 느끼거나 소리를 들을 수 없다. `[영상]`
그래서 결과는 수식은 맞는데 타격감이 없고, 상태이상이 많은데 화면에서 구분이 안 되는 전투가 된다.

## 2. AI 티 패턴
| 패턴 | 왜 티가 나나 | 대신 이렇게 | 출처 |
|---|---|---|---|
| 데미지 공식만 있고 피드백 설계가 없음 | AI가 볼 수 있는 건 숫자뿐 | 공격 하나마다 예고 → 발동 → 적중 → 결과 4단계 피드백을 정한다 | `[실무]` |
| 상태이상 10종 이상 기본 탑재 | RPG 기본값 | 플레이어가 화면에서 구분할 수 있는 수만 둔다. 보통 4~6종 | `[실무]` |
| 상태이상 이름과 설명이 문서마다 다름 | 같은 개념을 다른 말로 씀 | 용어집에서 이름·효과·중첩 규칙을 한 번에 정한다 | `[영상]` |
| 모든 공격이 즉발, 같은 속도 | 타이밍 설계 생략 | 선딜·후딜·판정 프레임을 공격마다 정한다 | `[실무]` |
| 중첩·갱신·면역 규칙이 빠짐 | 예외 상황을 생략 | 같은 효과가 두 번 들어오면 어떻게 되나를 표로 정한다 | `[실무]` |
| "타격감 있게" 같은 형용사 지시 | 검증 불가 | 히트스톱 ms, 화면 흔들림 px, 넉백 거리 같은 숫자로 쓴다 | `[영상]` |

## 3. 작업 전에 정할 것 (프로젝트 설정값)
값은 [프로젝트 설정](../00_공통/03_프로젝트설정_템플릿.md)에 적는다.
- 전투 템포 (초당 공격 수, 한 전투 길이)
- 화면에 동시에 나오는 최대 적 수와 투사체 수
- 상태이상 목록과 시각 표현 규칙
- 피드백 기본값: 히트스톱(ms), 화면 흔들림(px, ms), 피격 플래시(ms), 데미지 숫자 표시 규칙
- 대상 선정 규칙 (가장 가까운 / 체력 낮은 / 경로 앞쪽 등)

## 4. 작업 규칙
1. **공격을 타임라인으로 쓴다.** 예고(텔레그래프) → 판정 → 적중 → 결과. 각 구간을 ms나 프레임으로 정한다. `[실무]`
2. **피드백은 숫자로 정한다.** 히트스톱 60ms, 흔들림 4px/120ms처럼 쓴다. 숫자가 있어야 AI가 구현하고 검증할 수 있다. `[영상]`
3. **상태이상은 표 하나로 관리한다.** 이름 / 효과 / 지속 / 중첩 / 갱신 / 면역 / 화면 표시. 텍스트, 아트, VFX가 모두 이 표를 따른다. `[실무]`
4. **용어를 고정한다.** 상태이상 이름은 툴팁, 로그, 번역 어디서나 같은 단어를 쓴다. `[영상]`
5. **손맛은 사람이 판단한다.** AI에게는 지표를 준다. 적중 판정 오차 ms, 입력 후 반응 시간, 한 전투 길이 같은 것이다. `[영상]`
6. **비교 영상으로 고른다.** 피드백 수치 A안/B안을 나란히 녹화해 비교한다. 사람은 판정만 한다. `[영상]`

## 5. 금지
| 금지 | 이유 | 예외 |
|---|---|---|
| 구분이 안 되는 상태이상 추가 | 화면에서 읽히지 않음 | 숨겨진 내부 효과로 설계한 경우 |
| 중첩·갱신 규칙 없는 효과 | 버그와 밸런스 붕괴 | 없음 |
| "타격감 있게", "시원하게" 단독 지시 | 검증 불가 | 숫자와 함께 쓸 때 |
| 피드백 없이 수치만 바뀌는 공격 | 플레이어가 차이를 못 느낌 | 패시브 보정 |

## 6. 요청서 예시
```
[목표] 액션 게임 근접 3타 콤보의 피드백 수치 2안
[맥락] 무거운 대검, 느리고 강한 느낌. 60fps.
[형식] 타마다 선딜/판정/후딜(프레임), 히트스톱(ms), 흔들림(px/ms), 넉백(유닛)
[조건] 3타째가 가장 무겁게. A안과 B안은 히트스톱 차이가 최소 30ms
[검증] 두 안을 같은 장면에서 녹화한 비교 영상으로 제출
```
```
[목표] 타워디펜스 상태이상 표 검토
[요청] 첨부 표에서 중첩/갱신/면역이 빠진 칸, 화면 표시가 다른 효과와 겹치는 칸을 찾아라. 새 효과를 추가하지 마라.
```

## 7. 검증 체크리스트
- [ ] 모든 공격에 타임라인(예고/판정/적중/결과) 숫자가 있다
- [ ] 상태이상 표에 중첩·갱신·면역·화면 표시가 다 있다
- [ ] 상태이상 이름이 용어집과 같다
- [ ] 최대 동시 적 수에서도 상태이상이 화면에서 구분된다 (스크린샷)
- [ ] A/B 비교 영상으로 사람이 손맛을 판정했다
- [ ] 결정한 수치와 이유를 기록했다
