# 기획 / UX·온보딩

> 범위: 화면 흐름, 정보 우선순위, 조작 설계, 튜토리얼과 첫 경험. 화면 그림은 [../02_아트/06_2D_UI_아이콘](../02_아트/06_2D_UI_아이콘.md), 구현은 [../03_개발/02_UI구현](../03_개발/02_UI구현.md)에서 다룬다.
> 함께 볼 파일: [01_시스템](01_시스템.md), [04_레벨디자인](04_레벨디자인.md), [../05_텍스트/01_UI문구_툴팁](../05_텍스트/01_UI문구_툴팁.md), [../06_QA/02_시각_해상도](../06_QA/02_시각_해상도.md)

## 1. 이 파트에서 AI 티가 나는 이유
AI가 가장 많이 학습한 UI는 게임이 아니라 웹과 앱이다. `[영상]`
그래서 게임 화면을 기획해도 카드 그리드, 사이드바, 설명 패널 같은 웹 구조가 나온다. `[영상]`
튜토리얼도 텍스트 팝업을 순서대로 띄우는 방식이 기본값이다. 플레이 중 시선과 손의 흐름은 고려되지 않는다.

## 2. AI 티 패턴
| 패턴 | 왜 티가 나나 | 대신 이렇게 | 출처 |
|---|---|---|---|
| 카드 그리드 + 사이드바 + 설명 패널 | 웹 UI 기본값 | 게임 장면 위에서 시선이 머무는 곳 기준으로 배치 | `[영상]` |
| 모든 정보를 한 화면에 동시 노출 | 정보 우선순위 없음 | 정보를 지금 꼭 봐야 함 / 결정할 때만 / 궁금할 때만 3단계로 나눈다 | `[실무]` |
| 텍스트 팝업 연속 튜토리얼 | 설명 = 글이라는 기본값 | 해보게 하고, 실패해도 안전한 상황에서 배우게 한다 | `[실무]` |
| 장식 이모지와 느낌표 많은 안내 | 웹·SNS 톤 | 세계관 톤에 맞는 짧은 안내 | `[영상]` |
| 버튼 모양·위치가 화면마다 다름 | 화면을 따로 생성 | 화면 구조도를 먼저 정하고 그 위에서 만든다 | `[영상]` |
| 해상도 하나에서만 맞춘 배치 | 생성 기준 해상도 하나 | 지원 비율 전부에서 확인 | `[영상]` |

## 3. 작업 전에 정할 것 (프로젝트 설정값)
값은 [프로젝트 설정](../00_공통/03_프로젝트설정_템플릿.md)에 적는다.
- 입력 방식 (마우스, 터치, 패드)과 손 위치
- 지원 화면 비율과 안전 영역
- 화면별 정보 3단계 분류
- 첫 10분 동안 배울 것 목록과 순서
- 최소 터치/클릭 영역 크기

## 4. 작업 규칙
1. **화면 흐름도를 먼저 그린다.** 화면 목록과 이동 경로. 막다른 화면, 뒤로 가기 없는 화면을 찾는다. `[실무]`
2. **구조도를 미리 정한다.** 화면 레이아웃을 목업이나 이미지 생성, 위젯으로 먼저 그려 버튼 배치를 고정한다. 그다음 AI에게 구현을 맡긴다. `[영상]`
3. **실제 스크린샷 위에 그린다.** 지금 게임 화면 스크린샷 위에 구조도를 덧그려 넘긴다. 버튼 일관성이 크게 오른다. `[영상]`
4. **정보는 3단계로 나눈다.** 항상 보임 / 결정 순간에 보임 / 요청 시 보임. 항상 보이는 정보는 최소로. `[실무]`
5. **온보딩은 행동으로 가르친다.** 배울 것 하나에 상황 하나. 글 설명은 한 줄 이내. 실패해도 잃는 게 적은 구간에서 가르친다. `[실무]`
6. **여러 비율에서 확인한다.** 16:9, 4:3, 21:9 등 지원 비율에서 스모크 테스트하고 스크린샷을 찍게 한다. `[영상]`
7. **마지막은 사람 눈으로.** 코드와 비전 검사를 통과해도 사람이 보면 문제가 있는 경우가 많다. 스크린샷을 사람에게 보내게 한다. `[영상]`

## 5. 금지
| 금지 | 이유 | 예외 |
|---|---|---|
| 웹 레이아웃을 그대로 게임 화면에 사용 | AI 티, 플레이 시선과 안 맞음 | 장르가 실제로 그 구조를 쓸 때(관리 시뮬 등) |
| 3줄 넘는 튜토리얼 팝업 | 읽지 않음 | 플레이어가 직접 연 도움말 |
| 구조도 없이 화면별 개별 생성 | 버튼 일관성 깨짐 | 없음 |
| 장식 이모지 | 웹 톤 | 의도된 캐주얼 SNS형 게임 |

## 6. 요청서 예시
```
[목표] 타워디펜스 전투 화면 HUD 배치 2안
[입력] 현재 전투 스크린샷(첨부)에 구조도 덧그린 이미지
[맥락] 마우스 조작. 시선은 화면 중앙 경로에 머문다. 항상 보임: 체력, 골드, 웨이브. 결정 순간: 설치 메뉴.
[금지] 사이드바, 카드 그리드, 이모지, 네온
[검증] 16:9, 16:10, 21:9, 4:3에서 스크린샷. 경로를 가리는 UI 면적 비율 표기
```

## 7. 검증 체크리스트
- [ ] 화면 흐름도에 막다른 화면이 없다
- [ ] 모든 화면이 같은 구조도의 버튼 위치·모양 규칙을 따른다
- [ ] 정보가 3단계로 나뉘어 있고 항상 보이는 정보가 최소다
- [ ] 첫 10분 학습 목록이 행동 기반이다
- [ ] 지원 비율 전부에서 스크린샷을 확인했다
- [ ] 사람이 스크린샷과 실제 플레이로 최종 확인했다
