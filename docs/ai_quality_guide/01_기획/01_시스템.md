# 기획 / 시스템

> 범위: 게임을 이루는 규칙과 구조(성장, 자원, 상호작용, 루프)의 설계. 개별 수치 조정은 [05_밸런스_경제](05_밸런스_경제.md), 전투 규칙 세부는 [03_전투](03_전투.md)에서 다룬다.
> 함께 볼 파일: [02_컨텐츠](02_컨텐츠.md), [08_데이터테이블](08_데이터테이블.md), [07_UX_온보딩](07_UX_온보딩.md)

## 1. 이 파트에서 AI 티가 나는 이유
AI 티는 화면에서만 나는 게 아니다. 기획에서도 난다. `[영상]`
"재밌는 로그라이크 시스템 짜줘"라고 하면 AI는 학습 데이터에서 가장 흔한 조합을 낸다. 3장 중 1장 고르기, 메타 화폐, 일일 퀘스트, 등급 5단계 같은 것들이다.
각 요소는 멀쩡하지만 이 게임이어야 하는 이유가 없다. 플레이어는 "어디서 본 시스템 짜깁기"라고 느낀다.

## 2. AI 티 패턴
| 패턴 | 왜 티가 나나 | 대신 이렇게 | 출처 |
|---|---|---|---|
| 장르 불문 "증강 카드 3장 중 1장 선택" | AI가 가장 많이 본 성장 구조 | 핵심 동사(배치, 회피, 조합 등)에서 성장 방식을 끌어낸다 | `[실무]` |
| 등급 5단계(일반~전설), 메타 화폐 2~3종 기본 탑재 | 모바일 F2P 기본값 | 장르와 판매 모델에 필요한 것만 둔다. 없앨 이유가 없으면 넣지 않는다 | `[실무]` |
| 시스템 간 연결 없이 나열 | 기능 목록을 채우는 방식으로 생성됨 | 시스템마다 "무엇을 입력받아 무엇을 내놓는가"를 적고 루프로 잇는다 | `[실무]` |
| 근거 없는 수치("공격력 +15%") | 그럴듯한 숫자를 기본값으로 붙임 | 수치는 밸런스 단계에서 목표 지표로 정한다. 시스템 문서엔 변수 이름만 둔다 | `[실무]` |
| 모든 시스템이 "재미있고 전략적인 선택" | 효과를 형용사로만 설명 | 플레이어가 실제로 고민하는 상황 하나를 예로 쓴다 | `[실무]` |
| 차별점 문장이 장르 설명과 같음 | 컨셉 없이 장르 평균을 냄 | "다른 OO 게임과 다른 점" 한 줄을 먼저 정하고 시스템이 그걸 받치는지 본다 | `[실무]` |
| 장황한 서론과 목차만 큰 기획서 | 분량으로 완성도를 흉내냄 | 1페이지 요약 + 규칙 표 + 예외 목록 | `[실무]` |

## 3. 작업 전에 정할 것 (프로젝트 설정값)
값은 [프로젝트 설정](../00_공통/03_프로젝트설정_템플릿.md)에 적는다.
- 핵심 동사 1~2개 (플레이어가 가장 많이 하는 행동)
- 한 판의 길이와 세션 길이
- 핵심 루프 한 줄 (행동 → 보상 → 성장 → 다시 행동)
- 차별점 한 줄
- 판매 모델 (프리미엄 / F2P / 광고)
- 넣지 않을 시스템 목록

## 4. 작업 규칙
1. **핵심 동사부터 정한다.** 모든 시스템은 그 동사를 더 재미있게 만들거나, 더 의미 있게 만들어야 한다. 둘 다 아니면 뺀다. `[실무]`
2. **시스템 카드를 쓴다.** 시스템마다 아래 다섯 줄을 쓴다.
   - 목적: 이 시스템이 없으면 무엇이 무너지나
   - 입력: 플레이어 행동이나 다른 시스템의 출력
   - 출력: 보상, 상태 변화, 다음 시스템의 입력
   - 결정: 플레이어가 고민하는 지점
   - 실패 시: 플레이어가 잘못 골랐을 때 무슨 일이 생기나
3. **루프 다이어그램을 그린다.** 시스템 카드를 화살표로 잇는다. 어디에도 연결되지 않는 카드는 빼거나 연결을 만든다. `[실무]`
4. **AI에게는 맥락을 다 준다.** 장르, 핵심 동사, 차별점, 넣지 않을 시스템을 같이 넘긴다. 맥락이 없으면 기본값이 나온다. `[영상]`
5. **후보를 여러 개 받아 비교한다.** 한 번에 하나를 받지 말고 2~3안을 받아 표로 비교한다. 사람이 고른다. `[영상]`
6. **제안과 확정을 구분한다.** 문서에 `제안` / `확정` 상태를 붙인다. 사람이 고른 것만 `확정`이다. `[실무]`
7. **결정 이유를 남긴다.** 고른 안과 버린 안, 그 이유를 적는다. 다음 시스템을 설계할 때 AI에게 같이 넘긴다. `[영상]`

## 5. 금지
| 금지 | 이유 | 예외 |
|---|---|---|
| 장르 관습 시스템을 이유 없이 기본 탑재 | 기본값 조합이 됨 | 장르 팬이 없으면 불편해하는 필수 관습(예: 로그라이크의 재시작) |
| 시스템 문서에 확정 수치 기입 | 근거 없는 숫자가 굳어짐 | 시스템 규칙 자체가 숫자인 경우(예: 슬롯 3칸) |
| "재미있는", "전략적인", "몰입감 있는" 단독 사용 | 검증 불가 형용사 | 구체적 상황 예시와 함께 쓸 때 |
| AI 제안을 확인 없이 확정으로 기록 | 결정 주체가 사라짐 | 없음 |

## 6. 요청서 예시
```
[목표] 타워디펜스의 웨이브 사이 성장 시스템 후보 3안
[맥락] 핵심 동사: 경로 위 배치. 한 판 20분. 차별점: 타워끼리 인접하면 성질이 섞인다.
[금지] 3장 중 1장 고르기 카드, 메타 화폐, 등급 체계
[형식] 안마다 시스템 카드 5줄(목적/입력/출력/결정/실패 시) + 기존 루프와 연결되는 지점
[검증] 안마다 "이 시스템이 없으면 무엇이 무너지나"에 답하지 못하면 제외
```
```
[목표] 액션 RPG 장비 시스템 검토
[입력] 첨부한 시스템 카드 6개
[요청] 어디에도 연결되지 않는 카드, 핵심 동사(회피)와 무관한 카드를 표시하고 이유를 적어라. 새 시스템을 추가하지 마라.
```

## 7. 검증 체크리스트
- [ ] 모든 시스템 카드에 목적·입력·출력·결정·실패 시가 있다
- [ ] 루프 다이어그램에서 고립된 시스템이 없다
- [ ] 차별점 한 줄을 받치는 시스템이 최소 하나 있다
- [ ] "넣지 않을 시스템" 목록에 있는 것이 섞이지 않았다
- [ ] 문서 안에 근거 없는 확정 수치가 없다
- [ ] 각 항목에 `제안`/`확정` 상태가 붙어 있다
- [ ] 사람이 종이 프로토타입이나 짧은 플레이로 핵심 결정이 실제로 고민되는지 확인했다
