# 기획 / 밸런스·경제

> 범위: 수치 목표, 성장 곡선, 자원 흐름(획득·소비), 난이도 조정. 시스템 구조는 [01_시스템](01_시스템.md), 데이터 형식은 [08_데이터테이블](08_데이터테이블.md)에서 다룬다.
> 함께 볼 파일: [03_전투](03_전투.md), [04_레벨디자인](04_레벨디자인.md), [../06_QA/03_재미지표_플레이테스트](../06_QA/03_재미지표_플레이테스트.md)

## 1. 이 파트에서 AI 티가 나는 이유
AI는 숫자를 그럴듯하게 만든다. 1.1배씩 오르는 곡선, 10·25·50·100 같은 둥근 값, 표가 빽빽한 밸런스 시트가 나온다.
그런데 왜 그 숫자인지, 플레이어가 어떤 경험을 하게 되는지가 없다.
숫자 나열만 있는 밸런스는 검증할 기준이 없어서 고칠 수도 없다.

## 2. AI 티 패턴
| 패턴 | 왜 티가 나나 | 대신 이렇게 | 출처 |
|---|---|---|---|
| 목표 없이 숫자표만 있음 | 숫자 생성이 쉬움 | 목표 경험을 지표로 먼저 쓴다(예: 3웨이브에서 첫 위기) | `[실무]` |
| 모든 곡선이 같은 배율(×1.1, ×1.2) | 공식 기본값 | 구간마다 의도를 다르게: 초반 빠른 성장, 중반 정체, 후반 폭발 등 | `[실무]` |
| 둥근 숫자만 사용(10, 50, 100) | 사람이 고른 것 같지 않음 | 지표 기준으로 역산한 값을 쓴다. 둥근 값은 UI 표시용으로만 | `[실무]` |
| 자원 획득만 있고 소비처 설계 없음 | 한쪽만 생성 | 자원마다 수입원/소비처/쌓이는 양 그래프 | `[실무]` |
| "적절한 난이도" 같은 형용사 목표 | 검증 불가 | 승률, 평균 남은 체력, 클리어 시간 같은 숫자 목표 | `[실무]` |
| 시뮬레이션 없이 숫자만 조정 | 감으로 조정 | 봇 시뮬레이션으로 지표를 측정하고 그 결과로 조정 | `[영상]` 지표화 원칙 |

## 3. 작업 전에 정할 것 (프로젝트 설정값)
값은 [프로젝트 설정](../00_공통/03_프로젝트설정_템플릿.md)에 적는다.
- 목표 지표 3~5개 (예: 첫 클리어 승률, 평균 플레이 시간, 위기 발생 시점, 자원 잔액)
- 구간 나누기 (초반/중반/후반의 기준)
- 자원 목록과 각 자원의 역할 한 줄
- 허용 오차 (지표가 목표에서 얼마나 벗어나면 다시 조정하나)
- 바꾸면 안 되는 고정값 목록

## 4. 작업 규칙
1. **경험 → 지표 → 숫자 순서로 정한다.** "중반에 한 번 위기를 겪는다" → "8웨이브 코어 체력 50% 이하 비율 40%" → 적 체력과 수 역산. 숫자부터 정하지 않는다. `[실무]`
2. **자원은 흐름으로 본다.** 시간에 따른 수입·소비·잔액 그래프를 그린다. 잔액이 계속 쌓이면 소비처가 부족한 것이다. `[실무]`
3. **봇으로 측정한다.** 정해진 전략의 봇을 여러 번 돌려 지표를 뽑는다. AI는 숫자를 보고 판단할 수 있다. `[영상]`
4. **한 번에 하나만 바꾼다.** 같은 조건에서 변수 하나만 바꾸고 전후 지표를 비교한다. `[실무]`
5. **전후 비교표를 남긴다.** 바꾼 값, 이전 지표, 이후 지표, 판단을 표로 남긴다. 사람은 표를 보고 판정한다. `[영상]` 평가 쉽게 만들기
6. **재미 판단은 사람이 한다.** 지표가 목표에 맞아도 지루할 수 있다. 마지막은 사람이 직접 플레이한다. `[영상]`
7. **고정값을 지킨다.** 확정된 밸런스는 AI가 임의로 바꾸지 못하게 고정값 목록에 넣는다. `[실무]`

## 5. 금지
| 금지 | 이유 | 예외 |
|---|---|---|
| 목표 지표 없는 수치 조정 | 맞았는지 알 수 없음 | 없음 |
| 여러 변수 동시 변경 | 원인 추적 불가 | 전체 스케일 조정(모든 값 ×k) |
| 측정 실패나 악화를 빼고 보고 | 판단을 왜곡 | 없음 |
| 고정값 목록 항목의 임의 변경 | 확정된 결정을 무너뜨림 | 사람이 명시적으로 승인 |

## 6. 요청서 예시
```
[목표] 타워디펜스 1~10웨이브 적 체력 조정안
[목표 지표] 기본 전략 봇 기준 승률 70~80%, 6~8웨이브 사이 코어 체력 50% 이하 1회 이상
[고정값] 타워 비용, 웨이브 수, 골드 획득량
[방법] 적 체력 배율 하나만 바꿔 3안. 안마다 봇 30회 실행
[산출물] 안별 승률/평균 남은 체력/위기 웨이브 표 + 측정 실패 여부
```
```
[목표] 로그라이크 상점 화폐 흐름 점검
[입력] 층별 획득/소비 로그
[요청] 층별 잔액 그래프와, 잔액이 2층 연속 증가하는 구간 표시. 수정안 제안은 2개까지.
```

## 7. 검증 체크리스트
- [ ] 목표 지표가 숫자로 정해져 있다
- [ ] 바꾼 변수가 하나뿐이다
- [ ] 전후 비교표에 같은 조건, 실행 횟수, 결과가 있다
- [ ] 측정 실패나 악화도 기록했다
- [ ] 자원 잔액 그래프가 의도대로 움직인다
- [ ] 고정값이 바뀌지 않았다
- [ ] 사람이 직접 플레이해 지루함이나 억울함이 없는지 판정했다
