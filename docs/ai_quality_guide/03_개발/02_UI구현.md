# 개발 / UI 구현

> 범위: HUD·메뉴·팝업을 엔진에 구현하는 일(레이아웃, 앵커, 데이터 바인딩, 입력). UI 그래픽 제작은 [02_아트/06_2D_UI_아이콘](../02_아트/06_2D_UI_아이콘.md), 문구는 [05_텍스트/01_UI문구_툴팁](../05_텍스트/01_UI문구_툴팁.md)에서 다룬다.
> 함께 볼 파일: [06_QA/02_시각_해상도](../06_QA/02_시각_해상도.md), [01_기획/07_UX_온보딩](../01_기획/07_UX_온보딩.md)

## 1. 이 파트에서 AI 티가 나는 이유
AI가 가장 많이 학습한 UI는 웹과 앱이다. 게임 UI를 맡기면 카드 그리드, 사이드바, 설명 패널 같은 웹 구조가 나온다. 그리고 코드상 동작하면 끝났다고 판단해서 글자 넘침, 겹침, 잘림을 놓친다. `[영상]`

## 2. AI 티 패턴
| 패턴 | 왜 티가 나나 | 대신 이렇게 | 출처 |
|---|---|---|---|
| 카드 그리드·사이드바·설명 패널 | 웹 레이아웃 기본값 | 목업·와이어프레임을 먼저 고정 | `[영상]` |
| 기능 동작만 보고 완료 | 코드 기반 검증만 함 | 스모크 테스트 + 스크린샷 | `[영상]` |
| 글자가 버튼·카드 밖으로 넘침 | 화면을 안 봄 | 비전 기반 검증, 최장 문자열 테스트 | `[영상]` |
| 한 해상도에서만 맞음 | 기준 해상도만 확인 | 16:9, 4:3, 21:9 등 다해상도 테스트 | `[영상]` |
| 버튼마다 크기·간격이 조금씩 다름 | 매번 새로 배치 | 스크린샷 위에 구조도를 그려 지시, 공통 프리팹 | `[영상]` |
| 픽셀 좌표 하드코딩 | 비율 바뀌면 깨짐 | 앵커·레이아웃 그룹·안전 영역 | `[실무]` |
| 매 프레임 텍스트 갱신 | 값이 안 바뀌어도 리빌드 | 값이 바뀔 때만 갱신 | `[실무]` |
| 상태(비활성·눌림·쿨다운) 누락 | 기본 상태만 구현 | 상태 표를 먼저 정의 | `[실무]` |

## 3. 작업 전에 정할 것 (프로젝트 설정값)
- UI 시스템(uGUI / UI Toolkit), Canvas Scaler 설정(기준 해상도, Match 값)
- 지원 비율 목록과 안전 영역
- 공통 컴포넌트 목록(버튼, 툴팁, 게이지, 팝업) 과 프리팹 경로
- 폰트 에셋, 최소 글자 크기, 줄바꿈·말줄임 규칙
- 각 화면의 목업 이미지 경로

## 4. 작업 규칙
1. **목업을 먼저 고정한다.** 피그마·이미지 생성·위젯 등으로 버튼 배치를 먼저 정한다. 실제 스크린샷 위에 구조도를 그려 넘기면 일관성이 높아진다. `[영상]`
2. **기준선, 안전 영역, 바운딩 박스로 지시한다.** 이 키워드를 넣으면 AI가 배치를 더 잘 지킨다. `[영상]`
3. **공통 컴포넌트를 재사용한다.** 화면마다 버튼을 새로 만들지 않는다.
4. **상태를 표로 정의한다.** 기본·호버·눌림·비활성·선택·쿨다운·잠김.
5. **최장 데이터로 테스트한다.** 가장 긴 이름, 최대 자릿수 숫자, 가장 긴 번역문.
6. **다해상도 스모크 테스트를 돌리고 스크린샷을 찍는다.** `[영상]`
7. **마지막은 사람에게 스크린샷을 보낸다.** 코드·비전 검증을 통과해도 사람 눈에 문제가 보이는 경우가 많다. `[영상]`

## 5. 금지
| 금지 | 이유 | 예외 |
|---|---|---|
| 목업 없이 레이아웃 생성 | 웹 UI 기본값으로 감 | 기존 화면에 요소 1개 추가 |
| 화면 확인 없는 완료 보고 | 넘침·겹침 미검출 | 없음 |
| 절대 좌표 배치 | 비율 대응 실패 | 고정 해상도 전용 게임 |
| 화면마다 다른 버튼 스타일 | 일관성 붕괴 | 의도된 강조 버튼 |
| 장식용 이모지·그라데이션 버튼 | AI 기본값 | 컨셉상 필요 |

## 6. 요청서 예시
```
[목표] 포탑 업그레이드 팝업 구현.
[레퍼런스] 첨부 스크린샷 위에 그린 구조도 (빨간 박스 = 버튼 영역, 파란 선 = 기준선).
[숫자 스펙] 팝업 폭 480px(1920 기준), 버튼 160x56, 간격 16, 안전 영역 안쪽 48px.
[금지] 카드 그리드, 사이드바, 이모지, 새 버튼 스타일. 기존 공통 버튼 프리팹 사용.
[검증] 1920x1080, 1440x1080(4:3), 2560x1080(21:9)에서 스크린샷. 가장 긴 포탑 이름으로 테스트.
       글자가 바운딩 박스를 넘는지 이미지로 확인하고, 스크린샷을 나에게 보내라.
```

## 7. 검증 체크리스트
- [ ] 목업과 실제 화면을 나란히 비교한 이미지
- [ ] 16:9 / 4:3 / 21:9 (+모바일이면 세로·노치) 스크린샷
- [ ] 최장 문자열·최대 숫자에서 넘침·잘림 없음
- [ ] 모든 상태(비활성·쿨다운 등) 화면 확인
- [ ] 안전 영역 밖에 상호작용 요소 없음
- [ ] 값이 바뀔 때만 텍스트 갱신
- [ ] 사람이 스크린샷을 보고 최종 승인
