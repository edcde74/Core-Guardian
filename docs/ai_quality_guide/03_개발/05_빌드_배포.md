> 범위: 빌드 설정, 버전 관리, 플랫폼 업로드, 패치 배포. 스토어 페이지 문구·이미지는 [07_출시마케팅](../07_출시마케팅/01_스토어페이지.md)에서 다룬다.
> 함께 볼 파일: [04_최적화](04_최적화.md), [06_QA/01_기능_회귀](../06_QA/01_기능_회귀.md)

## 1. 이 파트에서 AI 티가 나는 이유
AI는 "빌드 성공"을 "출시 가능"으로 착각한다. 빌드가 만들어졌는지만 보고 실행해보지 않으며, 디버그 로그·개발용 치트·테스트 씬이 들어간 채로 배포 파일을 만든다. 버전 번호와 변경 기록이 빠지고, 매번 수동으로 다른 설정으로 빌드한다. `[실무]`

## 2. AI 티 패턴
| 패턴 | 왜 티가 나나 | 대신 이렇게 | 출처 |
|---|---|---|---|
| 빌드 성공 = 완료 | 실행 확인 없음 | 빌드 실행 스모크 테스트 | `[실무]` |
| 디버그 UI·치트·로그 포함 | 개발 설정 그대로 | 릴리스 프로필 분리, 정의 기호로 제거 | `[실무]` |
| 버전 번호 없음·수동 | 어떤 빌드인지 모름 | 빌드 시 자동 기입, 커밋 해시 포함 | `[실무]` |
| 매번 다른 수동 설정 | 재현 불가 | 빌드 스크립트·프로필 고정 | `[실무]` |
| 패치노트 AI 문체 | 엠대시·별표·과장 | [05_텍스트/01](../05_텍스트/01_UI문구_툴팁.md) 규칙 적용 | `[영상]` |
| 출시 잡일 전부 수작업 | 반복 실수 | 설명 입력·스크린샷 비율 맞추기 자동화 | `[영상]` |

## 3. 작업 전에 정할 것 (프로젝트 설정값)
- 대상 플랫폼과 빌드 프로필(개발 / 릴리스)
- 버전 규칙(예: 메이저.마이너.패치 + 빌드 번호)
- 빌드 출력 경로와 파일 이름 규칙
- 포함 씬 목록
- 업로드 도구(예: 스팀 SteamPipe)와 브랜치(기본 / 베타)
- 플랫폼 AI 사용 고지 내용 [00_공통/01](../00_공통/01_공통원칙.md) 참고

## 4. 작업 규칙
1. **빌드는 스크립트로 한다.** 같은 명령이면 같은 결과가 나와야 한다.
2. **릴리스 빌드에서 개발 요소를 제거한다.** 성능 표시, 치트 키, 테스트 씬, 상세 로그.
3. **버전을 자동으로 넣는다.** 타이틀 화면이나 설정 화면에 버전이 보여야 버그 리포트를 추적할 수 있다.
4. **빌드를 실행해서 확인한다.** 실행 → 타이틀 → 1판 플레이 → 종료까지 스모크 테스트.
5. **변경 기록을 남긴다.** 커밋 목록에서 패치노트 초안을 만들고 사람이 다듬는다.
6. **베타 브랜치에 먼저 올린다.** 기본 브랜치는 확인 후.
7. **출시 잡일을 자동화한다.** 스토어 설명 입력, 스크린샷 비율별 생성은 브라우저·스크립트 도구로 처리한다. `[영상]`

## 5. 금지
| 금지 | 이유 | 예외 |
|---|---|---|
| 실행 확인 없는 업로드 | 시작 불가 빌드 배포 위험 | 없음 |
| 릴리스에 개발 기능 포함 | 치트·성능 저하 | 의도적 디버그 메뉴(숨김) |
| 사람 승인 없는 업로드·공개 전환 | 되돌리기 어려움 | 없음 |
| 패치노트 AI 초안 그대로 게시 | AI 문체 노출 | 없음 |

## 6. 요청서 예시
```
[목표] Windows 릴리스 빌드 스크립트.
[스펙] 출력 Builds/Release/<버전>/, 버전 = ProjectSettings 버전 + 커밋 해시 7자리.
[제거] 성능 표시(F3~F5), 치트, 테스트 씬, Debug.Log(경고·오류 제외).
[검증] 빌드 후 실행해 타이틀→1라운드→종료 스모크 테스트, 타이틀 화면 버전 표시 스크린샷.
[금지] 업로드, 기본 브랜치 배포.
```

## 7. 검증 체크리스트
- [ ] 스크립트로 재현 가능한 빌드
- [ ] 릴리스 빌드에 개발 기능 없음
- [ ] 화면에 버전 표시
- [ ] 실행 스모크 테스트 통과(스크린샷)
- [ ] 최저 사양에서 실행 확인
- [ ] 패치노트 사람 검수
- [ ] 업로드·공개는 사람이 승인
