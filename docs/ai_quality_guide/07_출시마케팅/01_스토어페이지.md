# 출시·마케팅 / 스토어 페이지

> 범위: 스팀 등 스토어의 게임 설명, 짧은 소개, 태그, 캡슐 이미지 문구, AI 사용 고지. 스크린샷·트레일러 제작은 [02_스크린샷_트레일러](02_스크린샷_트레일러.md)에서 다룬다.
> 함께 볼 파일: [03_커뮤니티_공지](03_커뮤니티_공지.md), [05_텍스트/01_UI문구_툴팁](../05_텍스트/01_UI문구_툴팁.md), [05_텍스트/04_번역_현지화](../05_텍스트/04_번역_현지화.md)

## 1. 이 파트에서 AI 티가 나는 이유
스토어 페이지는 플레이어가 게임을 처음 만나는 곳이다. AI로 쓴 설명은 과장 형용사와 정해진 마케팅 문형으로 채워져 바로 티가 난다. 여기서 "AI 슬롭"으로 찍히면 유튜버 소개에서 빠지고, 알고리즘에서 불리해지고, 리뷰·토론 게시판에 악평이 몰린다. 특히 북미·유럽·일본 플레이어의 반감이 크다. `[영상]`

## 2. AI 티 패턴
| 패턴 | 왜 티가 나나 | 대신 이렇게 | 출처 |
|---|---|---|---|
| "Embark on an epic journey", "Unleash your..." | 영어권 AI 마케팅 문구의 전형 | 플레이어가 실제로 하는 행동부터 쓴다 | `[실무]` |
| 형용사 3개 나열 ("fast-paced, strategic, and addictive") | 아무 게임에나 붙는 말 | 이 게임만의 규칙 하나를 쓴다 | `[실무]` |
| 이모지 불릿 목록 | AI·SNS 톤 | 굵은 소제목 + 짧은 문장 | `[실무]` |
| 엠대시, 화살표, 별표 | AI 기호 | 쉼표, 마침표 | `[영상]` |
| "It's not just a X, it's a Y" | 대조 문형 | Y를 바로 설명 | `[실무]` |
| "A가 아닌 B", "핵심은 ~" | 한국어 AI 문형 | 직접 설명 | `[영상]` |
| 기능 목록만 있고 장면이 없음 | 게임이 안 그려짐 | 한 판의 흐름을 3~4문장으로 | `[실무]` |
| 실제 게임과 다른 과장 | 환불·악평 원인 | 현재 빌드에 있는 것만 | `[실무]` |

## 3. 작업 전에 정할 것 (프로젝트 설정값)
- 짧은 소개(스팀 기준 약 300자 이내 영문) 한 줄 목표
- 핵심 판매 포인트 3개 (실제 플레이로 증명 가능한 것만)
- 비교 대상 게임 (태그·장르 이해용, 문구에 이름을 그대로 쓰지는 않는다)
- 지원 언어, 언어별 설명 작성 방식 (번역/현지 작성)
- AI 사용 범위 기록 (어떤 에셋·텍스트에 AI를 썼는지)

## 4. 작업 규칙
1. 첫 문장은 플레이어가 하는 행동으로 시작한다. "~를 배치해 ~를 막는다"처럼.
2. 핵심 판매 포인트마다 근거가 되는 스크린샷이나 GIF를 짝지어 둔다.
3. AI가 초안을 쓰면 금지 문형·기호 개수를 세서 0으로 만든다. `[영상]`
4. 영어 설명은 영어 AI 단어 목록으로 검색해 지운다. 가능하면 원어민 검수.
5. 스토어 설명은 번역보다 언어별로 다듬어 쓴다. [04_번역_현지화](../05_텍스트/04_번역_현지화.md)
6. 스토어 설명 입력, 스크린샷 비율 맞추기 같은 반복 작업은 브라우저 자동화 도구로 처리해도 된다. 최종 제출 버튼은 사람이 누른다. `[영상]`
7. **AI 사용 고지**: 스팀은 제출할 때 AI 생성 콘텐츠 사용 여부와 범위를 공개하도록 하고 있다(개발 중 사전 생성 콘텐츠와 실시간 생성 콘텐츠 구분). 정책은 바뀔 수 있으니 **출시 전에 스팀 공식 문서에서 최신 내용을 다시 확인한다.** 다른 스토어도 각각 확인한다. `[실무]`
8. 고지 내용은 정직하게, 구체적으로 쓴다. 숨기다 드러나는 것이 가장 큰 악평 원인이다. `[실무]`

### AI 사용 기록 표 `[실무]`
고지를 쓰기 쉽게 개발 중에 계속 기록한다.

| 에셋/텍스트 | 사용 도구 | 사람이 한 작업 | 최종 결과물에 남은 비율 |
|---|---|---|---|
| 예: 몬스터 스프라이트 | 이미지 생성 | 후처리, 팔레트 보정, 애니메이션 | 기반 이미지 |
| 예: UI 툴팁 | 텍스트 생성 | 전면 수정, 용어 통일 | 초안만 |

### 태그와 짧은 소개 `[실무]`
- 태그는 실제 플레이 경험 기준으로 고른다. 많이 노출되는 태그를 억지로 넣으면 기대와 달라 평가가 나빠진다.
- 짧은 소개는 "장르 + 플레이어 행동 + 차별점" 한 문장으로 시작해 줄여간다.

### 자주 하는 실수
- 영어 설명만 AI로 쓰고 검수 없이 올린다. 영어권이 AI 문구에 가장 민감하다.

## 5. 금지
| 금지 | 이유 | 예외 |
|---|---|---|
| 위 AI 문형·기호 | AI 슬롭 인상 `[영상]` | 없음 |
| 빌드에 없는 기능 홍보 | 환불·악평 | "출시 예정" 명시 |
| 다른 게임 이름을 내세운 비교 문구 | 상표·인상 문제 | 공식 협업 |
| AI 사용 고지 누락·축소 | 정책 위반, 신뢰 손상 | 없음 |
| 이미지에 구운 설명 글자 | 언어별 수정 불가 | 로고 |

## 6. 요청서 예시
```
[목표] 스팀 상세 설명 초안 (영어, 한국어 각각)
[자료] 게임 한 줄 컨셉, 핵심 판매 포인트 3개, 대표 스크린샷 설명
[구조] 첫 문단: 플레이어 행동 2문장 / 소제목 3개: 각 포인트를 장면으로 2문장 / 마지막: 현재 콘텐츠 분량
[금지] embark, unleash, epic journey, 형용사 3개 나열, 이모지, 엠대시, "A가 아닌 B"
[검증] 금지 표현 검색 결과 표, 각 문장이 어떤 스크린샷으로 증명되는지 표
```

## 7. 검증 체크리스트
- [ ] 첫 문장이 플레이어 행동으로 시작한다
- [ ] 금지 문형·기호·영어 AI 단어 0
- [ ] 모든 홍보 문장이 현재 빌드로 증명된다
- [ ] 언어별로 자연스럽다 (원어민 또는 역번역 확인)
- [ ] AI 사용 고지를 최신 정책으로 확인하고 정직하게 작성했다
- [ ] 페이지 미리보기를 데스크톱·모바일 폭에서 봤다
- [ ] 처음 보는 사람이 30초 안에 무슨 게임인지 말할 수 있다 (사람 판단)
