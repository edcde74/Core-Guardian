> 범위: 패치 노트, 업데이트 공지, 개발 로그, SNS 글, 디스코드·스팀 토론 답변. 스토어 설명은 [01_스토어페이지](01_스토어페이지.md)에서 다룬다.
> 함께 볼 파일: [05_텍스트/01_UI문구_툴팁](../05_텍스트/01_UI문구_툴팁.md), [05_텍스트/03_용어집](../05_텍스트/03_용어집.md)

## 1. 이 파트에서 AI 티가 나는 이유
커뮤니티 글은 개발자 본인의 목소리로 읽힌다. AI가 쓴 공지는 감사 인사와 과장, 이모지 불릿, 정형화된 마무리로 채워져서, 플레이어는 "개발자가 직접 쓰지도 않았다"고 느낀다. AI 반감이 큰 커뮤니티에서는 공지 하나가 게임 전체의 인상을 바꾼다. `[영상]` (반감 부분), 나머지 `[실무]`

## 2. AI 티 패턴
| 패턴 | 왜 티가 나나 | 대신 이렇게 | 출처 |
|---|---|---|---|
| "We're thrilled to announce..." / "여러분의 성원에 힘입어..." | 정형 도입 | 바뀐 것부터 쓴다 | `[실무]` |
| 이모지 불릿 패치 노트 | AI·SNS 톤 | 분류 소제목 + 하이픈 목록 | `[실무]` |
| 모든 변경을 "개선", "향상"으로 | 정보 없음 | 전후 수치 ("공격력 10 → 12" 대신 "공격력 10에서 12로") | `[실무]` |
| 엠대시, 화살표, 별표 | AI 기호 | 쉼표, "~에서 ~로" | `[영상]` |
| 비판 글에 정형 사과문 | 기계적 응대 | 문제를 구체적으로 인정하고 다음 행동을 쓴다 | `[실무]` |
| 매 글 끝에 같은 마무리 인사 | 템플릿 티 | 필요할 때만 짧게 | `[실무]` |
| "A가 아닌 B", "핵심은 ~" | AI 문형 | 직접 설명 | `[영상]` |
| 용어가 게임과 다름 | 혼동 | 용어집 단어 | `[영상]` |

## 3. 작업 전에 정할 것 (프로젝트 설정값)
- 개발자 말투 (1인칭 "저/저희", 존댓말 수준, 영어 톤)
- 패치 노트 분류 (신규 / 변경 / 수정 / 알려진 문제)
- 수치 변경 표기 규칙
- 공지 채널별 길이 (스팀 공지, 디스코드, X 등)
- 답변하지 않을 주제 (출시일 약속, 미확정 기능)

## 4. 작업 규칙
1. 사실 목록을 먼저 만든다. 바뀐 것, 수치, 이유. 이 목록은 사람이 확정한다.
2. AI에게는 사실 목록 + 개발자 말투 샘플(직접 쓴 글 2~3개) + 용어집을 넘긴다.
3. 패치 노트는 분류별로, 수치는 전후를 같이 쓴다.
4. 초안의 금지 문형·기호 개수를 세서 0으로 만든다. `[영상]`
5. 개발 로그는 실제 작업 과정(실패와 결정 이유 포함)을 쓴다. 사람이 고른 이유가 들어가야 개발자 글이 된다.
6. 비판·버그 제보 답변은 AI 초안을 그대로 올리지 않는다. 사람이 읽고 고친다.
7. AI 사용에 대한 질문을 받으면 스토어 고지와 같은 내용으로 정직하게 답한다.
8. 미확정 기능은 "검토 중"으로 쓰고 날짜를 약속하지 않는다.

### 패치 노트 틀 `[실무]`
```
v0.4 업데이트

신규
- (추가된 것, 한 줄씩)

변경
- (대상) (항목) A에서 B로. (짧은 이유)

수정
- (증상)이 발생하던 문제를 고쳤습니다.

알려진 문제
- (증상). (임시 해결법이 있으면)
```

### 채널별 길이 `[실무]`
- 스토어 공지: 전체 패치 노트
- 디스코드: 요약 3~5줄 + 스토어 공지 링크
- SNS: 한 가지 변경 + 짧은 영상이나 GIF

### 자주 하는 실수
- 한국어 공지만 고치고 영어 공지를 그대로 둔다.

## 5. 금지
| 금지 | 이유 | 예외 |
|---|---|---|
| AI 답변을 검토 없이 게시 | 오답·말투 문제 | 없음 |
| 수치 없는 "밸런스 조정" | 정보 없음 | 숨겨진 수치 정책 |
| 정형 감사·사과 문구 반복 | 템플릿 티 | 없음 |
| 미확정 기능의 날짜 약속 | 신뢰 손상 | 확정된 일정 |
| AI 사용 여부 회피 답변 | 신뢰 손상 | 없음 |

## 6. 요청서 예시
```
[목표] v0.4 패치 노트 (한국어, 영어)
[자료] 사람이 확정한 변경 목록(수치 포함), 이전 패치 노트 2개(말투 샘플), 용어집
[구조] 신규 / 변경 / 수정 / 알려진 문제. 수치는 "A에서 B로"
[말투] 1인칭 "저희", 짧은 평서문, 도입 인사 1문장 이하
[금지] 이모지, 엠대시, 화살표, "thrilled", "개선되었습니다" 단독 사용
[검증] 변경 목록과 패치 노트 항목이 1:1인지 대조표 제출
```

## 7. 검증 체크리스트
- [ ] 사실 목록과 1:1로 대응한다 (누락·추가 없음)
- [ ] 수치 변경은 전후가 모두 있다
- [ ] 금지 문형·기호 0
- [ ] 용어집 단어만 사용
- [ ] 개발자 말투 샘플과 톤이 이어진다 (사람 판단)
- [ ] 미확정 내용에 날짜 약속이 없다
