# 적·탄환 모델 풀링 설계 제안

2026-10-21 Asia/Seoul. 기준 `1f523a8`. 사용자 요청: 앞서 제외한 모델 객체 풀링도 진행. **사용자가 공개 참조 API 변경 설명 후 이 설계를 승인하고 진행을 요청했다.** 구현 복구 기준 `ed81777`, [구현/검증 기록](../../development/model_pooling_20261021/README.md). Play·자동 테스트·성능 측정·빌드·실행파일 실행·push 보류는 유지한다.

## 현재 구조에서 확인한 문제

Session은 가변 `List<EnemyState>`/`List<ProjectileState>`와 같은 객체를 타깃/스냅샷/이벤트에 직접 노출한다. DebugSpawn은 적 객체를 반환하고 ProjectileLaunched/DamageApplied는 실제 객체를 전달한다. 기존 AnimationTiming 검사도 발사 객체를 List에 저장한 뒤 다음 Tick 이후 다시 읽는다. 적 사망 이벤트에서 Art/HUD/Audio는 마지막 위치·체력·골드·보스 상태를 읽는다.

따라서 같은 EnemyState/ProjectileState 인스턴스를 새 ID로 재초기화하면 이전 참조가 새 개체를 가리킨다. 회수를 몇 프레임 늦춰도 외부 참조의 사용 종료를 증명할 수 없다. 객체에 Generation 필드만 추가해도 기존 참조에서 읽는 Generation 자체가 바뀌므로 해결되지 않는다.

## 대안과 선택 제안

1. 현재 직접 참조 API 유지: 표시/내부 버퍼 풀은 유지할 수 있지만 모델 객체의 안전한 재사용은 보장할 수 없다.
2. 모델 재사용 + 사용자가 예전 참조를 모두 버린다는 규약만 추가: 구현은 작지만 잘못된 타깃/다른 개체 수정의 위험을 런타임에서 막지 못하므로 채택하지 않는다.
3. **권장: 풀 내부 모델 + 외부 값 핸들/이벤트 스냅샷.** 공개 모델 참조 계약을 바꾸되 이전 개체가 새 개체를 가리킬 수 없게 한다. 모델 데이터는 재사용하고, 각 생명의 식별자는 값 타입으로 전달한다.

## 식별·접근 계약

- 풀의 소유 Session, 슬롯, 단조 증가 세대를 담는 EnemyHandle/ProjectileHandle 값 타입을 둔다. 다른 Session/종류/세대의 핸들은 같은 개체로 취급하지 않는다. 재사용/세대 만료 핸들의 TryRead/TryUpdate는 실패하고 새 개체를 수정하지 않는다. 세대 overflow 슬롯은 재사용하지 않는다.
- 현재 EnemyState/ProjectileState는 풀 소유의 비공개 데이터가 된다. 상태 읽기는 값 스냅샷, 변경은 Session의 검증된 메서드를 사용한다. 공개 목록은 핸들의 읽기 전용 뷰로 바꾸고 실제 가변 저장소는 노출하지 않는다. DebugSpawn도 핸들을 반환한다.
- ID는 지금처럼 Session 내 단조 증가를 유지하고 재사용하지 않는다. 슬롯과 게임 ID는 별개다. 기본/만료/다른 Session 핸들의 동작을 명시하고 null 대신 Invalid 핸들을 사용한다.
- Enemy/Projectile의 마지막 상태를 오래 보관할 필요가 있는 코드는 즉시 스냅샷을 저장한다. 만료 핸들로 과거 상태를 읽는 기능은 제공하지 않는다. 기존 C# 호출자와 검사는 API 변경에 맞춰 이관한다.

## 이벤트·타깃·회수 순서

- ProjectileLaunched는 투사체/타깃 핸들과 발사 ID·위치·출처·피해·속도를 포함한 불변 값 스냅샷을 각 실제 발사마다 전달한다. DamageApplied는 당시 적 ID·핸들·위치·병종·체력·퇴장·보스 상태·골드 및 실제 피해를 스냅샷으로 전달한다. 원래 이벤트 순서/횟수는 유지한다.
- 이벤트 관찰자가 보관한 발사/피해 값은 이후 Tick/회수/재사용에도 변하지 않는다. 발사 직후 같은 틱 명중의 이펙트·소리도 누락하지 않는다. 관찰자가 게임을 변경하려면 스냅샷 자체가 아니라 Session 변경 API와 핸들을 사용한다. 이벤트 구독자의 객체 직접 수정 계약은 이 방식으로 변경된다.
- 플레이어/포탑 타깃과 탄환 타깃은 핸들로 보관하고 조회/이동/피해 직전에 세대를 확인한다. 타깃 사망 후 발사체는 다른 슬롯 재사용 개체로 이동/명중하지 않고 기존 규칙대로 제거한다. 기존 역할→낮은HP→남은경로·최초/현재 대상 유지 규칙은 그대로다.
- 틱 스냅샷/재진입에서도 핸들은 유지한다. 논리 삭제는 원래 순서에 반영하고 모델 슬롯의 재대여는 최외곽 Tick/이벤트가 끝날 때까지 격리한다. 중첩 Tick/관찰자 예외에도 finally로 정리하고 이중 반환을 막는다. 삭제된 핸들은 활성 조회에서 실패한다.
- 제거·코어 퇴장·전투 패배·라운드 종료·진단 재시작·Session 종료의 회수 경로를 한곳에 모은다. 풀 보관 제한은 비활성에만 적용하고 활성 수/생성 시점·게임 물량은 제한하지 않는다. 초기 제안은 일반 병종별32/보스4·탄환256이며 계측 전 임시 보관 정책이다. 초과 회수는 참조를 비우고 보관하지 않는다.

## 변경 범위

- 모델/Session: 새 핸들·스냅샷·소유 풀·조회/변경 API, 타깃/구역 인덱스/지원하지 않는 외부 수정 경로 정리, 단계별 회수.
- Prototype/CombatAnimation/CombatArt/HUD/CombatAudio: 즉시 값 읽기와 ID 기반 뷰를 유지하며 이벤트 스냅샷/핸들로 이관. 표시 본체 풀·효과·음량·횟수·수명·위치/방향 품질은 유지한다.
- 기존 EditMode/PlayMode 검사 소스: 직접 가변 객체/참조 동일성 전제는 같은 개체 핸들 동등성·안전한 변경 API로 이관하고 원래 전투 규칙의 assertions는 유지한다. 새 풀 검사는 소스 추가만 하며 실행은 현재 보류 지시를 따른다.
- 씬/CSV/밸런스/렌더링/Player 설정은 변경 대상이 아니다. 기존 개인 설정·미추적 파일·dirty 씬을 보존한다.

## 검증과 비용 판정

필수 회귀 범위는 슬롯 재사용 후 이전 핸들 실패/스냅샷 불변, 서로 다른 Session 핸들, 사망/퇴장·같은 틱 발사/명중·잔존 탄환 타깃, 단계별 회수·초기화/이중 반환, 이벤트에서 재진입/예외, 풀 확장/보관 상한/참조 정리, 동일 입력·dt·seed에서 전투/이벤트 동등성이다. 지금은 소스 이관/독립 리뷰/컴파일까지만 가능하며 새 실행 검사는 사용자 보류 상태다.

풀은 신규 모델 할당을 줄이는 대신 대기 메모리·세대 검증·핸들 해석 비용을 추가한다. 실제 GC/CPU/피크/잔류 메모리·최소/최대/평균 FPS·절감량/율은 아직 미측정이고 개선을 보장하지 않는다. 테스트 재개 시 현재 API 버전과 이관 버전의 같은 조건 비교를 먼저 수행한다.
