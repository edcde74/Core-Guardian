# 강조 윤곽 구조 교체 설계안

2026-10-24. **설계 문서이며 구현·측정·Unity 조작 승인이 아니다.** 근거: [현재 기준 재측정](../../development/baseline_remeasure_20261024/README.md), 소스 `CoreGuardianObjectEmphasis.cs`, `CoreGuardianSelectionOutline.cs`, `SelectionOutline` 참조 셰이더. 측정값은 모두 Editor 기준이다.

## 1. 왜 구조를 바꾸나

- 게임 메인 스레드(PlayerLoop) 13.15ms 가운데 `CG.Emphasis.Present`가 5.31ms(약 40%)를 차지한다. 그중 `CG.Mask.Present`가 4.43ms다. 렌더 시점의 마스크 Flush도 이전 측정에서 약 2.5ms였다. 이번 측정에는 그 마커가 없어서 재지 못했다.
- 최근 미세 조정 6건(뷰 동기화, 마스크 A·B1·B2, 카메라 재사용, 윤곽 셰이더)은 각각 0.3ms 안팎에 그쳐 모두 미채택됐다. 비용의 원인은 개별 연산이 아니라 **"개체마다 마스크를 따로 만든다"는 구조 자체**다.
- 목표 60FPS를 내려면 이 PC 기준으로 게임 메인 스레드를 약 7~8ms로 줄여야 한다. 이 정도 차이는 강조 구조를 바꾸지 않으면 만들기 어렵다.

## 2. 현재 구조 (소스 확인)

상시 강조 대상은 적 128, 타워 15, 코어 1로 약 144개체다. 매 프레임 LateUpdate에서 개체마다 다음을 한다.

1. 부품 SpriteRenderer 목록을 읽고 검증한다 (`CG.SpriteReferences.Read`, 0.83ms).
2. 부품 bounds를 합쳐 화면 8개 모서리를 투영하고 crop 영역을 계산한다.
3. 개체 전용 마스크 RT를 캐시에서 찾는다 (`CacheLookup`, 0.91ms). 없으면 공용 페이지에 부품 shape를 큐잉하거나 CommandBuffer로 부품을 그려 **이진 합집합 마스크**를 만든다.
4. 출력 quad 4정점을 `ScreenToWorldPoint`로 계산해 업로드한다. UV와 MPB(마스크 텍스처, 원점, 색, 폭)를 설정하고, 맨 앞 부품의 정렬값 +3으로 정렬한다 (`Output`, 1.18ms).
5. 출력 셰이더는 마스크 밖이면서 반경 `_Width`(=1px) 안에 마스크가 있는 픽셀만 윤곽색 `(.06,.065,.075,.90)`으로 칠한다.
6. 렌더 직전 BeginCameraRendering에서 본체 밝기 ×1.15 tint를 적용하고 렌더 후 복원한다 (`Tint`, 0.89ms).

현재 외형의 핵심은 다섯 가지다. 이 다섯 가지가 바뀌면 품질 회귀로 본다.
- (Q1) 부품 사이에 선이 없는 **합집합 실루엣** 윤곽
- (Q2) **화면 1픽셀** 두께, 알파 기준 0.1
- (Q3) 윤곽이 개체의 정렬 순서(맨 앞 부품 +3)에 끼워져 그려져서, 앞뒤 개체·체력바·효과와의 겹침 순서가 유지됨
- (Q4) 색·불투명도 0.90
- (Q5) 본체 밝기 ×1.15

## 4. A안 상세

### 4.1 마스크 패스 (렌더 쪽)
- `ScriptableRendererFeature`를 URP 2D Renderer(`Assets/Settings/Rendering/Renderer2D.asset`)에 추가한다. 카메라 렌더 초반에 화면 크기 R16G16 RT(또는 RG32) 1장을 클리어한다.
- 강조 대상 부품 SpriteRenderer만 그린다. 원본 스프라이트·위치·flip을 그대로 쓰고 override 머티리얼로 알파 ≥ 0.1 픽셀에만 `(entityId, sortDepth)`를 기록한다. 대상만 고르는 방법은 전용 rendering layer 또는 강조 owner가 넘기는 Renderer 목록으로 하고, 설계 확정 시 둘 중 하나를 정한다.
- `sortDepth`는 개체 맨 앞 부품의 (sorting layer, order)를 단조 매핑한 값이다. 깊이 테스트로 화면 픽셀마다 가장 앞 개체만 남는다.
- 개체 ID는 부품별 MaterialPropertyBlock에 1회 설정한다. 개체 생성·풀 재사용·부품 변경 때만 갱신하고 매 프레임 설정하지 않는다.

### 4.2 출력 (기존 정렬 유지)
- 개체별 출력 quad와 정렬값(맨 앞 부품 +3)은 지금처럼 유지한다(Q3).
- 출력 셰이더 규칙: 픽셀 p의 ID가 내 ID가 아니고, p가 비었거나 p의 sortDepth가 나보다 뒤이고, 반경 1px 안에 내 ID 픽셀이 있으면 윤곽색으로 칠한다.
- quad 범위는 개체 bounds의 화면 투영 + pad다. 정점 계산 비용은 남는다. 정적 quad를 transform에 붙여 `ScreenToWorldPoint` 호출을 줄일 수 있는지는 2단계 후보로 분리한다.

### 4.3 범위 밖 (기존 경로 유지)
- HUD 선택 윤곽(능력치 패널), 강화 성공 overlay, 방어형·보스 fallback 판정은 그대로 둔다. 상시 강조 144개체 경로만 교체한다.
- Tint(×1.15, 0.89ms)는 이번 범위가 아니다. 별도 후보로 다룬다(예: 전용 머티리얼 속성).
- 기존 A 출력 배칭 보류, B 마스크 생성 제한, SpriteAtlas 보류, native batch OFF 정책은 그대로 둔다. 새 경로는 토글로 켜고 끌 수 있게 만들고, 기본값은 검증 통과 후 사용자 승인으로 정한다.

### 4.4 예상되는 차이 (픽셀 비교로 확인할 가설)
- **가려진 부품 둘레:** 현재는 개체마다 자기 전체 실루엣으로 마스크를 만들어서, 다른 개체에 가려진 부품 둘레에도 윤곽 후보가 있다. A안은 화면에 보이는 맨 앞 개체만 기록한다. 같은 색·같은 폭이라 대부분 같은 픽셀이 칠해질 것으로 예상하지만 확정이 아니다.
- **이중 블렌딩:** 지금은 두 개체 윤곽이 같은 픽셀에 겹치면 알파 0.9가 두 번 섞여 더 진해진다. A안에서는 한 번만 칠해질 수 있어 겹침 픽셀이 약간 옅어질 수 있다.
- **정렬 사이 끼임:** 개체 A의 정렬값과 A+3 사이에 다른 개체 C가 있으면, 현재는 A 윤곽이 C 위에 보이고 A안에서는 숨는다.
- 위 세 경우는 차이 수, 좌표, 이미지를 남겨 사용자에게 보여 준다. 받아들일지는 **사용자가 결정**한다. 임의로 "같다"고 판정하지 않는다.

## 5. 검증 계획

1. **원본 대 원본 재현성:** 고정 장면 1개(적128·타워15, 1920×1080, ortho 8.5/4.25, 고정 dt, 고정 위상)를 원본으로 두 번 캡처해 0차이를 먼저 확인한다(PITFALLS 2).
2. **픽셀 비교:** 원본 대 A안 최종 화면 전체 합성과 윤곽 격리 화면을 따로 비교한다. 차이 수·좌표·채널·차이 이미지와 raw RGBA를 보존한다. 포함 범위는 Attack/Buff/Defense/Boss, 4방향 × 4위상, 단독/겹침, 체력바·효과 중첩이다.
3. **동작 회귀:** 개체 생성·사망·풀 재사용, 같은 ID의 새 세대, 부품 활성 변화(보행 전환), 카메라 줌 8.5↔4.25, Play 재시작, 씬 종료 후 RT·머티리얼 잔류를 확인한다.
4. **성능:** 같은 조건에서 원본/후보 각 warm15+sample90 ×3을 돌린다. Emphasis.Present, Mask, 렌더 스레드, Draw/SetPass, GC, 최저/최고/평균 FPS를 비교한다. 렌더 쪽 비용 증가도 기록한다(마스크 패스 draw가 늘어남).
5. **채택 기준(수집 전 고정 제안):** 게임 메인 스레드 평균 **2.5ms 이상 절감**(3회 범위가 겹치지 않을 것), 렌더 스레드 증가 1ms 이하, 4.4 외의 픽셀 차이 0, 4.4 차이는 사용자 시각 승인. 미달하면 원본으로 복구하고 결과를 보고한다.
6. Editor 결과를 실행 파일·목표기기 성능으로 쓰지 않는다. 실행 파일 측정은 별도 요청 때 진행한다.

## 7. 아직 모르는 것

- Unity 6000.6 URP 2D Renderer에서 Renderer Feature 패스 위치와 RenderGraph 연동 세부. 공식 문서를 조사하고 결과를 기록한 뒤 구현한다(RULES 3).
- 마스크 패스의 GPU·렌더 스레드 비용. 이 PC의 D3D12 Editor는 GPU Profiler를 지원하지 않는다. 목표기기 GPU(GTX750Ti)에서는 화면 크기 RT 1장 + 약 1,500 부품 draw가 추가된다.
- 출력 quad 정점 계산을 남겼을 때 실제 남는 ms. 1.18ms 중 일부만 사라질 수 있다.
- 기대 절감은 "제거 대상 구간 비용"이지 확정 절감량이 아니다. 실제 수치는 3단계에서만 판정한다.
